# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Internal website for Matematikrevyen (Danish student revue) at `matematikrevy.dk`. Plain HTML/CSS/JS front end — no framework, no bundler, no package manager for the site itself, no test suite, no linter; validation is manual. One PHP file (`server/update-data.php`) is the whole write API (POST only, except Teknikken's signed download GET). Node is only used by the two build scripts in `scripts/` (dev dependencies `pdf-lib` and `qrcode` in `package.json`).

Since 2026-10-02 everything — site, API and data — runs on **web-1** (Hetzner, `188.245.30.36`), deployed by **Coolify** from this repo's `main` branch as one Docker Compose app. Before that it was GitHub Pages + a Simply.com PHP host + GitHub-repo-as-database. Simply.com now only hosts DNS (DNS-only plan; records in README.md), and mail goes through Forward Email.

Planning documents (`plans/autosave.md`, `plans/multi-tenant-plan.md`, …) live in the local `plans/` folder, which is gitignored — they exist only on the maintainer's machine, not on GitHub or the server.

## Hosting & data flow

`docker-compose.yml` defines two containers, both mounting the host folder `/srv/matrevy/data` at `/data`:

- **`web`** (`server/Dockerfile.site`, `php:8.3-apache`, build context = repo root): serves the repo's static files plus `update-data.php`, `health.php` (Coolify healthcheck/UptimeRobot), and `config.php` (= `server/config.docker.php`, every value from Coolify env vars: `REVYST_PASSWORD`, `BOSS_PASSWORD`, `ADMIN_PASSWORD`, optional `SHARED_PIN`; data dirs default to `/data/{budget,forms,faellesspisning,band,lokaler,site}`). `server/apache-site.conf` aliases `/data/`, `/archive/`, `/posts/`, `/wiki/` to `/data/site/…`, every `js/<name>-data.js` **except** `js/manus-data.js` (hand-written code) to `/data/site/generated/js/`, and `/calendar.ics` to `/data/site/generated/calendar.ics`. It redirects `www.` → apex (pages on `www.` would otherwise fail CORS and keep a separate login) and sends `Cache-Control: no-cache` on everything (cheap 304s; a save or deploy is never hidden behind a cache). `.dockerignore` keeps the data folders and generated files out of the image.
- **`worker`** (`server/Dockerfile.worker`, `texlive/texlive:latest-medium` + Node, runs as uid 33 like Apache): `server/worker.sh` runs `scripts/embed-scenes.js` once at startup, then polls every 2 s for flag files in `/data/site`: `.embed-requested` → `embed-scenes.js`, `.regen-pdfs-requested` → `scripts/generate-pdfs.js`. The flag is removed before each run, so a save landing mid-run triggers one more run. `/app/{data,archive,js,calendar.ics}` are symlinks into `/data/site`, so both scripts run unchanged.
- **Archive mirror to GitHub** (also `worker.sh`): `update-data.php` touches `.archive-sync-requested` on any write under `archive/`, and the worker touches it after every PDF build. Once the flag has been quiet for `ARCHIVE_SYNC_QUIET_SECONDS` (default 300), the worker `rsync --delete`s `/data/site/archive/` into a sparse clone at `/data/archive-git` and pushes one `[skip ci]` commit to `main` (deploy key = base64 in Coolify's `ARCHIVE_SYNC_DEPLOY_KEY`; empty = mirror off). Strictly one-way, server → GitHub; `archive/README.md` is repo-managed. Until Manus's "Revyster kan se manus" (`pdfLinksVisibleToRevyst`) is on, the current production is mirrored as a **hidden view**: only `submitted/` (plus `cover.jpg`/`other/`/`snapshot/`), with the selected scenes copied back into it from `sketches/`/`songs/` as their current server version, and no generated PDFs (top-level `*.pdf`, `manuskripter/`). With manus on but "Revyster kan se roller" (`rolesVisibleToRevyst`) off, it's a **redacted view**: the whole folder, but `sketches/`/`songs/`/`manus.pdf` come from the generator's `anonym/` copies and `manuskripter/`/`Rolleoversigt.pdf` are left out. Both restricted views run every `.tex` through `redact_tex` (`\role{X}[…]` → `\role{X}[navn]`); with both on the next sync is a plain full mirror. `anonym/` itself is never mirrored. Any write to `data/config.json` backdates the flag so the sync runs within seconds instead of after the quiet period. This keeps closed years and the current production's `submitted/`/`sketches/`/`songs/` browsable on GitHub, so Arkiv's GitHub pill, the Manus Guide link and Program QR codes keep working. Because the worker pushes to `main`, `git pull --rebase` before pushing code (it only touches `archive/`, so it never conflicts).

**Live data**: public site data lives in `/srv/matrevy/data/site/{data,archive,posts,wiki}` (+ `generated/`); private data in `/srv/matrevy/data/{budget,forms,faellesspisning,band,kostumetinder,ninjas,rekvisitten,lokaler,teknikken,koordinator}`, outside every web-served folder. `/srv` is backed up nightly with restic (README.md → Drift), except `teknikken/` (temporary, large files). The repo doesn't track `data/*.json`, `posts/`, `wiki/`, `calendar.ics` or `js/*-data.js` (except `manus-data.js`); local copies (see Local development) are gitignored, and editing them changes nothing live. The repo's `archive/` is different: it stays tracked as the worker's live mirror (below) — don't edit it in the repo, the next sync overwrites it.

**Save path**: browser → `update-data.php` → `github_api()`, which despite its name is now a local-disk stand-in for the GitHub Contents API (kept so every caller works unchanged): same return shape (base64 `content` + `sha`), `sha` = sha1 of the file bytes, reads/writes under a `.write.lock` flock, atomic temp-file + rename, and a stale `sha` → `409`. After a write it touches `.embed-requested` (any path under `data/`) and `.regen-pdfs-requested` (when the write's message contains `[regen-pdfs]`). Saved data is visible on the next page load within ~3 s; a full PDF build takes ~15 s.

**Deploy**: push to `main` → Coolify rebuilds and redeploys both containers (code and static files are baked into the `web` image, so any change needs a rebuild). Secrets live only in Coolify's environment variables.

**`SITE_API_ENDPOINT`** (`js/site.js`): always `/update-data.php` (same origin, so a test domain writes to its own data). CORS in `update-data.php` still only allows `https://matematikrevy.dk`.

**Local development**: pull the live public data and embed it — also what keeps the `file://` offline mode working:

```
rsync -a web-1:/srv/matrevy/data/site/{data,archive,posts,wiki} ./
node scripts/embed-scenes.js
```

Saves from a local copy go to the local host's `/update-data.php`, never the real API; run `php -S` with a hand-written `config.php` pointing `SITE_DATA_DIR` at a scratch copy if needed. PHP's built-in server sends no `Last-Modified` for static files, so the stale-page banner only works locally behind a small router script that adds it (Apache on web-1 does).

**Embedded data**: `scripts/embed-scenes.js` is table-driven (`EMBEDS`): each `data/<name>.json` becomes a flat global (`SCENES_DATA`, `CAST_DATA`, `CALENDAR_DATA`, …) in a generated `js/<name>-data.js`, loaded via `<script src>` only on the pages that need it — globals rather than `fetch()` so pages work over `file://`. A `raw: true` entry writes verbatim (used for `calendar.ics`). A file is only rewritten when its content changed (`writeIfChanged`), so its `Last-Modified` means "this data changed" (the stale-page banner depends on it). Adding a data file = an `EMBEDS` entry + `<script>` tags + creating the JSON on the server disk once (`update_file()` has no create-if-missing branch) — the Apache alias picks up any `[a-z]+-data.js` automatically. The `async` on `loadScenes()` in `schedule.js` is vestigial.

## Site shell & access levels (`site.js`)

Four access levels: **public / revyst / boss / admin**, unlocked by three shared passwords (handed out verbally — deliberately not real per-user auth). **Boss** edits Manus/Kalender/Wiki/Formularer; **Admin** is the top tier (site maintainer) — everything Boss has plus Koordinator, Budget management, site-wide config, Arkiv, Gantt/Revyugen, Bosser. **Øveplan** (`schedule.js`) is revyst-level since it never writes through the server (every placement lives in that browser's `localStorage`). Reads are gated client-side only (cosmetic — nothing is secret); writes are genuinely validated server-side.

- `site.js` renders the header nav on every page from `SITE_PAGES` (`{href, label, level, group?}`) — the **only** place a page is registered. Revyst-level pages render greyed/unclickable until login; boss/admin-level pages are omitted below that level.
- **Redskaber (grouped tool tab)**: a `SITE_PAGES` entry with a `group` key (label in `SITE_NAV_GROUP_LABELS`) folds into one shared nav tab — today Bandet and Øveplan under "Redskaber", Kostumetinder, Ninjas, Mics & Cues, Teknikken and Rekvisitten; future tools register with the same `group`, no nav/CSS changes. `renderNavGroup()` lists a group's members alphabetically (`localeCompare(…, 'da')`), whatever their `SITE_PAGES` order. `buildSiteNavLinks()` renders a group as nothing (all members hidden), a greyed `.site-nav-locked` span (all visible members locked), or an interactive tab: a click-to-open dropdown on desktop (`renderDesktopNavGroup`, reusing `.site-field-pop`/`.site-list-row`/`.site-list-selected`, with its own open/close/outside-click/Escape handling since `schedule.html` doesn't load `site-utils.js`), or an in-place accordion in the mobile overlay (`renderMobileNavGroup`, auto-expanded on a member page). `applyPageGate()`/`injectSitePrefetchLinks()` key off `SITE_PAGES` by `href` regardless of grouping.
- **Nav preloading**: `injectSitePrefetchLinks()` idle-prefetches every reachable page's HTML at load; `setupSiteNavPreload()` loads a page as soon as its nav link (`SITE_NAV_LINK_SELECTOR`: `.site-nav`/`.site-menu-nav` links) is hovered, touched or focused. Chromium gets a Speculation Rules `prerender` (`moderate` eagerness — the whole page, JS included, renders in the background, so its on-load API reads run on hover); other browsers fall back to fetching the page's HTML + its `script[src]`/stylesheets into the HTTP cache (parsed in a detached `DOMParser` doc), leaving only 304s for the real navigation. Both skipped over `file://`.
- **Stale-page banner** (`setupSiteStaleCheck()`): when the tab becomes visible again (≥1 min since the last check) and every 15 min while visible, HEADs `js/site.js` (its `Last-Modified` changes on every deploy → "Siden er blevet opdateret") and every `js/<name>-data.js` the page loads except `manus-data.js` (→ "Der er kommet nye ændringer"), comparing with what it saw at load. Only a real change shows the fixed bottom `.site-stale-banner` (Genindlæs / ✕; ✕ re-baselines so only a newer change shows it again; z-index 120). `<body data-stale-watch="code">` limits a page to the deploy check (Øveplan, which deliberately keeps its scenes). The tab's own saves also regenerate embeds, so a `window.fetch` wrapper notes this tab's API writes (`SITE_READ_ONLY_ACTION_RE` skips reads), and a change within ~2 min of one (server time, estimated from HEAD `Date` headers) is accepted silently. Pages with drafts call `siteRegisterUnsavedCheck(fn)` (site-utils autosavers, Manus, Budget) so the banner adds "Gem dine ændringer først"; the reload itself still goes through each page's `beforeunload`. Relies on `embed-scenes.js` writing only changed files (`writeIfChanged`). Skipped over `file://`.
- **Login**: top-right button → modal (✕, Escape, backdrop click with the mousedown guard below; "Log ind" right-aligned via `.login-actions-end`) → POST `{action:'login', password}` → level. `{level, password}` stored in `localStorage['matrevy-auth']` (password kept so later writes can send it). Logout removes the key; both reload the page.
- **Level switch** (`buildViewLevelSwitch()`): a boss/admin gets a `Revyst/Boss[/Admin] ▾` header button (left of Log ud, and left of the hamburger when collapsed — it's never in the overlay) to view the site as a lower level without logging out. The choice is `viewLevel` in `matrevy-auth` (`siteSetViewLevel()` stores it and reloads; a fresh login has none). `getSiteAuth()` returns `{level: <effective view>, realLevel, password}`, so every `siteHasLevel()` gate follows the view; "Log ud (…)" shows `realLevel`. UI only: writes still send the real password, so revyst-level actions (Budget submit, Manus upload, …) work at any view.
- **Page gate**: `applyPageGate()` hides `<main>` for an insufficient level and shows a login card (blue `.site-gate-login` button). Cosmetic only, by design.
- **`file://` bypass**: `getSiteAuth()` returns a synthetic admin with an empty password (writes still prompt and fail offline); no login button is rendered and prefetch is skipped. Preserves offline use of the tools.
- **Boss-level saves**: the shared password-resolution helpers trust a stored login's password when the level is `boss` *or* `admin`; admin-only resources only trust `admin`.
- **Mobile menu**: the header collapses to a hamburger whenever the nav + login button overflow (`siteUpdateHeaderFit()` → `.site-header-collapsed`), at any width — not tied to a breakpoint. The overlay holds nav links, then login/logout at the bottom; closes on ✕/Escape/nav-tap; body scroll locks.
- **z-index ladder**: header 100 → mobile menu 150 → login/edit modals 200 → field-picker popups 210 → Manus's PDF progress box 220 → hover tooltips 250 (`.faelles-field-tooltip`, `.gantt-tooltip`, `.budget-field-tooltip`, …) → `.site-toast` 300.
- **719px is the site-wide content breakpoint** — every page stylesheet with a mobile layout uses `@media (max-width: 719px)`; keep new ones on the same value.

## Site-wide title & button conventions (`style.css`)

One design system for every page **except `schedule.html`/Øveplan**, which keeps its own pre-theme look and its own `.btn-primary`/`.btn-secondary` in `schedule.css` (its "Ryd skema?" confirm does use the shared `.login-overlay`/`.login-actions`/`site-btn-*`).

- **Page titles**: `.page-content h1` (1.6rem/600, centered). Only Arkiv's `.arkiv-hero h1` tweaks its margin.
- **First-level buttons** (inline, not in an overlay): `.btn-small`/`.btn-small-danger` — warm-cream idle, warm-amber hover; `-danger` stays red.
- **Second-level buttons** (inside a `.login-overlay`/`.login-modal`): `.site-btn-primary` (blue) / `.site-btn-danger` (red) / `.site-btn-warm` (amber) / `.site-btn-success` (green), 6px radius, solid fill, white text. `calPillBtn()`/`budgetPillBtn()`/`wikiPillBtn()`/`formsPillBtn()`/`faellesPillBtn()`/`koordPillBtn()` are thin per-page factories (`variant` names the class; default `site-btn-warm`, e.g. Annuller).
- **Blue is for Login** (and the gate card's login button). Every other positive/confirm/save action — "Gem", "Indsend", "Betalt", "Forbind" — is `.site-btn-success` (green). One deliberate exception: Formularer's builder "Skabelon" button is blue.
- **Arkiv's detail overlay keeps the old oval pills**: its link actions (`.arkiv-action-btn`) use `.site-pill-btn` / `-primary` (green) / `-danger` (red) / `-warm` (amber) — idle white/cream oval, thin border, hover/focus-visible only changing `border-color`. Kept in `style.css` solely for that. (`archive.js`'s own `openYearEditor()` also uses them, but it's unwired legacy code — years are edited from Koordinator.)
- **Button-width floor**: `.site-btn-*` buttons (Manus excepted — own sizing) have `min-width: 5rem` with `0.7rem` horizontal padding, so common labels render at a uniform width while long labels grow. Set on `.login-actions > button`; `.wiki-edit-actions > button` repeats it (not an overlay).
- **Orange = chosen/selected, everywhere**: a dropdown's selected row (`.site-list-selected`), the date picker's chosen day (`.site-dp-selected`), Kalender's today-marker and active Måned/Liste toggle use `--accent-warm-text`/`--accent-warm-fill`, never blue. Øveplan's `.picker-selected` uses its own literal `#d8b879` (same idea, separate literals per its own convention). `.cal-cat-deadline`'s blue is that category's identity color, not a selection state.
- **Scrollbars** are themed site-wide in `style.css` (every page, Øveplan included): thin tan `--border` thumb on a transparent track, `--accent-warm` while the scroll box is hovered (html/body excluded, or the page scrollbar would stay amber). Don't style a page's own.
- **Inline field-editing style** (Fællesspisning's recipe, also Forside's Bosser and Budget's category edit mode): resting `border: 1px solid transparent`, hover-only `border-color: var(--border)` (inside `@media (hover: hover)`), `border-color: var(--accent-warm)` + `background: var(--input-bg)` while focused. A non-editable field (e.g. `.budget-manage-input-locked`) opts out of the hover border explicitly.
- **Modal action layout** (`.login-actions`): `justify-content: center` by default — every ordinary confirm dialog needs no per-modal code. Editor-shaped modals pin actions to the corners (delete left, save right) with `justify-content: space-between`, combining `.login-actions` with their own class for specificity: `.login-actions.cal-event-actions`, `.faelles-connect-modal .login-actions`, `.streg-connect-modal .login-actions`, `.login-actions.budget-expense-edit-actions`. The three that can render a single button (a new Kalender event has only Gem; the two connect modals have only "Forbind" until connected) add `:has(> :only-child) { justify-content: center }`. Self-contained bars outside `.login-actions` — `.post-detail-actions`, `.budget-save-bar`, `.forms-builder-actions` — use plain `space-between` (the latter two center a middle button absolutely: `.budget-center-btn`, `.forms-builder-cancel`). Wiki's in-page editor always has Annuller/Slet/Gem, `space-between`.

### Site-wide field pickers (`site-utils.js`)

Native `<input type="date"/"time">`/`<select>` hand their UI to an unstylable OS shadow root, so every page except Øveplan uses a shared custom-popup system:

- `siteOpenFieldPopup`/`sitePositionFieldPopup`/`siteCloseFieldPopup`/`siteToggleFieldPopup` — popup chrome (`.site-field-pop`, `position:fixed`, clamped on-screen, **repositions** on scroll/resize, closes on outside mousedown or Escape, one open at a time; Escape `stopPropagation`s so it closes just the popup, not a surrounding modal).
- `siteCreateDateField(initialIso)` — `.site-field-btn` opening a month grid (`siteOpenDatePicker`, `.site-dp-today` marker).
- `siteCreateTimeField(initialValue)` — typeable combo (`.site-field-combo`: real `<input>` + clock toggle opening a quarter-hour list); `siteParseTimeInput` normalizes `14:30`/`14.30`/`1430`/`930` on blur/Enter, reverting to the last valid value otherwise.
- `siteCreateDateTimeField` — one field for date with optional time: picking a day re-opens the popup as a time list (`siteOpenTimePicker`, with an "Ingen tid" row and an optional pinned "23:59" `endOfDayOption`); the date applies as soon as it's picked.
- `siteCreateDropdownField(options, initialValue, placeholder?)` — `<select>` replacement without per-option color (`siteOpenDropdownPicker`), used site-wide.

Every factory returns an element with a `.value` getter/setter and a `change` event, so call sites use them like native inputs. Kalender's category field (`calCreateCategoryField`) stays page-specific (colored dot per option) on the same primitives. `schedule.js` carries its own `sched`-prefixed duplicates of the popup chrome, dropdown and time field (it doesn't load `site-utils.js`) with the same CSS classes; its time field fires no `change` event.

## Data-driven pages & `site-utils.js`

Shared architecture for every data-backed page:

- **Data flow**: `data/<name>.json` → `EMBEDS` → generated `<name>-data.js` → `<script src>` on the page. Script order per page: `site.js` → `site-utils.js` → `<feature>-data.js` → `<feature>.js`.
- **One JS file per feature** (`posts.js`, `bosses.js`, `calendar.js`, `archive.js`, `wiki.js`, `manus.js`, `koordinator.js`, `budget.js`, `forms.js`, `faellesspisning.js`, `band.js`, `schedule.js`), page-scoped. Since each page loads a different subset of scripts, **shared logic that isn't in a commonly-loaded file gets duplicated per page** rather than imported — role classification, dance-split logic, drag helpers, tooltips, time-field widgets. This is a deliberate convention, not an oversight.
- **Optimistic shadow**: each feature keeps `let xOverride = siteLoadOverride('x')` + `getEffectiveX()`. A successful save calls `siteSaveOverride(resource, data)` and re-renders, so the saving tab sees its change before the worker regenerates the embed. The override survives a refresh for `SITE_OVERRIDE_TTL_MS` (30 s), then falls back to the embedded data. Manus uses the same mechanism (`setManusSavedOverride()` in `manus-data.js` also writes `siteSaveOverride('manus', …)`, which Øveplan reads too); Forside's Bosser keeps an in-memory-only shadow.
- **`site-utils.js`** (every page except Øveplan): Danish date helpers (`DA_MONTHS`, `DA_WEEKDAYS_SHORT`/`_LONG` Monday-first, `parseIsoDate` — always from parts, never `new Date('YYYY-MM-DD')` which parses as UTC — `formatDaDate`, `formatDaDateMaybeTime`, `todayIso`); `siteShowToast`; `siteSaveResource(resource, payload)` (the boss/admin save flow — stored login password or a `sessionStorage`-cached prompt keyed `matrevy-manus-pin`; returns `{ok}` or `{ok:false, message}`, never throws; `message === ''` means cancelled → silent no-op); `siteFileAction`/`siteUploadFile`/`siteDeleteFile` (the `upload`/`delete` actions); `siteCreateAutosave({save, onStatus})` (debounced ~1 s, serialized auto-save of a page's local draft — `{schedule, flush, isBusy, hasUnsaved}`; `save()` builds from the current draft and must not re-render; a failure isn't retried until the next change/`flush()`; a `beforeunload` warning while anything is unsaved — used by Gantt, Revyugen, Masterplan, Lokalebooking, Manus's Stjerneark and Program; see `plans/autosave.md` for the site-wide plan); `siteDraftBackup(name)` (a Gem page's unsaved draft mirrored to `localStorage['matrevy-draft-<name>']` as `{data, savedAt, tabId}` — `read()` ignores this tab's own and >14-day-old backups, `clear()` only removes one this tab wrote so a clean tab never deletes another tab's work, `discard()` always; used by Manus's Gem tabs); `siteFileStatus(path)` (same-origin `HEAD`, `{exists, date, checkFailed}` from `Last-Modified` — on the server a file's `Last-Modified` only changes when it's rewritten); `siteOpenEditModal`/`siteEditField` (imperative modal chrome) and `siteOpenModalWithClose` (✕ + Escape). Both modal helpers track a backdrop `mousedown`'s own target and only close on a matching backdrop `click` (a drag that started inside the modal, e.g. a textarea resize, must not close it).
- **Saves send the full next array** (`{events:[...]}`, `{posts:[...]}`, …) — no per-item patch API. The server reads the file and writes it back within one request, so the stale-sha `409` only catches two saves landing in the same instant; two tabs editing the same data a minute apart resolve as **last save wins** (see Known issues). **Exceptions**: Manus merges before saving (below), and **Kalender, Posts and Wiki** save through `siteSaveListResource(resource, listKey, update)` (`site-utils.js`): boss `resource_read` returns the live file + sha, `update(liveList)` applies just this one change (add/edit/delete by `id`; may be async; a string = error message, `null` = cancelled), then the save sends `baseSha` and a 409 `stale` re-reads and re-applies (3 attempts). The result list becomes the override shadow. So a tab open all day never drops what others saved meanwhile. Same-item edits are last save wins, except Wiki's in-place chapter editor, which asks before overwriting a chapter someone else saved since editing started (`wikiConfirmOverwrite`); editing something deleted meanwhile shows "… slettet af en anden". Posts' edit keeps the live `pinned`/`comments`; Wiki's "Rediger kapitler" applies only its own order/adds/removals/title and publish changes, keeping chapters added by others (at the end).
- **Every write caller treats a reply as success only when the body parses as JSON with `ok === true`** (`siteSaveResource`, `siteFileAction`, `budgetApi`, `formsApi`, `faellesApi`, `bandApi`, `postsApi`, `manusApi`). A PHP fatal or a proxy/WAF error page can arrive as HTTP 200 + HTML; this rule was learned the hard way when a form wrongly reported success. `update-data.php`'s shutdown handler turns a fatal into a JSON 500 when it can.
- **Rendering rule**: build DOM via `createElement`/`textContent` — never `innerHTML`. Two deliberate, scoped exceptions: Wiki and Posts rich-text bodies (sanitized via a detached `DOMParser` document and rebuilt from an allow-list — see Wiki). `escHtml()` in `schedule.js` is the sanitizer for Øveplan's own `innerHTML` templates.

## Kalender (`kalender.html`/`calendar.js`, `data/calendar.json`, boss-level editing)

1200px-wide page. Month grid + list toggle (view persists in `localStorage`, defaults to list at ≤719px). List view shows only upcoming events, grouped by month. `category` is an ASCII key; `CAL_CATEGORIES` in `calendar.js` is the source of truth for label/order/color (duplicated in `embed-scenes.js`'s `.ics` builder). Multi-day events carry `endDate` (`>= date`); `calEventEndDate(ev)` is the one helper for "when does this end." A month-grid chip opens a read-only detail modal; boss/admin also get "Rediger" there. Date/time/category fields use the shared pickers.

- **`.ics` subscribe feed**: a static RFC 5545 file built by `embed-scenes.js` (`raw: true` entry), written by the worker to `/data/site/generated/calendar.ics` and served at `/calendar.ics`. Timed events are real UTC (`Z`) `DTSTART`/`DTEND` via `copenhagenOffsetMinutes()`/`icsUtcDateTime()` — a hand-coded, DST-aware Europe/Copenhagen offset (EU last-Sunday-of-March/October rule), no timezone library. Floating local times were misread as UTC by Google Calendar's URL importer, and a `TZID` + embedded `VTIMEZONE` attempt was also unreliable there; real UTC has nothing to mishandle. `X-WR-TIMEZONE:Europe/Copenhagen` is a harmless hint for other clients. All-day events use `VALUE=DATE` with `DTEND` one day past `endDate` (exclusive).
- **Revyperiode Gantt** (`data/gantt.json`, **admin** `gantt` resource, `renderGantt()`): second card, public to read (hidden while empty). Axis September–November of the stored `year`; admin-named rows, each with `{start, end, label, color}` bars (`color` one of six `GANTT_COLORS`, picked via swatches; falls back to a per-row cycle), positioned by percentage, clipped to the window, stacked into lanes on overlap. Hover shows `calShowTooltip` (label + date range). ## Arkiv (`arkiv.html`/`archive.js`, `data/archive.json`, admin editing)

One square-cover card per year. ## Forside (`index.html`): Posts + Bosser

## Wiki (`wiki.html`/`wiki.js`, `data/wiki.json`, boss-level)

A flat chapter list, `{id, title, body, published?, attachments?}`. `body` is sanitized HTML limited to `WIKI_ALLOWED_TAGS` (`b/strong`, `i/em`, `u`, `ul`, `ol`, `li`, `p`, `br`, `h2`, `h3`): untrusted HTML is parsed into a **detached** `DOMParser` document (never executes, never attached) and rebuilt with allow-listed `createElement`/`createTextNode`, copying no attributes — no persisted-attribute XSS surface. `<a>` isn't allowed; links are auto-detected from text at render time. On load a backup for the current production folder is offered in a banner above the tabs (`manusRenderBackupBanner`, Gendan/Kassér; nothing is written while the offer is open). The run writes `{state: running|done|failed, startedAt, finishedAt, errors}` to `PDF_STATUS_FILE` (`/data/site/generated/pdf-status.json` on web-1, not web-served; `.pdf-status.json` locally). Each error is located by `buildErrorEntry()`: the `.tex` builders emit `% matrevy:part=titel|roller|manus` / `% matrevy:scene=<id>` / `% matrevy:part=medvirkende|ordliste` / `% matrevy:qr=<id>` comment lines, and walking back from the log's `l.<N>` to the nearest marker gives the scene, part and line within the manus/Program text; a "Unicode character X" error instead searches the scenes' fields for X (pdflatex reports a `\title{}` at `\maketitle`, and Rolleoversigt's `\resizebox` at the box's end). pdflatex halts on the first error per file, so one run shows at most one error per document.

No run picked up within 30 s (and no older one running) → "PDF-generatoren startede ikke". Polling never prompts for a password (`manusApi(…, {prompt:false})`); without one it falls back to `siteFileStatus` on `manus.pdf`'s `Last-Modified`. 10 min timeout, shown explicitly. On load, a failed last run turns the "Sidst genereret" line into "Seneste generering fejlede. Vis detaljer", and a run still going resumes the "Genererer..." state. The quick-link buttons append `?v=<lastGeneratedAt>` (redundant now that everything is `no-cache`, harmless).
- `save_manus()` stamps `generatedAt` on every save (separate from the day-granularity `version` printed in each manuscript header) — a leftover from the git era, harmless.

### Program tab (`data/program.json`, boss/admin) — printed programme booklet

Generates `archive/<folder>/Program.pdf` (front cover / Aktoversigt / Medvirkende / Ordliste / QR page(s) / back cover). The sixth Main Manus View tab, independent of `manusDraft` (not per-scene), with its own `programDraft` + `siteLoadOverride`/`siteSaveOverride` shadow. **Auto-saved, not part of Gem** (`programAutosave` → `programSaveNow()`): each save sends `baseSha` (from `program_read` or its own last save, which `save_program` returns); on a 409 it re-reads and merges per section (Medvirkende / Ordliste / QR-koder) against `programBase`. A section only they changed is pulled into the draft; one both changed shows a banner in that section ("Behold min" / "Brug deres", `programConflicts`) and waits while the others save. Status line at the top of the tab (`manusAutosaveStatusEl`).

- **Medvirkende**/**Ordliste** are each a single **raw-LaTeX** textarea (`\arb{Kategori}` headers, `\\`-terminated lines), inserted verbatim — not escaped, not sorted (ordering is the editor's job). **QR-codes** `{label, url}`: the PNG is generated at build time from `url` via `qrcode`, never stored; added via a centered "+" (`.boss-manage-add-plus`); only `label`/`url` are `texEscape()`'d. A QR row is saved only once it has a label and a valid (or empty) link (`programQrSaveable`); until then it lives in the draft only. QR rows are draggable but have no custom drag image/drop tail (the one exception to the drag convention below).
- `buildProgramSections()` sources Aktoversigt from `scenes.json` (centered `\Huge`, like the original hand-written `program.tex`, not `Aktoversigt.pdf`'s numbered layout) and **excludes the `E`/Ekstranumre act**. Front cover = the current production's Arkiv `coverImage`, falling back to `archive/_assets/placeholder-cover.jpg`; back cover is always that placeholder. The six pieces compile as separate PDFs (Medvirkende/Ordliste have unknowable page counts); `composeProgramPdf()` assembles `Program.pdf` in reading order and a reordered "booklet source" (front, Aktoversigt, Ordliste, Medvirkende, blanks, QR, back — see `imposeBooklet()`'s comment) padded to a multiple of 4, which `imposeBooklet()` imposes two-up on landscape A4 in saddle-stitch order: `ProgramHaefte.pdf` (vertical flip) and `ProgramHaefteHorisontal.pdf` (every back side rotated 180°). The booklet order is a fixed template sized for a normal year (two folded sheets), by product decision.
- Rebuilt by "Generér PDF'er" like the other PDFs. `data/program.json` must exist before the first save (no create-if-missing); if missing, `generate-pdfs.js` skips Program with a notice.
- **Not reset** by Koordinator's close-year: a new production inherits Medvirkende/Ordliste/QR as a starting point.

## Koordinator (`koordinator.html`/`koordinator.js`, admin-only)

The card re-reads the live file once per page load (`koordFraRefresh`) to show imports newer than the embed.

Secret, so stored in the private `KOORD_DATA_DIR` (`/data/koordinator/logins.json`) via the admin `$KOORD_ACTIONS` `koord_logins_read`/`koord_logins_save` (full replace of the list, ≤30), never in public data or the repo. Config is read as `koordConfig()` (`CONFIG_DATA` + the `config` override shadow, so this tab's own saves show without a reload).

Teknikken's text says to "Download alt" and upload the videos to YouTube (no login info on the site: the repo and config are public). ## Budget (`budget.html`/`budget.js`/`budget.css`) — private datastore

Digitises the revue's reimbursement/accounting workflow. Revyst-level page. Its data (names, phone numbers, receipt photos) is personal, so it lives only in `BUDGET_DATA_DIR` (`/data/budget` on web-1), never in a web-served folder, read/written only through authenticated `update-data.php` actions.

- **Two audiences**: `siteHasLevel('boss')` → management view, **read-only below admin** (`budgetReadOnly()`: no save bar, approve/edit/split/reject, Tilføj udgift, pencils, Forbind/Nulstil, "+"/✕ or drag; amounts shown as text via `budgetMarkReadOnly`/`budgetReadOnlyAmount`; receipts, filters, mode tabs, budget picker and Udskriv still work); else revyst → submit form (a boss submits from the Revyst view). Online-only.
- **`budgetApi(action, body)`**: its own authenticated POST helper (a revyst-level submit needs a revyst password, which `siteSaveResource` won't use); JSON-`ok` rule as everywhere. Receipt images are re-encoded to JPEG client-side with a `createImageBitmap`→`<img>`→original-bytes fallback chain (HEIC iPhone photos always upload); receipts are streamed password-gated (`budget_receipt`), never at a public URL.
- **Categories** are per-budget data (`categories.json`, `{expense:[{key,label,abbrev,subcategories?}], income:[{key,label}]}`), lazy-seeded from `budget_default_categories()` and admin-editable via the sheet's "Rediger" toggle (`buildCategoryEditSection`/`budget_categories_save`). Receipt filename + bilagsnummer is `<abbrev>_<n>`, numbered per category at approval; deleting/re-abbreviating a category with a paid expense is blocked (`abbrev_locked`).
- **Sub-categories** (one level, `{key,label}`, sharing one global key namespace so `planned`/`subBreakdown` lookups are unambiguous): edit mode's per-row chevron expands an indented sub-list (same draft, drag helpers, `.budget-subcat-drop-tail`, delete confirms). A category with subcategories shows a read-only Planlagt sum of its subcategories' editable Planlagt; each subcategory gets a derived Brugt/Rest (`computeSpentBySubcategory` over expenses' `subBreakdown`). Revyster only pick the top-level category; splitting happens at approval/"Tilføj udgift"/expense edit, where `subBreakdown` must sum to the amount (`budget_validate_breakdown_sum`, shared with Stregregnskab's `stregBreakdown`). The protected `stregnskab` category never has subcategories and is excluded from the main sheet.
- **⚠️ PHP const-ordering landmine** (whole file): `update-data.php`'s top-level `const`s are registered in execution order, so a const used by a handler dispatched *before* its declaration line is `Undefined constant` at call time. Budget/Forms/Fællesspisning/upload handlers dispatch near the top, so they use **hoisted functions** instead (`budget_receipt_re()`, `budget_max_upload_bytes()`, `budget_default_categories()`, `budget_streg_category_key()`, `upload_path_level()`, …) or consts declared above the dispatch. Any new early-dispatched handler must do the same.
- **Per-budget datastore**: `BUDGET_DATA_DIR/<budgetId>/{budget,requests,expenses,categories,streg}.json` + `receipts/`, beside a root `years.json` (`{activeBudgetId, years:[{budgetId, year, label, createdAt}]}`). Several budgets can share a `year`; `label` is unique (checked on create and rename). Legacy budgets have `budgetId` = the year as a string (`budget_normalize_years_shape()` back-fills on every read); new ids are `<year>_<label>` slugs (`budget_slugify_budget_id()`), which can never collide with a bare year. `budget_active_budget_id()` resolves where revyst uploads land; `budget_resolve_budget_id($body)` lets admin handlers target any budget (default active); `budget_submit` always uses the active one. Year actions: `budget_create_year` (seeds `planned` from the budget closest in time), `budget_set_active_year` (`null` allowed), `budget_rename_year` (metadata only), `budget_delete_year` (recursive delete; clears `activeBudgetId` if needed). No server-side confirmation — the client asks.
- **No active budget is a supported state**: "Skift aktivt budget" has an "Intet valgt" option; revyst submissions then get an explicit `no_active_year` state, and every budget stays browsable by explicit `budgetId`. `loadAndRenderAdmin()` re-fetches the most recently created budget when nothing is active, so deleting the active budget lands on real data.
- **Server actions** (`$BUDGET_ACTIONS`): revyst — `budget_submit`, `budget_active_year_info`, `budget_active_categories`; boss (the read-only view) — `budget_read`, `budget_receipt` (strict filename regex, the only guard against reading arbitrary files), `streg_read`; admin — `budget_approve`, `budget_request_reject`, `budget_request_update`, `budget_request_split` (one receipt → several expenses), `budget_save_sheet`, `budget_expense_add`/`_update`/`_remove`, `budget_categories_save`, the four year actions, and `streg_upsert_row`/`streg_delete_row`/`streg_save_rows`/`streg_save_categories`/`streg_save_connection`. Storage uses `budget_mutate()` (flock'd read-modify-write, no sha/409).
- **Admin layout**: Budget sheet (planned/brugt/rest per category; brugt always derived) + Afventende udlæg side by side, Betalte udgifter below. A year toolbar picks the viewed budget (`budgetViewId`, in `localStorage`) independently of the active one. Godkend stamps `paidBy`/`settled:true`/the submission date; category, bilag and receipt lock once paid.
- **Height sync** (`budgetSyncPendingColumnHeight`): Afventende udlæg's list gets Budget's exact height (scrolling or padding out); `renderPendingSection()` always wraps content in `.budget-scroll-wrap` (even the empty state), whose `flex-basis` must stay `auto` (a `0%` basis ignores an explicit `height`). No-op in streg mode.
- **Stregregnskab** (`budgetStregMode`; tab bar `renderBudgetModeTabs`/`budgetSwitchMode`, styled like Formularer's tabs, mode in `localStorage`): swaps the Budget card for a names × drink-category grid and Afventende udlæg for "Priser", hiding Betalte udgifter. Data in `streg.json` beside the budget's other files (`budget_load()`/`budget_mutate()`), seeded Øl/Cider/Soda (`streg_default_doc()`).
  - **Grid** (`buildStregSheetCard`/`stregBuildTable`): always editable (Fællesspisning look), **auto-saved per row** like Fællesspisning: Navn and each count commit on change (blur), "har betalt" on click, each sending only the changed field via `streg_upsert_row` (`stregCommitRow`; `navn`/`paid` replace, `counts` merges per key, 0 clears it), so two admins editing different rows/cells don't overwrite each other. Commits on one row are chained on `row._inFlight` (a create always lands before the edits queued behind it). A "+" row stays local (in the working copy `stregSheetDraft`) until its Navn is filled; clearing a saved Navn puts the saved one back (the server refuses empty). Status ("Gemmer …" / "Gemmes automatisk" / the error) sits in the bottom bar (`.streg-save-group`, `stregPaintSaveStatus`); `beforeunload` warns while a save is in flight. Betaling and Priser's per-streg price recompute on every keystroke against the working copy. Row removal confirms (unless never saved) and deletes right away (`streg_delete_row`, idempotent). **Nulstil** clears every row (`streg_save_rows` with an empty array — its only remaining caller) and disconnects a Formularer connection first (it would re-sync names back). "Forbind" (Formularer Navn-field mapping, `streg_save_connection`; `streg_read` lazily syncs via `streg_maybe_sync`). A truncated Navn shows the full name in a tooltip (`budgetShowFieldTooltip`); checkbox + input live in `.streg-navn-wrap` (a flex `<td>` broke the row border). A "har betalt" checkbox (`.streg-paid-checkbox`, persisted `paid`) strikes through the row's Betaling (`.streg-paid`). **Udskriv** (`.budget-center-btn`) prints the current grid as a plain table via `#budget-print-sheet` + `window.print()`.
  - **Priser** (`buildStregPricesCard`): **live-save** — Navn/Indkøbspris commit on blur, reorder commits on drop (`budgetWireDropHighlight`/`budgetMoveDraftItem`); each commit resends the whole list (`streg_save_categories`; unknown `key` → `stale_categories`, omitted `key` → new) and refreshes the grid. A new row isn't sent until its Navn is filled. Deleting asks first and is blocked at zero categories; existing tallies for a removed category are left alone server-side. Per-streg price previews live against the typed price (`stregPriceRefreshComputed`).
  - Pris pr. streg and Betaling are derived client-side only (`stregComputePricePerUnit`/`stregCategoryTallyTotal`, which take an explicit `rows` list so the grid can pass its draft).

## Formularer (`forms.html`/`forms.js`/`forms.css`) — self-hosted sign-up forms

Replaces the ~5 Google Forms rebuilt every year. Revyst-level page. Definitions, templates and responses (names, phone numbers) all live in the private `FORMS_DATA_DIR` (`/data/forms`) — no public consumer of a form's schema exists.

- **Two audiences**: `siteHasLevel('boss')` → management (build/edit forms and templates, view/export responses); else revyst → open forms + fill-in. Boss-level (coordination tooling, like Manus/Kalender).
- **`formsApi(action, body)`** mirrors `budgetApi` (any logged-in level; JSON-`ok` rule).
- **Storage**: `FORMS_DATA_DIR/forms/<formId>/{definition,responses}.json` + one `templates.json`. No year/active concept — several forms can be open at once. `formId`/`templateId` are server-generated hex (`forms_id()`), validated with `forms_valid_id()` before building any path.
- **Structure**: a form has `sections` (`{id, title, description, fields}`); an old top-level `fields` array is converted on read. A `FieldSpec` is `{id, type, label, required, optionsSource?, options?, sourceFilter?, …}`. Types: `text`, `textarea`, `select`, `checkboxes`, `scale`, `grid_single`, `grid_multi` (+ legacy `yesno`, accepted but no longer offered). `optionsSource` (`manual`/`scenes`/`rehearsals`) is orthogonal to type: live sources resolve client-side at render time from `SCENES_DATA`/`CALENDAR_DATA` (`formsOptionsFromScenes`/`formsOptionsFromRehearsals`, rehearsals = category `ove`), never stored — `forms.html` loads `scenes-data.js`/`calendar-data.js` for this.
- No hardcoded name/phone fields — "Navn" is just a required `text` field.
- **Frist** (`deadline`): `'YYYY-MM-DD'` or `'YYYY-MM-DDTHH:MM'` via `siteCreateDateTimeField`, shown with `formatDaDateMaybeTime`.
- **Synlighed** (`visibility`, `'boss'` default or `'admin'`): restricts only a form's responses (Statistik/Svar) — withheld server-side by caller level (`forms_visibility()`/`responsesRestricted`); the definition stays boss-editable. Oversigt greys out the icons for a boss on a restricted form.
- **Svar screen**: above the table a collapsible **Betingelser** card (`formsBuildResponseConditionsCard`, closed on every visit) hides rows that don't match its conditions, live; it uses the same `formsCreateConditionEditor()` as the Eksportér CSV modal (offered every fixed-answer question, not scoped to columns), shows the active count in its title ("Betingelser (2)") and "Viser N af M svar", and "Fjern betingelser" resets it. Each row starts with an eye button and ends with the ✕ (slet svar). The eye opens that one response as the whole form stacked on one page (`formsRenderResponseDetail`: the fill-in widgets via `formsRenderAnswerInput`, filled and locked by `formsFillAnswerInput`, text read-only and choice widgets `inert`; dependency-hidden fields left out; an answer with no matching live option shown as text); the ← top right swaps the table back in, with its conditions, pins and scroll intact (no re-fetch).
- **Svar table**: the question row is sticky inside `.forms-responses-wrap`'s own scroll box. Clicking a column title (Sendt or any answer column) opens a one-row popup, "Fastgør kolonne"/"Frigør kolonne" (`formsOpenStickyColMenu`). A pinned column is `position: sticky` with both `left` and `right` (`formsApplyStickyColumns`, offsets = summed widths of the other pinned columns), so it catches on whichever edge it would scroll out of. Pins are per browser and per form, in `localStorage` `matrevy-forms-sticky-cols`.
- **Validation posture**: `forms_submit` checks shape/type/length only, never live options (a race between page load and submit must not lose a submitter's work).
- **Oversigt rows drag to reorder** (`formsWireDropHighlight`/`formsMoveListItem`, within the year-filtered view): the client stamps `order` 0..N-1 optimistically, then `forms_reorder` writes it into each `definition.json`. `forms_save` carries an existing `order` through; new forms get `null`. `formsCompareOrder`: ordered forms first, then by `id` (hex-timestamp prefix ≈ creation order).
- **Dynamic templates** (`FORMS_DYNAMIC_TEMPLATES`): client-only `{id, title, description, generate}` entries run fresh against embedded data and applied through the normal template path — `rolleonsker` (`formsGenerateRolleonskerSections`: fixed sections, one section per act incl. Ekstranumre with one 1-5 Skala per non-song scene and two (Sanger/rapper + Danser) per song, skipping `schedulable:false`, plus a Fravær section) and `fravaer` (`formsGenerateFravaerSections`: one text field per `ove` event in October–November of the current year).
- **Server actions** (`$FORMS_ACTIONS`): revyst — `forms_list_open`, `forms_get`, `forms_submit`; boss — `forms_admin_list`, `forms_admin_read`, `forms_save`, `forms_reorder`, `forms_delete`, `forms_delete_response`, `templates_list`, `templates_save`, `templates_delete`. Saves are create-or-update by optional `id`, full replace; Åben/Lukket just resends the definition. CSV export is client-side. The first save creates whatever directories it needs.

## Fællesspisning (`faellesspisning.html`/`faellesspisning.js`/`faellesspisning.css`) — communal-meal sign-up

One row per person (alphabetical by Navn, Danish collation — `localeCompare(..., 'da', {sensitivity:'base'})`), one column per rehearsal/performance day, a checkbox = "eating that day", plus a per-day headcount/food-preference summary. Revyst-level page; private data in `FAELLESSPISNING_DATA_DIR` (`/data/faellesspisning`). Replaced the old generic "Ark" page.

- **Attendance default (opt-out/opt-in)**: each row carries its own `attendanceMode`, stamped by the server at creation (`faelles_upsert_row` create, `faelles_sync_connection` new rows) from the document's `attendanceMode` (`faelles_attendance_mode()`; missing = `'out'`, so every row from before the setting is opt-out). `'out'`: a day defaults to **checked** from the row's own `createdAt` date onward, unchecked before. `'in'`: every day defaults to unchecked. Switching the setting only affects rows created afterwards. `row.dayOverrides` (`{dayId: bool}`) stores only deviations; a row without it reduces to the default. `faellesDayDefault(row, col)`/`faellesIsDayChecked(row, col)`/`faellesRowMode(row)` are the source of truth (server: `faelles_validate_day_overrides()`). An unsaved draft row previews the sheet's current mode against today. Overrides for removed/hidden days are left alone.
- **Notice** (`faellesBuildNotice`): two short lines centered in the sheet card's toolbar. The bold `notice`, default "Madtilmelding lukker kl. 12 på dagen" while never set (`faelles_notice()`), and under it the plain, muted `subNotice`, default "(I bliver automatisk tilføjet madarket gennem tilmeldingsformularen)" (`faelles_sub_notice()`); `''` = that line isn't shown. Boss/admin edit each in place (inline field style, saves on blur/Enter, Escape reverts) via `faelles_set_notice`, which changes only the keys sent; plain text below boss.
- **Boss Box** (`faellesBuildBossBox`, boss/admin, a collapsible card above the sheet, closed on every load — `faellesBossBoxOpen` is in-memory only): "Forbind til formular" (explanation, "Forbundet til: …"/"Ikke forbundet", Forbind/Skift forbindelse → `faellesOpenConnectModal`) and "Tilmelding for nye rækker" ("Nye rækker er" dropdown Automatisk tilmeldt alle dage / Ikke tilmeldt nogen dage → `faelles_set_attendance_mode`, toast on save).
- **Two fixed columns**: Navn and Madforbehold (`FAELLES_FIELDS`). Boss/admin drag a grip on either header's right edge to resize it (`faellesColumnResizer`, Bandet's recipe; double-click resets), saved for everyone as `columnWidths` `{navn?, madforbehold?}` px via `faelles_save_column_widths` (full replace, 40-1000). The table keeps its auto layout: a width is applied as `--faelles-w-<id>` + `.faelles-sized-<id>` on the table (`faellesApplyColumnWidths`), pinning every cell of that column; header/summary labels sit in `.faelles-clip` so their text can't hold a narrowed column open. A truncated Navn/Madforbehold shows its full text in a tooltip.
- **Rows**: any revyst+ can edit any existing row (shared passwords, no per-user identity), but only boss/admin add (the "+" row; `faelles_upsert_row` without `rowId` is checked for boss at dispatch) or delete rows (the ✕ column); revyster get neither, and rows normally arrive through the connected form. `faelles_delete_row` is idempotent.
- **`faellesApi(action, body)`** mirrors `formsApi`/`budgetApi`.
- **Single document**: `faellesspisning.json` = `{rows, connection, extraDays, hiddenDays, attendanceMode, notice, subNotice, columnWidths, updatedAt}`; `faelles_extra_days()`/`faelles_hidden_days()` back-fill `[]` for older documents.
- **Row-granular, live writes**: `faelles_mutate()` (flock'd) backs `faelles_upsert_row`, which **merges** sent `answers` keys and **full-replaces** `dayOverrides`. No batched draft: fields commit on blur, checkboxes on change; `row._inFlight` chains same-row commits (no duplicate creates); each request is built when its turn comes, and only the reply to the latest edit (`row._editSeq`) may overwrite the row, so quick successive edits are never dropped. `faellesSavesPending` drives a `beforeunload` warning and `siteRegisterUnsavedCheck`.
- **Day columns** = Kalender's `ove`/`forestilling` events (read live, minus `hiddenDays`; `faellesCalendarOverride` mirrors Kalender's own override so a new event shows immediately) + the document's own `extraDays`, filtered to the current rolling half-year (`faellesCurrentHalfYearRange()`: Jan–Jun or Jul–Dec of today), sorted by date, labeled `d/m` with the event title as tooltip (`faellesShowFieldTooltip`). Not keyed off `currentProductionFolder` (a jubilee revy can run alongside).
- **Boss adds a sheet-only day** via the "+" after the last column (`faellesOpenQuickAddDateModal` → `faelles_add_day`, into `extraDays`; never touches Kalender). **Every column is removable** (bottom-row "✕", `faellesOpenDeleteDayConfirm`): an extra day is deleted (`faelles_delete_day`), a calendar day is only hidden from this sheet (`faelles_hide_day` → `hiddenDays`; no un-hide UI).
- **Summary** is client-side: headcount per day, and an "ⓘ N" button per day opening a modal of only the attendees with a food preference (`faellesOpenPreferencesModal`).
- **Server actions** (`$FAELLES_ACTIONS`): revyst — `faelles_read` (also lazily syncs), `faelles_upsert_row` (creating a row: boss); boss — `faelles_delete_row`, `faelles_add_day`, `faelles_delete_day`, `faelles_hide_day` (calendar ids validated as bounded strings), `faelles_save_connection`, `faelles_set_attendance_mode` (`mode: 'in'|'out'`), `faelles_set_notice` (`notice`/`subNotice`, ≤200 chars each), `faelles_save_column_widths`.
- **Connect to a Formularer form** (boss; from the Boss Box; `faellesOpenConnectModal`): pick a form and which fields answer Navn and Madforbehold (reuses `forms_admin_list`/`forms_admin_read`). Persistent: `faelles_save_connection` stores `{formId, navnFieldId, madforboholdFieldId, formTitle, syncedCount}` (the key's misspelling is real) and syncs; every `faelles_read` runs `faelles_maybe_sync()` — a lock-free response-count check that only locks and reconciles when there's new data. Synced rows carry `source: {formId, responseId}` and are updated in place (only Navn/Madforbehold; `dayOverrides` untouched); `faelles_forms_answer_to_text()` stringifies any field type. Disconnecting keeps synced rows; a hand-deleted row reappears on the next sync while its response exists (one-way). Disconnect confirms via `faellesOpenDisconnectConfirm`, stacked on the connect modal.
- **Buttons**: the Boss Box's Forbind is `.btn-small` (no "Opdater" — a page refresh does the same); "+"/"✕" affordances use `.boss-manage-add-plus`/`.faelles-remove-btn`/`.faelles-col-day-remove`; modal buttons are `.site-btn-*`; deletes confirm with a styled modal, never `confirm()`. Checkboxes use `accent-color: var(--accent-warm-text)`.

## Bandet (`band.html`/`band.js`/`band.css`) — the band's folder

Replaces the band's Google Drive folder (a "Sangoversigt" spreadsheet + one folder of sheet music per song). Revyst-level page under Redskaber. **Edit rights per folder** (`bandCanEdit()` / server `band_folder_writable()`, checked at dispatch for every non-read action): only the **active folder** is open to any revyst+ (like the Drive folder); older revys, extra instances and the Arkiv tab's `_arkiv` store are view-only below boss (inputs `readOnly`, no add/remove/drag/upload/rename; server answers 403 `read_only`). Creating/editing/deleting extra instances is boss-level. The active folder is chosen in the boss-only **Boss Box** card beside Bandmedlemmer ("Aktiv mappe") (`bandBuildBossSettingsCard` → `band_set_active_folder`, stored as `BAND_DATA_DIR/settings.json` `{activeFolder}`); unset → `currentProductionFolder`. `band_instances_read` returns it as `activeFolder`; deleting the active instance resets it to unset. Private data in `BAND_DATA_DIR` (`/data/band`) — sheet music is often copyrighted, so never a web-served folder and never in the GitHub archive mirror. Online-only.

- **Per revy**: a revy picker top-right of the title (`siteCreateDropdownField`) lists Arkiv's years by `folder` (newest first, plus the current production if it has no Arkiv entry yet) and the band's **extra instances**, default `currentProductionFolder`, choice in `localStorage` `matrevy-band-revy`. Storage: `BAND_DATA_DIR/<folder>/band.json` = `{rows, instruments, columnLabels, columnWidths, updatedAt}` + `files/<rowId>/<fileId>.<ext>`. A revy without a document reads as a default (sections Revysange / Pausefisk, sketchsange eller dansenumre / Bandintroer og -jingles; Bandmedlemmer copied from the most recently edited other revy, else a built-in list: Vokal, Klaver, Guitar, Bas, Trommer, Trompet, Alt Sax, Tenor Sax, but only for the active folder, the current production or an extra instance (`band_folder_inherits_members()`); an older Arkiv year starts with an empty table) with **deterministic ids** (`band_default_id()`), so a default row can be edited before anything is written.
- **Extra instances** (e.g. "MatGalla 2025" — the band also plays the Galla): registered in `BAND_DATA_DIR/instances.json` = `{instances:[{folder, name, year, createdAt}]}` (flock'd `band_instances_mutate()`); each one's data is an ordinary band folder, so every row/file action and the Arkiv tab work unchanged. The picker's last option "+ Opret ny" (`BAND_NEW_INSTANCE`) opens a Navn + År modal; `bandRevyOptions()` sorts year desc, and within a year Arkiv's revy before instances (MatRevy 2025 → MatGalla 2025 → MatRevy 2024). `folder` is slugified from the name once (`band_slugify_folder()`, a port of `slugifyFolderName`) and never recomputed; it gets a `_2`… suffix past any clash with an instance, an existing band dir, `_arkiv`, or the client-sent `avoid` list (Arkiv's folders, which only the client knows); the client also rejects a label already in the picker. When the selected folder is an instance a "Rediger" button sits beside the picker: rename/change year (`band_instance_update`, folder unchanged) or Slet (`band_instance_delete`, registry entry first, then `band_remove_tree()` of the whole folder; refuses anything not registered, so never an Arkiv revy or `_arkiv`). Actions: `band_instances_read` (revyst), `_create`/`_update`/`_delete` and `band_set_active_folder` (boss). The registry loads before the picker renders (`bandInit()`).
- **`rows`**: one flat ordered list of `{id, type:'section', title}` and `{id, type:'song', originaltitel, revytitel, originalToneart, revytoneart, instruktoer, sangere, arrangement, arrangementKlar, files:[{id, name, ext, size, uploadedAt}]}`. `arrangementKlar` is `''`/`'delvis'`/`'klar'`, shown as a click-to-cycle pill `-` / `(Tjek!)` / `Tjek!` (the old sheet's convention).
- **Renamable column titles**: every sheet column and the Bandmedlemmer table's three headers are editable in place (a wrapping `contenteditable` `.band-head-input`, read via `textContent`, so long titles wrap instead of truncating). Only renamed titles are stored, in `columnLabels` (`{key: title}`, keys from `band_column_label_keys()`); clearing one brings the default back. Defaults: Title / Revytitel / Toneart / Revytoneart / Instruktør / Sanger(e) / Arrangement / Klar, and Navn / Instrument(er) / Stemmer.
- **Adding/removing columns** (per band folder, `band_save_columns`, full replace of both lists): clearing a column's title and pressing Backspace/Delete once more (`bandColumnTitleInput`'s `onDeleteEmpty`) opens a "Fjern kolonnen?" confirm — a built-in one is only **hidden** (`hiddenColumns`; its values stay on the rows and come back when re-added), a **custom** one (`customColumns: [{key: 'c<hex>', label, type: 'text'|'status'}]`, values stored on the row under `key` like a built-in's) is deleted along with its values, title and width. `originaltitel` (Title) can't be removed — Arkiv is keyed on it. The "+" in the header's actions cell opens "Tilføj kolonne": a new column (Navn + Tekst/Status) or a previously removed built-in. `bandSheetColumns()` = visible built-ins + customs (inserted before Klar); `bandAllValueKeys()` covers hidden ones too (drafts, content check). The server validates row fields, titles and widths against the folder's current custom keys (`band_custom_keys()`).
- **Resizable columns**: the sheet is a `table-layout: fixed` table sized by a `<colgroup>` (default px in `BAND_COLUMNS[].width`, table width = `max(100%, sum)`: fills the card, scrolls when wider). A grip on each header's right edge (`bandColumnResizer`, pointer events → touch works) drags a width (min 48px); double-click resets it. Only dragged widths are stored, shared per band folder like the titles: `columnWidths` `{key: px}` via `band_save_column_widths` (full replace, 40–1000px, sheet keys only). Cells keep their own colour while focused (only the warm border marks focus).
- **Each song row *is* a folder**: tab **Oversigt** is the sheet (+ the **Bandmedlemmer** table: Navn / Instrument / Stemmer i, stored as `instruments: [{id, navn, name, stemme}]`, rows drag-reorderable by their handle — `bandMoveMember`, saved via the full-replace `band_save_instruments`), tab **Noder** lists the same song rows as collapsible folders, in a 3-column grid per section (1 column ≤719px), sorted alphabetically by title within each section (Danish collation; the sheet's own order is untouched, so `bandRerenderFolder` finds a card by `data-row-id`, not position). "+ Ny mappe" = a new song row (revytitel + section); renaming happens in Oversigt; deleting a row deletes its files. Tabs styled like Koordinator's (`.band-mode-tabs`, duplicated), active tab in `matrevy-band-tab`.
- **Arkiv tab** (third tab; the revy picker stays visible, and picking a revy there only takes effect back on Oversigt/Noder): the long-term sheet-music library across every revy. `band_archive_read` returns every song row with a title (`originaltitel`, fallback `revytitel`) from every `<folder>/band.json` plus the reserved **`_arkiv`** store; the client merges equal titles (trimmed, case-insensitive) into one card, sorted alphabetically (Danish collation), files grouped by source (Arkiv first, then revys newest first). Arkiv only ever writes to `_arkiv` (`BAND_ARCHIVE_FOLDER`/`band_archive_folder()`; its leading `_` can never match `band_valid_folder()`, and `band_folder_from_body()` accepts it explicitly, so every row/file action works on it): "+ Ny sang" creates an `_arkiv` row (an existing title just opens its card), and uploading to a card without an `_arkiv` row creates one first (`row._ensureCreated`, so a cancelled upload leaves nothing). A search box centered in the card head (`bandArkivQuery`) filters cards by title as you type — in place via `hidden` (`bandApplyArkivFilter`), so the input keeps focus; the query survives re-renders. Only the `_arkiv` part of a card can be deleted there; a revy's song is deleted from its Oversigt. Rows carry `_folder`/`_arkivKey`, and every file call sends `folder: row._folder || bandFolder`; `bandRefreshRow()` re-renders the right card/folder.
- **Live writes** like Fællesspisning (no Gem): text cells commit on blur, pills on click, drag-reorder (handle-only, so inputs keep text selection) on drop. A new row is a client draft until its first non-empty blur (`row._inFlight` serializes); a section's "+" inserts at the end of that section via `afterId` (the only way to add a song in Oversigt); the centered "+" under the sheet adds a section. No "Opdater" button — a page refresh does the same.
- **Files**: `.pdf`/`.mscz`/`.mscx`, 15 MB (`band_max_upload_bytes()`/`BAND_MAX_UPLOAD_MB`; base64 must fit php.ini's 25M `post_max_size`), uploaded one at a time (button or drag-from-desktop onto a folder). Stored under server ids — the original filename is metadata only. `band_file` streams bytes with the password; Picking or dropping files opens a modal (`bandOpenUploadModal`) that asks for each file's name (the part — Trompet, Sax, …), required; it's sent as `<name>.<ext>` (`/`/`\` → `-`), so that name is both what the page shows (extension stripped, `bandFileDisplayName`) and the download filename. A PDF's name opens it as a blob in a window opened synchronously in the click (popup blockers); the download icon saves any file via `a[download]`; the pencil (`bandOpenRenameFileModal` → `band_rename_file`) renames it — name only, the stored extension is kept. Lists show PDFs first and MuseScore files last (`bandSortedFiles`, upload order within each); no size/date line. The "Upload filer" bar is centered under each folder/card. Badges: `MSC` (MuseScore) blue, `PDF` grey. A folder card shows the revy title with the original title smaller underneath — except in an extra instance, which has no revy titles: `bandSongLabel()` then uses the original title alone.
- **Server actions** (`$BAND_ACTIONS`, revyst except the instance writes, every row/file one takes `folder`; writes outside a revyst-writable folder need boss): `band_read`, `band_upsert_row` (create, or merge only the sent fields), `band_delete_row` (idempotent, removes `files/<rowId>/`), `band_reorder` (must be a permutation of the current ids, else 409 `stale_rows` → the page reloads), `band_save_instruments` (full replace), `band_save_column_labels`/`band_save_column_widths`/`band_save_columns` (full replace), `band_upload_file`, `band_delete_file`, `band_rename_file`, `band_file`, `band_archive_read`. `band_mutate()` = flock'd read-modify-write per revy (copy of `faelles_mutate()`); hoisted functions, no consts (dispatched early).

Koordinator's Afslut sets it `true` (locked until Ny Revy, which sets it `false`). Online-only.

- **Tree**: folders open/close in place like Bandet's Noder (open set in `localStorage` `matrevy-teknik-open`), contents indented by `--depth`; folders first, then files, Danish-alphabetical. A folder row shows its direct contents; deleting one confirms with the recursive count and removes the whole subtree + bytes (`teknik_delete_folder`, idempotent). Folders can't be moved (only renamed).
- **Moving files**: drag a file row (`teknikGetDragImageEl()` ghost) onto a folder row, onto a row inside an open folder (→ that folder) or anywhere else on the card (→ the top level), all via one handler on the card (`teknikWireDrop`/`teknikDropTarget`, rows carry `data-target`) → `teknik_move_file`. The file's edit modal ("Rediger fil": Navn + Mappe) also moves it — the touch-screen path.
- **Card head**: "Filer" | "+ Mappe" (centred, a `1fr auto 1fr` grid) | "Upload filer" + "Upload videoer" (equal widths, `.teknik-upload-btns`).
- **Upload filer** (`teknikOpenUploadModal`): every non-video upload — the button or files dragged in from the desktop (preselecting the folder they were dropped on). Videos (`teknikIsVideo()`, the `video` kind's exts) are skipped with a toast pointing to Upload videoer; a desktop drop of exactly one video opens the video modal instead. The modal asks **Afsender** (required free-text name, remembered in `localStorage` `matrevy-teknik-uploader`, stored as `uploadedBy` and shown in the file row's meta line; not asked for folders), a name per file (prefilled with its own name, extension kept, like Bandet's upload modal) and "Upload til" (top level or any folder); it refuses a batch bigger than the free space (`teknikFreeBytes()`, which counts this tab's queue too).
- **Upload videoer** (`teknikOpenVideoUploadModal`): opens the modal first; Afsender, a video file, the project as one `.zip` and a Navn are all required (+ Upload til). Uploaded as two ordinary files, `<Navn>.<videoext>` and `<Navn> (projektfil).zip`, same `uploadedBy`.
- **Chunked upload** (php.ini caps a request at 25 MB, so Bandet's one-base64-JSON upload can't carry big files): `teknik_upload_start {folderId, name, uploadedBy, size}` (`413 quota_exceeded` when files + every upload in progress + `size` passes the quota — checked and reserved under `uploads/.lock`, so simultaneous starts can't both fit; `507 disk_full` unless `size` + 2 GB stays free on disk) → `teknik_upload_chunk {uploadId, offset, contentBase64}` (≤8 MB raw, strictly appended at the `.part`'s current size; an already-written chunk answers ok, a gap answers `409 bad_offset` with `received`, which the client resumes from) → `teknik_upload_finish` (size check, rename into `files/`, stores `crc32`, 404 if the folder was deleted meanwhile) / `teknik_upload_abort`. The client uploads one file at a time from a queue (`teknikQueue`, upload panel with progress bars and ✕), retries a chunk on network/5xx errors with backoff, and warns on `beforeunload`/`siteRegisterUnsavedCheck` while anything is queued.
- **Signed downloads** (the browser downloads natively — no blob in memory): `teknik_download_url {fileId, inline}` / `teknik_folder_download_url {folderId}` (null = everything — "Download alt", bottom right of the card) return `teknik_dl=<payload>.<HMAC-SHA256>` valid 10 min, keyed on the three passwords (new passwords void old links). The GET branch streams a file with single-range support (206, video seeking), `nosniff`, `attachment` unless `inline` was asked for an allow-listed type (`teknik_inline_types()` ↔ `TEKNIK_INLINE_EXTS`: pdf/images/mp4/mov/audio — never SVG/HTML). A folder comes as a **.zip streamed on the fly** (`teknik_serve_zip()`): stored, not compressed, every CRC (saved at upload; computed for older files) and size known up front, so nothing is buffered or written to disk and the exact `Content-Length` is sent; ZIP64 records only when an entry or offset passes 4 GiB; one top directory named after the folder (or "Teknikken"), empty folders included, clashing names get " (2)". Downloads go through a hidden iframe (no navigation → no unload warning mid-upload); inline types open in a tab opened synchronously in the click; iOS navigates in place.
- **Server actions** (`$TEKNIK_ACTIONS`, all revyst): `teknik_read` (+ `quotaBytes`), `teknik_create_folder`, `teknik_rename_folder`, `teknik_delete_folder`, `teknik_rename_file`, `teknik_delete_file`, `teknik_move_file`, `teknik_upload_start`/`_chunk`/`_finish`/`_abort`, `teknik_download_url`, `teknik_folder_download_url`; admin `teknik_clear_all` (empties the whole store, idempotent). `teknik_mutate()` = flock'd copy of `kostume_mutate()`; hoisted functions, no consts (dispatched early).

## Øveplan (`schedule.html`/`schedule.js`)

Loads only `site.js` → `scenes-data.js` → `config-data.js` → `calendar-data.js` → `lokaler-data.js` → `fravaer-data.js` → `schedule.js` (no `site-utils.js`, no `manus-data.js`).

- **Manus gate**: below boss, `loadScenes()` loads no `scenes.json` scenes (only `CUSTOM_SCENES`; the cast roster stays) until Manus's "Revyster kan se manus" and "Revyster kan se roller" (`config.pdfLinksVisibleToRevyst`/`rolesVisibleToRevyst`, or their `matrevy-override-config` shadow) are both on (`schedManusVisible()`/`schedManusHidden`); sidebar and picker show "Manus er ikke frigivet endnu." or "Rollerne er ikke frigivet endnu." Cosmetic, like every read gate.

- Single global `state`: `{ rooms, slots, slotsConfig, grid, scenes, allScenes, allCast, absentees, title }` — `slotsConfig` = `{startTime, endTime, segmentMinutes, gapMinutes}` (defaults 25-minute segments, 5-minute "Pause mellem segmenter").
- `grid[slotIdx][roomIdx]` is `{ sceneId, customCast?, crossedOutCast?, customText?, customName?, pairedSceneId? } | null` — only ids, never scene objects. `customCast` overrides a placement's cast; `crossedOutCast` marks people struck through in that cell; `customText`/`customName` are Scenemøde-only; `pairedSceneId` marks a merged dance/actor placement.
- State persists to `localStorage['matrevy-schedule']` on every mutation (`saveState()`), restored by `restoreState()`. Any new mutation must keep this contract. Flush sequence: `renderGrid()` + `renderSceneSidebar()` + `saveState()`. No reactive framework — explicit render calls.
- **Scene data**: from `SCENES_DATA`; on a fresh session or after "Ryd skema", `loadScenes()` prefers Manus's `localStorage` override (`matrevy-override-manus`, with its own TTL) so a just-saved Manus change shows up in the same browser. Otherwise it reflects the embed on reload.
- Scenes are placed via a picker modal (multi-select fills empty rooms left-to-right; a single pick goes straight into the clicked cell), or by drag-and-drop from sidebar chips and between cells (swap; blocked drops highlighted). The picker tags "O" (role conflict) or "F" (absent) — advisory only. A scene with `repeat` can be placed twice before it dims (↻).
- **Priority** badges are read-only, from `scenes.json`'s `priority` (main half = max of Stjerneark's Skuespil/Sang) and `dansPriority` (the "(Dans)" half = Stjerneark's Dans).
- `buildGrid()` preserves placements by matching rooms **by name**, so reordering/adding/removing rooms doesn't scramble them (a renamed room starts empty). Changing start/end/segment/gap fully resets the grid (`buildSlots(start, end, segment, gap)`); otherwise manually edited slot times are kept.
- **Custom scenes** (`CUSTOM_SCENES`, `custom:true`): `Scenemøde` (editable cast line/title) and `Rekvisitten` (no fixed cast — opens a full-roster checklist; chosen names become `customCast`). Both exempt from "already placed" dimming.
- **Dance/actor split**: a scene with any cast member tagged Dans or Koreograf (`isDanceSplitCandidate`/`isDanceCastRole`) is split at load (`applyDanceSplits()`) into the main part (original id) and `"<name> (Dans)"` (id `::dans`), each with its own priority/repeat (`dansPriority`/`dansRepeat`). Picking both together merges them (`pairedSceneId`, union cast). Runtime-only.
- **Cast classification**: `ROLE_CATEGORIES`/`classifyRoleCode`/`classifyOrKeep` live here (moved from the removed `import.js`). **Always call `classifyOrKeep`.** Displayed and conflict-checked cast both use the filtered list (`getCellCastNames` → `filteredCastNames`, hiding Statist/Ninja; an unmerged song/dance placement narrows to its categories), skipping crossed-out people; a `customCast` is returned verbatim.
- **Per-cell cast editor**: "Roller" (open by default) and "Andre revyster" (closed; open by default for Rekvisitten). A Roller row toggles crossed-out (`(overstreget)`). Busy/absent rows show a suffix and are disabled-but-removable.
- **Absences**: `state.absentees` = `{name, start, end}[]` (minutes since midnight). `isPersonAbsentAtSlot(name, slotIndex)` is the single source of truth (grid styling, "F" tag, editor). An absent person is exempt from conflicts for that slot.
- **Opmærksomhed** (`computeAttentionLists`/`renderAttentionSection`): lists of people needing attention, split at 13:00; hidden in print.
- **Merging/splitting slots** lives in the per-slot time editor (`openSlotTimeEditor`/`renderSlotTimeEditor`): "Flet (op)"/"Split"/"Flet (ned)" above Start/Slut. Merging (`mergeSlots(si)`, enabled only when `canMergeSlots(si)` — no room occupied in both) spans the earliest start to latest end, keeps whichever placement exists per room, and closes the modal. "Split" (`slotTimeMode`) shows two editable Start/Slut rows seeded from `defaultSplitMid()`; "Opdel" (`confirmSlotTimeEditor` → `splitSlot`) keeps placements on the first half.
- **Lokalebooking button** (on the "Lokaler (ét per linje)" line, `openLokalebookingModal()`): a modal of day columns, each listing the rooms booked that day in Koordinator's Lokalebooking (non-blank cells, sheet order; a cell's text other than "x" shown as a note), scrolled to today/the next day. "Hent" **replaces** `#input-rooms` with that day's rooms and `saveState()`s (no rebuild — "Byg øveplan" still does that). Day columns are `schedLokalerDays()`, a copy of Koordinator's `koordLokalerDays()`; data prefers the `matrevy-override-lokaler`/`-calendar` shadows (`schedLoadOverride`), else `LOKALER_DATA`/`CALENDAR_DATA`. Built on `schedOpenDayStripModal()`, shared with:
- **Fravær button** (on the "Fraværende revyster" line, `openFravaerModal()`): the same day strip listing Koordinator's Fravær sheet (`FRAVAER_DATA` or the `matrevy-override-fravaer` shadow) per day — name + cell text. `schedParseAbsenceText()` reads a cell (`14:00 - 16:00`, `14-16`, `1430-1600`, `fra/efter 15`, `til/indtil 13`, `x`/`hele dagen` = the Start/Slut fields' day); names match `state.allCast` case-insensitively. Unknown names and unreadable times are shown in red and left out. "Hent" **replaces** `state.absentees` with that day's absences (undoable with Ctrl+Z).
- The grid title (`#sched-grid-title`) is `contenteditable`, stored in `state.title`. "Ryd skema" wipes only `state.grid`.
- **Undo/redo** (`schedUndo`/`schedRedo`): `saveState()` calls `schedUndoRecord()`, which pushes the previous whole-state snapshot (`schedUndoSnapshot()`: rooms, slots, `slotsConfig`, grid, absentees, title + the day-setup fields) whenever the state changed — so every mutation that keeps the `saveState()` contract is undoable for free. In memory only (max 20 steps, reset by `restoreState()` on load). Applying a snapshot re-renders (incl. the empty state when undoing the first build) and persists without recording. Keyboard only: Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl+Y outside text fields/modals (inside a field the browser's text undo wins); no buttons, by decision. The Byg/Ryd confirms say it can be undone.

## The write endpoint (`server/update-data.php`)

`action:'login'` maps a password to a level (`hash_equals` against the three passwords). Shared passwords are not real authentication and should be treated accordingly. Dispatch order:

0. `GET ?teknik_dl=<token>` (before the POST-only check) → `teknik_serve_download()`; the signed token is the authorization (Teknikken, above).
1. Legacy `{pin, scenes, cast}` → `save`/`manus`.
2. `login`.
3. `upload`/`delete` — binary files at client-chosen paths, level from `upload_path_level()`: `ARCHIVE_PATH_RE` (`archive/<folder>/{cover.jpg,manus.pdf,Manuskript.pdf}`) and `ARCHIVE_SNAPSHOT_RE` → admin, `WIKI_ATTACHMENT_PATH_RE` → boss. Checked before any write and re-checked inside the handlers.
4. `$BUDGET_ACTIONS`, `$FORMS_ACTIONS`, `$FAELLES_ACTIONS`, `$BAND_ACTIONS`, `$KOSTUME_ACTIONS`, `$REKVISIT_ACTIONS`, `$NINJAS_ACTIONS`, `$LOKALER_ACTIONS`, `$FRAVAER_ACTIONS`, `$TEKNIK_ACTIONS`, `$KOORD_ACTIONS` (private stores, Fravær's form connection and Koordinator's logins and notes, above).
5. `$POST_ACTIONS` (revyst, append-only — must never accept a client-supplied full array): `posts_create` (image at `POST_IMAGE_PATH_RE`), `comments_create`, `manuscripts_create`, `manuscripts_update`.
6. `manuscripts_sync_selection` (boss; only `{id, selected}` pairs; moves files between `submitted`/`sketches`/`songs`), `manus_read`/`manus_regenerate_pdfs`/`manus_pdf_status`/`manuscripts_remove`/`manuscripts_set_durations`/`manus_set_stars`/`manus_set_cast`/`program_read`/`resource_read` (boss; Manus's merge read, save-free PDF trigger, the last PDF run's status, one-record pool removal, pool durations, Stjerneark's per-click save, the Cast list's `manus_set_cast`, Program's merge read, and the live file + sha of `calendar`/`posts`/`wiki`/`masterplan`/`lokaler`/`fravaer` from a fixed map, `data: null` for a missing file) and `manuscripts_delete` (admin; one `{pdfPath, texPath, id?}`, `ARCHIVE_MANUS_ANY_RE`).
7. `save` → `$RESOURCES` (per-resource min level + validator + writer), full-array replace: **boss** — `manus` (optional `baseScenesSha`/`baseCastSha` → 409 `stale`), `calendar`, `posts`, `wiki` (each optional `baseSha` via `payload_base_sha()` → 409 `stale`; returns the new `sha`), `program` (optional `baseSha` → 409 `stale`; returns the new `sha`), `config` (boss for the revyst flags; `currentProductionFolder` admin-only); **admin** — `manuscripts` (only Koordinator's reset), `archive`, `bosses`, `masterplan`, `lokaler`, `fravaer` (optional `baseSha` → 409 `stale`; return the new `sha`; `fravaer` keeps the live `connection`), `gantt`, `revyugen`, `production`.

**`github_api()` can write anything under `SITE_DATA_DIR`** (all public site data), so the path allow-list regexes are what stand between a request body and overwriting any of it; `github_api()` adds a generic guard (no empty/`.`/`..` segments). **Never relax one of these regexes without an equally strict replacement.** Error codes still carry their git-era names (`github_read_failed`, `github_write_failed`).

PHP's `json_encode` writes JSON with 4-space indentation (hand-edited files used 2) — a cosmetic difference, not a content change.

## Code style

- `'use strict'` at the top of every JS file.
- **No em/en dashes (—, –) in any text the site shows**: labels, buttons, tooltips, toasts, modals, banners, placeholders, `aria-label`s and generated PDFs. Use a period, a comma or parentheses instead ("Ikke fundet. En anden …", "Træk for at ændre bredden (dobbeltklik for standard)", "Madforbehold (18/10)"). A plain hyphen is fine inside words, in number/time ranges without spaces (`10:00-16:00`, `1900-2100`), and as the "empty"/"not set" placeholder (`-`); a range of written-out dates uses "til". Comments in code may use dashes.
- Section headers in JS use `// ── Section name ─────`.
- HTML and every user-facing string/label is Danish.
- Every `:hover` rule lives inside `@media (hover: hover)` (no sticky hover on touch); split a combined `:hover, :focus-visible` so `:focus-visible` stays ungated. Hover-only *reveals* need a `@media (hover: none)` always-visible fallback (see `.cell-remove` in `schedule.css`).
- **Every draggable-to-reorder row/card supplies its own drag image.** The browser's default snapshot is messy, and a `<tr>` can't be rasterized outside its table at all. Each page has a small `<prefix>GetDragImageEl()` (`formsGetDragImageEl`, `budgetGetDragImageEl`, `wikiGetDragImageEl`, `manusGetDragImageEl`, `bossesGetDragImageEl`, `koordMpGetDragImageEl`, `calGetDragImageEl`) returning one shared, lazily-created, **off-screen** `<div>` (`position: fixed; top/left: -999px` — never `display:none`, which some browsers won't snapshot), styled as a small rounded label. Every `dragstart` sets its text to the item's identifying label and calls `e.dataTransfer.setDragImage(ghost, 12, 16)` first. New draggable lists follow the same recipe (Program's QR rows are the one current exception).
- **A `<table>`'s drop highlight must never use `border-top`/`border-bottom`**: under `border-collapse: collapse` a wider border wins the whole shared edge and eats the row separators. Use an inset `box-shadow` (`inset 0 2px 0 0 transparent` → `var(--accent-warm)` on `.<x>-drop-target`), as `.budget-manage-tr`/`.forms-dashboard-row` do. `<div>` rows aren't affected.
- **A per-row drop target can only insert *before* a row** — reordering to the end needs a trailing drop-tail element (`.wiki-manage-drop-tail`, `.manus-akt-drop-tail`, `.forms-drop-tail-row`, `.budget-manage-drop-tail-row`, `.budget-subcat-drop-tail`, `.streg-price-drop-tail`, `.koord-mp-drop-tail`, `.gantt-drop-tail`), or a drop zone on the whole list (Forside's Bosser `<ul>`, whose rows stop propagation).

## Updating for a new production

Koordinator → Arkivering: save Teknikken's files elsewhere and mark it ready, generate the PDFs and mark Manus ready, **Afslut revyen** (snapshot, archive entry, Teknikken emptied, empty Manus/manuscripts, no active folder), then **Start ny revy** (name, new folder, archive entry). Submissions then land in the new `archive/<folder>/submitted/`. `program.json` and Øveplan's per-browser state are not reset.

## Known issues & ideas

- **"Generér PDF'er" with an empty production** fails: with no scenes, Aktoversigt emits an empty `enumerate`, LaTeX rejects it (reported in the error modal; the merge steps are skipped). Fix: skip or placeholder empty acts.
- **Edit conflicts are last-save-wins**: the browser never sends the version it loaded, so the 409 only catches simultaneous saves. Fix: every save sends the `sha` of the data the page was built from (embedded, or a cheap read action); `update_file()` compares and returns 409 → "Nogen andre har ændret dette — genindlæs". Manus (merge before save), Kalender, Posts and Wiki (`siteSaveListResource`), Masterplan and Lokalebooking (merge on save) are fixed (Oct 2026); `archive`, `bosses`, `config`, `gantt`, `revyugen` aren't (rarely edited, by decision) — `plans/autosave.md` has the plan, plus the rest of the auto-save/undo roadmap.
- **Auto-place in Øveplan** — implemented once, removed for a redesign. Spec: greedy placement by priority respecting cast conflicts and absences, auto-placed cells visually distinct, re-runnable, with a summary.
- **Compile a video scene's manus into the PDFs** — `hasScript()` in `generate-pdfs.js` excludes `video` (bandsang is already compiled); the open question is which LaTeX environment to use (`revy.sty` has none for video; `sketch` is the obvious fallback).
- **SMS on reject (Budget)** — wanted with a branded "MatRevy" sender, which needs a paid SMS gateway account, an API key in Coolify's env vars and a new action; not worth the overhead yet. The zero-infra alternative is an `sms:` link from the admin's own phone.
- **Real per-user login** — only if the shared-password model stops being enough.
