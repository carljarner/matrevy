# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Stack

Internal website for Matematikrevyen (Danish student revue) at `matematikrevy.dk`. Plain HTML/CSS/JS front end — no framework, no bundler, no package manager for the site itself, no test suite, no linter; validation is manual. One PHP file (`server/update-data.php`) is the whole write API. Node is only used by the two build scripts in `scripts/` (dev dependencies `pdf-lib` and `qrcode` in `package.json`).

Since 2026-10-02 everything — site, API and data — runs on **web-1** (Hetzner, `188.245.30.36`), deployed by **Coolify** from this repo's `main` branch as one Docker Compose app. Before that it was GitHub Pages + a Simply.com PHP host + GitHub-repo-as-database; leftovers of that era are being cleaned up per `migration-guide.md` (dated checklist — read it before touching `CNAME`, `.github/workflows/`, `server/Dockerfile`, `server/simply-forwarder/`, or the tracked `data/`/`archive/`/`posts/`/`wiki/` folders).

## Hosting & data flow

`docker-compose.yml` defines two containers, both mounting the host folder `/srv/matrevy/data` at `/data`:

- **`web`** (`server/Dockerfile.site`, `php:8.3-apache`, build context = repo root): serves the repo's static files plus `update-data.php`, `health.php` (Coolify healthcheck/UptimeRobot), and `config.php` (= `server/config.docker.php`, every value from Coolify env vars: `REVYST_PASSWORD`, `BOSS_PASSWORD`, `ADMIN_PASSWORD`, optional `SHARED_PIN`; data dirs default to `/data/{budget,forms,faellesspisning,band,lokaler,site}`). `server/apache-site.conf` aliases `/data/`, `/archive/`, `/posts/`, `/wiki/` to `/data/site/…`, every `js/<name>-data.js` **except** `js/manus-data.js` (hand-written code) to `/data/site/generated/js/`, and `/calendar.ics` to `/data/site/generated/calendar.ics`. It redirects `www.` → apex (pages on `www.` would otherwise fail CORS and keep a separate login) and sends `Cache-Control: no-cache` on everything (cheap 304s; a save or deploy is never hidden behind a cache). `.dockerignore` keeps the data folders and generated files out of the image.
- **`worker`** (`server/Dockerfile.worker`, `texlive/texlive:latest-medium` + Node, runs as uid 33 like Apache): `server/worker.sh` runs `scripts/embed-scenes.js` once at startup, then polls every 2 s for flag files in `/data/site`: `.embed-requested` → `embed-scenes.js`, `.regen-pdfs-requested` → `scripts/generate-pdfs.js`. The flag is removed before each run, so a save landing mid-run triggers one more run. `/app/{data,archive,js,calendar.ics}` are symlinks into `/data/site`, so both scripts run unchanged.
- **Archive mirror to GitHub** (also `worker.sh`): `update-data.php` touches `.archive-sync-requested` on any write under `archive/`, and the worker touches it after every PDF build. Once the flag has been quiet for `ARCHIVE_SYNC_QUIET_SECONDS` (default 300), the worker `rsync --delete`s `/data/site/archive/` into a sparse clone at `/data/archive-git` and pushes one `[skip ci]` commit to `main` (deploy key = base64 in Coolify's `ARCHIVE_SYNC_DEPLOY_KEY`; empty = mirror off). Strictly one-way, server → GitHub; `archive/README.md` is repo-managed. This keeps closed years and the current production's `submitted/`/`sketches/`/`songs/` browsable on GitHub, so Arkiv's GitHub pill, the Manus Guide link and Program QR codes keep working. Because the worker pushes to `main`, `git pull --rebase` before pushing code (it only touches `archive/`, so it never conflicts).

**Live data**: public site data lives in `/srv/matrevy/data/site/{data,archive,posts,wiki}` (+ `generated/`); private data in `/srv/matrevy/data/{budget,forms,faellesspisning,band,lokaler}`, outside every web-served folder. `/srv` is backed up nightly with restic (README.md → Drift). The repo's own `data/`, `posts/`, `wiki/`, `calendar.ics` and `js/*-data.js` (except `manus-data.js`) are **stale snapshots from 2026-10-02** until the cleanup untracks them — editing them changes nothing live. The repo's `archive/` is different: it stays tracked as the worker's live mirror (below) — don't edit it in the repo, the next sync overwrites it.

**Save path**: browser → `update-data.php` → `github_api()`, which despite its name is now a local-disk stand-in for the GitHub Contents API (kept so every caller works unchanged): same return shape (base64 `content` + `sha`), `sha` = sha1 of the file bytes, reads/writes under a `.write.lock` flock, atomic temp-file + rename, and a stale `sha` → `409`. After a write it touches `.embed-requested` (any path under `data/`) and `.regen-pdfs-requested` (when the write's message contains `[regen-pdfs]`). Saved data is visible on the next page load within ~3 s; a full PDF build takes ~15 s.

**Deploy**: push to `main` → Coolify rebuilds and redeploys both containers (code and static files are baked into the `web` image, so any change needs a rebuild). Secrets live only in Coolify's environment variables.

**`SITE_API_ENDPOINT`** (`js/site.js`): `https://manus.matematikrevy.dk/update-data.php` on the apex (left over from the DNS move; `manus.` points at the same container), `/update-data.php` on any other host (so a test domain writes to its own data). CORS in `update-data.php` only allows `https://matematikrevy.dk`. Simplify to `/update-data.php` in the cleanup.

**Local development**: pull the live public data and embed it — also what keeps the `file://` offline mode working:

```
rsync -a web-1:/srv/matrevy/data/site/{data,archive,posts,wiki} ./
node scripts/embed-scenes.js
```

Saves can't be tested locally against the real API (CORS); run `php -S` with a hand-written `config.php` pointing `SITE_DATA_DIR` at a scratch copy if needed.

**Embedded data**: `scripts/embed-scenes.js` is table-driven (`EMBEDS`): each `data/<name>.json` becomes a flat global (`SCENES_DATA`, `CAST_DATA`, `CALENDAR_DATA`, …) in a generated `js/<name>-data.js`, loaded via `<script src>` only on the pages that need it — globals rather than `fetch()` so pages work over `file://`. A `raw: true` entry writes verbatim (used for `calendar.ics`). Adding a data file = an `EMBEDS` entry + `<script>` tags + creating the JSON on the server disk once (`update_file()` has no create-if-missing branch) — the Apache alias picks up any `[a-z]+-data.js` automatically. The `async` on `loadScenes()` in `schedule.js` is vestigial.

## Site shell & access levels (`site.js`)

Four access levels: **public / revyst / boss / admin**, unlocked by three shared passwords (handed out verbally — deliberately not real per-user auth). **Boss** edits Manus/Kalender/Wiki/Formularer; **Admin** is the top tier (site maintainer) — everything Boss has plus Koordinator, Budget management, site-wide config, Arkiv, Gantt/Revyugen, Bosser. **Øveplan** (`schedule.js`) is revyst-level since it never writes through the server (every placement lives in that browser's `localStorage`). Reads are gated client-side only (cosmetic — nothing is secret); writes are genuinely validated server-side.

- `site.js` renders the header nav on every page from `SITE_PAGES` (`{href, label, level, group?}`) — the **only** place a page is registered. Revyst-level pages render greyed/unclickable until login; boss/admin-level pages are omitted below that level.
- **Redskaber (grouped tool tab)**: a `SITE_PAGES` entry with a `group` key (label in `SITE_NAV_GROUP_LABELS`) folds into one shared nav tab — today Bandet and Øveplan under "Redskaber"; future tools register with the same `group`, no nav/CSS changes. `renderNavGroup()` lists a group's members alphabetically (`localeCompare(…, 'da')`), whatever their `SITE_PAGES` order. `buildSiteNavLinks()` renders a group as nothing (all members hidden), a greyed `.site-nav-locked` span (all visible members locked), or an interactive tab: a click-to-open dropdown on desktop (`renderDesktopNavGroup`, reusing `.site-field-pop`/`.site-list-row`/`.site-list-selected`, with its own open/close/outside-click/Escape handling since `schedule.html` doesn't load `site-utils.js`), or an in-place accordion in the mobile overlay (`renderMobileNavGroup`, auto-expanded on a member page). `applyPageGate()`/`injectSitePrefetchLinks()` key off `SITE_PAGES` by `href` regardless of grouping.
- **Nav preloading**: `injectSitePrefetchLinks()` idle-prefetches every reachable page's HTML at load; `setupSiteNavPreload()` loads a page as soon as its nav link (`SITE_NAV_LINK_SELECTOR`: `.site-nav`/`.site-menu-nav` links) is hovered, touched or focused. Chromium gets a Speculation Rules `prerender` (`moderate` eagerness — the whole page, JS included, renders in the background, so its on-load API reads run on hover); other browsers fall back to fetching the page's HTML + its `script[src]`/stylesheets into the HTTP cache (parsed in a detached `DOMParser` doc), leaving only 304s for the real navigation. Both skipped over `file://`.
- **Login**: top-right button → modal (✕, Escape, backdrop click with the mousedown guard below; "Log ind" right-aligned via `.login-actions-end`) → POST `{action:'login', password}` → level. `{level, password}` stored in `localStorage['matrevy-auth']` (password kept so later writes can send it). Logout removes the key; both reload the page.
- **Page gate**: `applyPageGate()` hides `<main>` for an insufficient level and shows a login card (blue `.site-gate-login` button). Cosmetic only, by design.
- **`file://` bypass**: `getSiteAuth()` returns a synthetic admin with an empty password (writes still prompt and fail offline); no login button is rendered and prefetch is skipped. Preserves offline use of the tools.
- **Boss-level saves**: the shared password-resolution helpers trust a stored login's password when the level is `boss` *or* `admin`; admin-only resources only trust `admin`.
- **Mobile menu**: the header collapses to a hamburger whenever the nav + login button overflow (`siteUpdateHeaderFit()` → `.site-header-collapsed`), at any width — not tied to a breakpoint. The overlay holds nav links, then login/logout at the bottom; closes on ✕/Escape/nav-tap; body scroll locks.
- **z-index ladder**: header 100 → mobile menu 150 → login/edit modals 200 → field-picker popups 210 → hover tooltips 250 (`.faelles-field-tooltip`, `.gantt-tooltip`, `.budget-field-tooltip`, …) → `.site-toast` 300.
- **719px is the site-wide content breakpoint** — every page stylesheet with a mobile layout uses `@media (max-width: 719px)`; keep new ones on the same value.

## Site-wide title & button conventions (`style.css`)

One design system for every page **except `schedule.html`/Øveplan**, which keeps its own pre-theme look and its own `.btn-primary`/`.btn-secondary` in `schedule.css` (its "Ryd skema?" confirm does use the shared `.login-overlay`/`.login-actions`/`site-btn-*`).

- **Page titles**: `.page-content h1` (1.6rem/600, centered). Only Arkiv's `.arkiv-hero h1` tweaks its margin.
- **First-level buttons** (inline, not in an overlay): `.btn-small`/`.btn-small-danger` — warm-cream idle, warm-amber hover; `-danger` stays red.
- **Second-level buttons** (inside a `.login-overlay`/`.login-modal`): `.site-btn-primary` (blue) / `.site-btn-danger` (red) / `.site-btn-warm` (amber) / `.site-btn-success` (green), 6px radius, solid fill, white text. `calPillBtn()`/`budgetPillBtn()`/`wikiPillBtn()`/`formsPillBtn()`/`faellesPillBtn()`/`koordPillBtn()` are thin per-page factories (`variant` names the class; default `site-btn-warm`, e.g. Annuller).
- **Blue is for Login** (and the gate card's login button). Every other positive/confirm/save action — "Gem", "Indsend", "Betalt", "Forbind" — is `.site-btn-success` (green). One deliberate exception: Formularer's builder "Skabelon" button is blue.
- **Arkiv's detail overlay keeps the old oval pills**: its link actions (`.arkiv-action-btn`) use `.site-pill-btn` / `-primary` (green) / `-danger` (red) / `-warm` (amber) — idle white/cream oval, thin border, hover/focus-visible only changing `border-color`. Kept in `style.css` solely for that. (`archive.js`'s own `openYearEditor()` also uses them, but it's unwired legacy code — years are edited from Koordinator.)
- **Button-width floor**: `.site-btn-*` buttons (Manus excepted — own sizing) have `min-width: 5rem` with `0.7rem` horizontal padding, so common labels render at a uniform width while long labels grow. Set on `.login-actions > button`; `.wiki-edit-actions > button` repeats it (not an overlay).
- **Orange = chosen/selected, everywhere**: a dropdown's selected row (`.site-list-selected`), the date picker's chosen day (`.site-dp-selected`), Kalender's today-marker and active Måned/Liste toggle use `--accent-warm-text`/`--accent-warm-fill`, never blue. Øveplan's `.picker-selected` uses its own literal `#d8b879` (same idea, separate literals per its own convention). `.cal-cat-deadline`'s blue is that category's identity color, not a selection state.
- **Inline field-editing style** (Fællesspisning's recipe, also Forside's Bosser and Budget's category edit mode): resting `border: 1px solid transparent`, hover-only `border-color: var(--border)` (inside `@media (hover: hover)`), `border-color: var(--accent-warm)` + `background: var(--input-bg)` while focused. A non-editable field (e.g. `.budget-manage-input-locked`) opts out of the hover border explicitly.
- **Modal action layout** (`.login-actions`): `justify-content: center` by default — every ordinary confirm dialog needs no per-modal code. Editor-shaped modals pin actions to the corners (delete left, save right) with `justify-content: space-between`, combining `.login-actions` with their own class for specificity: `.login-actions.cal-event-actions`, `.faelles-connect-modal .login-actions`, `.streg-connect-modal .login-actions`, `.login-actions.budget-expense-edit-actions`. The three that can render a single button (a new Kalender event has only Gem; the two connect modals have only "Forbind" until connected) add `:has(> :only-child) { justify-content: center }`. Self-contained bars outside `.login-actions` — `.post-detail-actions`, `.budget-save-bar`, `.forms-builder-actions` — use plain `space-between` (the latter two center a middle button absolutely: `.budget-center-btn`, `.forms-builder-cancel`). Wiki's in-page editor always has Annuller/Slet/Gem, `space-between`.

### Site-wide field pickers (`site-utils.js`)

Native `<input type="date"/"time">`/`<select>` hand their UI to an unstylable OS shadow root, so every page except Øveplan uses a shared custom-popup system:

- `siteOpenFieldPopup`/`sitePositionFieldPopup`/`siteCloseFieldPopup`/`siteToggleFieldPopup` — popup chrome (`.site-field-pop`, `position:fixed`, clamped on-screen, **repositions** on scroll/resize, closes on outside mousedown or Escape, one open at a time; Escape `stopPropagation`s so it closes just the popup, not a surrounding modal).
- `siteCreateDateField(initialIso)` — `.site-field-btn` opening a month grid (`siteOpenDatePicker`, `.site-dp-today` marker).
- `siteCreateTimeField(initialValue)` — typeable combo (`.site-field-combo`: real `<input>` + clock toggle opening a quarter-hour list); `siteParseTimeInput` normalizes `14:30`/`14.30`/`1430`/`930` on blur/Enter, reverting to the last valid value otherwise.
- `siteCreateDateTimeField` — one field for date with optional time: picking a day re-opens the popup as a time list (`siteOpenTimePicker`, with an "Ingen tid" row and an optional pinned "23:59" `endOfDayOption`); the date applies as soon as it's picked.
- `siteCreateDropdownField(options, initialValue, placeholder?)` — `<select>` replacement without per-option color (`siteOpenDropdownPicker`), used site-wide.

Every factory returns an element with a `.value` getter/setter and a `change` event, so call sites use them like native inputs. Kalender's category field (`calCreateCategoryField`) stays page-specific (colored dot per option) on the same primitives. `schedule.js` carries its own `sched`-prefixed duplicates of the popup chrome, dropdown and time field (it doesn't load `site-utils.js`) with the same CSS classes; its time field fires no `change` event.

## Data-driven pages & `site-utils.js`

Shared architecture for every data-backed page:

- **Data flow**: `data/<name>.json` → `EMBEDS` → generated `<name>-data.js` → `<script src>` on the page. Script order per page: `site.js` → `site-utils.js` → `<feature>-data.js` → `<feature>.js`.
- **One JS file per feature** (`posts.js`, `bosses.js`, `calendar.js`, `archive.js`, `wiki.js`, `manus.js`, `koordinator.js`, `budget.js`, `forms.js`, `faellesspisning.js`, `band.js`, `schedule.js`), page-scoped. Since each page loads a different subset of scripts, **shared logic that isn't in a commonly-loaded file gets duplicated per page** rather than imported — role classification, dance-split logic, drag helpers, tooltips, time-field widgets. This is a deliberate convention, not an oversight.
- **Optimistic shadow**: each feature keeps `let xOverride = siteLoadOverride('x')` + `getEffectiveX()`. A successful save calls `siteSaveOverride(resource, data)` and re-renders, so the saving tab sees its change before the worker regenerates the embed. The override survives a refresh for `SITE_OVERRIDE_TTL_MS` (30 s), then falls back to the embedded data. Manus uses the same mechanism (`setManusSavedOverride()` in `manus-data.js` also writes `siteSaveOverride('manus', …)`, which Øveplan reads too); Forside's Bosser keeps an in-memory-only shadow.
- **`site-utils.js`** (every page except Øveplan): Danish date helpers (`DA_MONTHS`, `DA_WEEKDAYS_SHORT`/`_LONG` Monday-first, `parseIsoDate` — always from parts, never `new Date('YYYY-MM-DD')` which parses as UTC — `formatDaDate`, `formatDaDateMaybeTime`, `todayIso`); `siteShowToast`; `siteSaveResource(resource, payload)` (the boss/admin save flow — stored login password or a `sessionStorage`-cached prompt keyed `matrevy-manus-pin`; returns `{ok}` or `{ok:false, message}`, never throws; `message === ''` means cancelled → silent no-op); `siteFileAction`/`siteUploadFile`/`siteDeleteFile` (the `upload`/`delete` actions); `siteCreateAutosave({save, onStatus})` (debounced ~1 s, serialized auto-save of a page's local draft — `{schedule, flush, isBusy, hasUnsaved}`; `save()` builds from the current draft and must not re-render; a failure isn't retried until the next change/`flush()`; a `beforeunload` warning while anything is unsaved — used by Gantt, Revyugen, Masterplan, Lokalebooking; see `autosave.md` for the site-wide plan); `siteFileStatus(path)` (same-origin `HEAD`, `{exists, date, checkFailed}` from `Last-Modified` — on the server a file's `Last-Modified` only changes when it's rewritten); `siteOpenEditModal`/`siteEditField` (imperative modal chrome) and `siteOpenModalWithClose` (✕ + Escape). Both modal helpers track a backdrop `mousedown`'s own target and only close on a matching backdrop `click` (a drag that started inside the modal, e.g. a textarea resize, must not close it).
- **Saves send the full next array** (`{events:[...]}`, `{posts:[...]}`, …) — no per-item patch API. The server reads the file and writes it back within one request, so the stale-sha `409` only catches two saves landing in the same instant; two tabs editing the same data a minute apart resolve as **last save wins** (see Known issues).
- **Every write caller treats a reply as success only when the body parses as JSON with `ok === true`** (`siteSaveResource`, `siteFileAction`, `budgetApi`, `formsApi`, `faellesApi`, `bandApi`, `postsApi`, `manusApi`). A PHP fatal or a proxy/WAF error page can arrive as HTTP 200 + HTML; this rule was learned the hard way when a form wrongly reported success. `update-data.php`'s shutdown handler turns a fatal into a JSON 500 when it can.
- **Rendering rule**: build DOM via `createElement`/`textContent` — never `innerHTML`. Two deliberate, scoped exceptions: Wiki and Posts rich-text bodies (sanitized via a detached `DOMParser` document and rebuilt from an allow-list — see Wiki). `escHtml()` in `schedule.js` is the sanitizer for Øveplan's own `innerHTML` templates.

## Kalender (`kalender.html`/`calendar.js`, `data/calendar.json`, boss-level editing)

1200px-wide page. Month grid + list toggle (view persists in `localStorage`, defaults to list at ≤719px). List view shows only upcoming events, grouped by month. `category` is an ASCII key; `CAL_CATEGORIES` in `calendar.js` is the source of truth for label/order/color (duplicated in `embed-scenes.js`'s `.ics` builder). Multi-day events carry `endDate` (`>= date`); `calEventEndDate(ev)` is the one helper for "when does this end." A month-grid chip opens a read-only detail modal; boss/admin also get "Rediger" there. Date/time/category fields use the shared pickers.

- **`.ics` subscribe feed**: a static RFC 5545 file built by `embed-scenes.js` (`raw: true` entry), written by the worker to `/data/site/generated/calendar.ics` and served at `/calendar.ics`. Timed events are real UTC (`Z`) `DTSTART`/`DTEND` via `copenhagenOffsetMinutes()`/`icsUtcDateTime()` — a hand-coded, DST-aware Europe/Copenhagen offset (EU last-Sunday-of-March/October rule), no timezone library. Floating local times were misread as UTC by Google Calendar's URL importer, and a `TZID` + embedded `VTIMEZONE` attempt was also unreliable there; real UTC has nothing to mishandle. `X-WR-TIMEZONE:Europe/Copenhagen` is a harmless hint for other clients. All-day events use `VALUE=DATE` with `DTEND` one day past `endDate` (exclusive).
- **Revyperiode Gantt** (`data/gantt.json`, **admin** `gantt` resource, `renderGantt()`): second card, public to read (hidden while empty). Axis September–November of the stored `year`; admin-named rows, each with `{start, end, label, color}` bars (`color` one of six `GANTT_COLORS`, picked via swatches; falls back to a per-row cycle), positioned by percentage, clipped to the window, stacked into lanes on overlap. Hover shows `calShowTooltip` (label + date range). Admin edits an auto-saved `ganttDraft` (`ganttAutosave`; the head's Rediger button becomes "Færdig", which flushes and leaves edit mode, staying put if the save failed; status line `calPaintSaveStatus`; an empty row title blocks saving): rename/drag-reorder/remove rows (`calGetDragImageEl`, `.gantt-drop-tail`), click an empty track or a row's "+" to add a bar, click a bar to edit it. Changing the year offers to shift every bar.
- **Revyugen week schedule** (`data/revyugen.json`, **admin** `revyugen` resource, `renderRevyugen()`): third card, a Google-Calendar-style week view of the revy's final days (`startDate`–`endDate`, max 31 days; `startHour`–`endHour`). Revyst-level to read (hidden below admin while empty). Blocks are `{id, date, start, end, title, text, category}` — bold `title`, plain `text`, no timestamp (time range in the `calShowTooltip` hover); `category` is one of `REVYUGEN_CATEGORIES` (Øvning/Frivillig/Scenefolk/Obligatorisk/Andet → blue/green/yellow/red/purple, legend in the card head). `end` may be `"24:00"` (an entered end of `00:00` is stored that way). Overlapping blocks split the column (`revyugenLayoutDay`). Admin edits an auto-saved `revyugenDraft` (`revyugenAutosave`, same Rediger/Færdig toggle as Gantt): click empty space to add (snapped to 30 min), click a block to edit; moving "Første dag" shifts the whole period and every block, moving "Sidste dag" only changes the end. Blocks use `.revyugen-color-*`, styled like `.cal-chip`. Reuses `calCreateCategoryField` with an options list.

## Arkiv (`arkiv.html`/`archive.js`, `data/archive.json`, admin editing)

One square-cover card per year. The stable key is `folder` — slugified once from `name` at creation (`slugifyFolderName()`) and never recomputed, so renaming can't orphan files. `year` isn't unique (a jubilee revy can share a year). Individual sketch/song/other `.tex`/`.pdf` files aren't tracked in the JSON — they live under `archive/<folder>/{sketches,songs,other,…}/` on the server disk (the card's GitHub link pill points at the repo's `archive/<folder>`, kept current by the worker's archive mirror). Only the cover photo and manuscript PDF upload from the browser, via the top-level `upload` action (`archive/<folder>/{cover.jpg,manus.pdf,Manuskript.pdf}`); covers are re-encoded to JPEG client-side; ~5 MB cap. Years are added/edited on Koordinator's Arkivering tab (`openKoordYearEditor`, a near-duplicate of `archive.js`'s never-wired `openYearEditor()`); `arkiv.html` itself is read-only.

## Forside (`index.html`): Posts + Bosser

**Posts** (`data/posts.json`, `posts.js`): a Facebook-style board, pinned first then date-desc (`renderPostFeed()` re-sorts the whole array). Anonymous visitors see "Log ind for at se opslag". Shows the last `POSTS_INITIAL_MONTHS` (6) months plus every pinned post; "Indlæs en måned mere" widens the window by a month. Each post is `{id, pinned, date, author, title, text, image, comments}` — `title` optional (shown as a small tag), dates are floating local timestamps. `text` is rich text sanitized like Wiki (`POST_ALLOWED_TAGS`, `renderSanitizedPostBody`); legacy plain-text posts (`postLooksLikeHtml` false) go through the line-split + auto-link path. `image` is uploaded inline at creation (`posts/<id>/image.jpg`) and can't be replaced from the edit modal. Pinning is a pin-icon toggle (`togglePinned`). **Three write paths, one file**: `posts_create`/`comments_create` are revyst-level **append-only** actions (server assigns `id`/date; posts always start `pinned:false`); editing/deleting posts/comments and pinning go through the boss full-array `siteSaveResource('posts', …)`. `postsApi()` is its own any-level authenticated helper for the append-only actions.

**Bosser** (`data/bosses.json` = `{title, roles:[{names, role}]}`, `BOSSES_DATA`, `bosses.js`, **admin** `bosses` resource): Forside's right-hand card. Admin "Rediger" switches the card to inline editing (title + rows editable with the inline field style, draggable rows, a "+" row, Rediger → Annuller with Gem below); fully blank rows are dropped on save. Drag ghost shows the role title; the drop zone is the whole `<ul>` (`.boss-list-editing` padding). In-memory-only shadow (no `siteLoadOverride`).

## Wiki (`wiki.html`/`wiki.js`, `data/wiki.json`, boss-level)

A flat chapter list, `{id, title, body, published?, attachments?}`. `body` is sanitized HTML limited to `WIKI_ALLOWED_TAGS` (`b/strong`, `i/em`, `u`, `ul`, `ol`, `li`, `p`, `br`, `h2`, `h3`): untrusted HTML is parsed into a **detached** `DOMParser` document (never executes, never attached) and rebuilt with allow-listed `createElement`/`createTextNode`, copying no attributes — no persisted-attribute XSS surface. `<a>` isn't allowed; links are auto-detected from text at render time. In-place editing: "Rediger" swaps in an editable view with a `document.execCommand` toolbar (deprecated but the only no-dependency option). Attachments (`{id, name, path}`, pdf/tex, 5 MB) upload via the boss-level `upload` action to `wiki/<chapterId>/<attachmentId>-<slug>.<ext>` (`WIKI_ATTACHMENT_PATH_RE`). Server validation checks shape only (boss-only path). **Publishing**: `published` per chapter — revyster see unpublished chapters greyed (toast on click) and a "Siden er under opbygning" banner when nothing is published; the eye toggle in "Rediger kapitler" is admin-only client-side (server only checks boss + boolean). A scroll-spy table of contents (`setupWikiScrollSpy`) tracks headings. **"Rediger kapitler"** (`openManageChaptersModal`): draggable flat list + centered "+" appending `{id, title:'Nyt kapitel'}`; drop position shown as an orange line above the row (`.wiki-manage-row::before`, since the row's own border would hide a color change), plus a trailing `.wiki-manage-drop-tail`.

## Manus (`manus.html`/`manus.js`, `data/manuscripts.json` + `data/scenes.json`/`cast.json`)

**Upload pool**: any revyst+ submits a sketch/song via the append-only `manuscripts_create` action. The server slugifies the title, writes `archive/<currentProductionFolder>/submitted/<slug>.{pdf,tex}` and appends the record. The revyst-level `manuscripts_update` ("Opdater") replaces a submission's files while it's still in `submitted/`. `config.json`'s `sketchUploadsClosedForRevyst`/`songUploadsClosedForRevyst` close uploads per type (admin toggles on the page; `MANUS_UPLOADS_CLOSED_KEYS`), and `pdfLinksVisibleToRevyst` shows the PDF quick links to revyster. Two delete paths: the pool's "Fjern" (boss, `manuscripts` resource) removes only the record and leaves the files; "Slet" in Vælg scener calls admin-level `manuscripts_delete`, which deletes the pdf/tex **and** the record. **"Sang (fisk)"** stores an ordinary `type:'sang'` submission plus `fisk: true` — a song in every respect; the flag only affects selection-stage lists (pool, Vælg scener, Stemmeark/Indtast point), which list fisk songs last, alphabetically, below a divider, as `Fisk: Title` (`manusSortWithFisk`/`manusRowIsFisk`, the latter resolving a graduated scene back via `sourcePdf`).

**Duration default from `\eta{}`**: the upload/Opdater modals parse the `.tex`'s `\eta{}` (`extractTexDuration`/`parseEtaDurationMinutes`, tolerant of prose like "$2:56$ minutter" or "$3-4$ minutter") and send it as `duration`, which seeds the row's duration in Vælg scener. Rows without one are backfilled from their `.tex` (fetched same-origin, `MANUS_TEX_RAW_BASE = '/'`) by `manusImportFromTex`. Boss/admin edit it freely.

**Udvælgelse card** (selection stage, before scenes exist): **Stemmeark** ("Hent stemmeark" prints voting sheets), **Indtast point** (per-browser points 0-10 per sheet in `localStorage` `matrevy-manus-points`, results as Tabel or Boxplot, `matrevy-manus-points-view`; `manusPointsStats` gives averages), **Aktfordeling** and the **Vælg scener** button.
- **Aktfordeling** (`openAktTagModal`/`manusPrintAktCards`, per type Sange/Sketches; `localStorage` `matrevy-manus-akt-tags`, keyed by submission `id`, never synced): three tabs — **Scener** hand-picks submissions (best point average first, never auto-picked), **Kategorier** edits labels, **Stil & Tema** tags each picked one with one **Stil** (→ card shape: rectangle/rounded/hexagon/rhombus/triangle/octagon, 2:1) and any number of **Tema** labels (→ fill colour, one stripe per theme). Stil labels are per type (Sange: Sang/Rap/Sang/rap/Fisk; Sketches: Kort/Lang/Serie/Musik), Tema labels one shared list (`store.themes`, seeded Kridt/Whist/Instruktor). Removing a label in use warns with the affected titles. Udskriv prints a legend + 4-up cut-out cards (inline SVG via `manusBuildAktShapeSvg`). Unrelated to the Main Manus View's own Aktfordeling tab despite the name.

**Main Manus View** (boss/admin): six tabs (active tab in `localStorage` `matrevy-manus-tab`) — **Scener** (which pool/existing scenes are in the revy, via the "Vælg scener" overlay of click-to-toggle rows, batched into one save), **Aktfordeling** (drag rows into one of 4 acts or "Ikke placeret"), **Rollefordeling** (per-scene cast via a monospace textarea of `\role{<code>}[<name>] <description>` lines, parsed only on "Opdater roller"), **Manus** (per-scene LaTeX body, a plain textarea — the content genuinely is LaTeX), **Stjerneark** (priority 0-3 + "wants a repeat" per scene, plus the dance half where applicable), **Program** (below). The first five share one flat draft row list (`manusDraft.rows`), built once per render and rebuilt only after a successful save. `manusRowScene(row, act, idx)` is the single source of truth for a row's save-shaped scene, so display and save can't drift.
- Role classification (`ROLE_CATEGORIES`/`classifyRoleCode`/`classifyOrKeep`) lives in `schedule.js` and is duplicated verbatim in `manus.js` and `scripts/generate-pdfs.js`; dance-split logic (`isDanceCastRole`/`splitDanceScene`) is duplicated from `schedule.js`. **Always call `classifyOrKeep`, never `classifyRoleCode` directly** — a role can already be a category string, and re-classifying matches against its spelling (`"Koreograf"` starts with `K` → Kor).
- **Videoer & Bandsange**: the only way to get a video/band-jingle scene into the pipeline (no upload path; `manuscripts.json` is sketch/song only). A manual row (`origin:'manual'`) is made via a modal with the same `\title{}/\author{}[/\melody{}]` header plus Roller/Manus textareas. `manusRowIsManualMedia(row)` (checks `types`, since a reloaded row is only detectable that way) filters them out of Rollefordeling/Manus/Stjerneark and out of Øveplan (`schedulable:false`).
- **`MANUS_POOL_ACT_CODE = 'pool'`**: a still-unplaced manual video/bandsang row survives a save in this reserved pseudo-act (pool sketches/songs persist through `manuscripts.json` instead). It's excluded from `draft.acts`, re-attached whenever the acts payload is rebuilt, and skipped by `generate-pdfs.js`.
- **Save** (`manusSaveMain()`) is optimistic: snapshot the draft, set the shadow, clear the draft and re-render *before* the network calls — `manuscripts_sync_selection` (when pool rows exist; moves files between `submitted`/`sketches`/`songs`), then the `manus` resource, then `program` if `programIsDirty()`. The toast fires only once the save succeeded; a failure rolls back to the snapshot. `manusResourceSaveInFlight` disables Gem and "Generér PDF'er" while either write is in flight (both write `manus`; a race would 409).
- **PDFs** (`scripts/generate-pdfs.js`, run by the worker on "Generér PDF'er", which sends `regeneratePdfs:true` → `save_manus()` adds `[regen-pdfs]` to the write message → flag file): reads `scenes.json`/`cast.json`/`config.json`/`archive.json`/`program.json`, composes one `.tex` per sketch/song/bandsang scene with a non-empty `scriptBody` (skips recompiling when byte-identical to the archived `.tex` and the PDF exists), and writes into `archive/<folder>/`: per-scene PDFs (`sketches/`, `songs/`), **Aktoversigt.pdf**, **Rolleoversigt.pdf** (no video/bandsang rows), **manus.pdf** (master manuscript, title page + every scene via `pdf-lib`; same filename as hand-uploaded pre-pipeline years so Arkiv's link is uniform), `manuskripter/` (one per cast member + Sangboss), and the Program PDFs. Each regeneration overwrites the scene's archived `.tex` (`sourceTex`) with the composed content. Role labels use each cast entry's `roleCode`/`description` when present. Can be run locally (`node scripts/generate-pdfs.js`, needs `pdflatex`) against a local data copy.
- **Completion poll** (`manusPollPdfCompletion()`): `siteFileStatus` on `archive/<folder>/manus.pdf` every 3 s (`MANUS_PDF_POLL_INTERVAL_MS`), 10 min timeout, comparing `Last-Modified` to a snapshot taken before triggering. A timeout is shown explicitly (toast + status), never as silent success. `manus.pdf` is written before `manuskripter/` and the Program PDFs, so those may land a few seconds after "done". The quick-link buttons append `?v=<lastGeneratedAt>` (redundant now that everything is `no-cache`, harmless).
- `save_manus()` stamps `generatedAt` on every save (separate from the day-granularity `version` printed in each manuscript header) — a leftover from the git era, harmless.

### Program tab (`data/program.json`, boss/admin) — printed programme booklet

Generates `archive/<folder>/Program.pdf` (front cover / Aktoversigt / Medvirkende / Ordliste / QR page(s) / back cover). The sixth Main Manus View tab, independent of `manusDraft` (not per-scene), with its own `programDraft` + `siteLoadOverride`/`siteSaveOverride` shadow, but no Gem of its own: `manusSaveMain()` sends `program` alongside `manus` whenever `programIsDirty()`. A failure on the program half doesn't roll back a successful scenes/cast half (separate files) — `programDraft` just stays dirty for the next Gem.

- **Medvirkende**/**Ordliste** are each a single **raw-LaTeX** textarea (`\arb{Kategori}` headers, `\\`-terminated lines), inserted verbatim — not escaped, not sorted (ordering is the editor's job). **QR-codes** `{label, url}`: the PNG is generated at build time from `url` via `qrcode`, never stored; added via a centered "+" (`.boss-manage-add-plus`); only `label`/`url` are `texEscape()`'d. The client drops entirely-blank QR rows on save; a half-filled row is left for `save_program`'s validation to reject. QR rows are draggable but have no custom drag image/drop tail (the one exception to the drag convention below).
- `buildProgramSections()` sources Aktoversigt from `scenes.json` (centered `\Huge`, like the original hand-written `program.tex`, not `Aktoversigt.pdf`'s numbered layout) and **excludes the `E`/Ekstranumre act**. Front cover = the current production's Arkiv `coverImage`, falling back to `archive/_assets/placeholder-cover.jpg`; back cover is always that placeholder. The six pieces compile as separate PDFs (Medvirkende/Ordliste have unknowable page counts); `composeProgramPdf()` assembles `Program.pdf` in reading order and a reordered "booklet source" (front, Aktoversigt, Ordliste, Medvirkende, blanks, QR, back — see `imposeBooklet()`'s comment) padded to a multiple of 4, which `imposeBooklet()` imposes two-up on landscape A4 in saddle-stitch order: `ProgramHaefte.pdf` (vertical flip) and `ProgramHaefteHorisontal.pdf` (every back side rotated 180°). The booklet order is a fixed template sized for a normal year (two folded sheets), by product decision.
- Rebuilt by "Generér PDF'er" like the other PDFs. `data/program.json` must exist before the first save (no create-if-missing); if missing, `generate-pdfs.js` skips Program with a notice.
- **Not reset** by Koordinator's close-year: a new production inherits Medvirkende/Ordliste/QR as a starting point.

## Budget (`budget.html`/`budget.js`/`budget.css`) — private datastore

Digitises the revue's reimbursement/accounting workflow. Revyst-level page. Its data (names, phone numbers, receipt photos) is personal, so it lives only in `BUDGET_DATA_DIR` (`/data/budget` on web-1), never in a web-served folder, read/written only through authenticated `update-data.php` actions.

- **Two audiences**: `siteHasLevel('admin')` → management view; else revyst → submit form. Online-only.
- **`budgetApi(action, body)`**: its own authenticated POST helper (a revyst-level submit needs a revyst password, which `siteSaveResource` won't use); JSON-`ok` rule as everywhere. Receipt images are re-encoded to JPEG client-side with a `createImageBitmap`→`<img>`→original-bytes fallback chain (HEIC iPhone photos always upload); receipts are streamed password-gated (`budget_receipt`), never at a public URL.
- **Categories** are per-budget data (`categories.json`, `{expense:[{key,label,abbrev,subcategories?}], income:[{key,label}]}`), lazy-seeded from `budget_default_categories()` and admin-editable via the sheet's "Rediger" toggle (`buildCategoryEditSection`/`budget_categories_save`). Receipt filename + bilagsnummer is `<abbrev>_<n>`, numbered per category at approval; deleting/re-abbreviating a category with a paid expense is blocked (`abbrev_locked`).
- **Sub-categories** (one level, `{key,label}`, sharing one global key namespace so `planned`/`subBreakdown` lookups are unambiguous): edit mode's per-row chevron expands an indented sub-list (same draft, drag helpers, `.budget-subcat-drop-tail`, delete confirms). A category with subcategories shows a read-only Planlagt sum of its subcategories' editable Planlagt; each subcategory gets a derived Brugt/Rest (`computeSpentBySubcategory` over expenses' `subBreakdown`). Revyster only pick the top-level category; splitting happens at approval/"Tilføj udgift"/expense edit, where `subBreakdown` must sum to the amount (`budget_validate_breakdown_sum`, shared with Stregregnskab's `stregBreakdown`). The protected `stregnskab` category never has subcategories and is excluded from the main sheet.
- **⚠️ PHP const-ordering landmine** (whole file): `update-data.php`'s top-level `const`s are registered in execution order, so a const used by a handler dispatched *before* its declaration line is `Undefined constant` at call time. Budget/Forms/Fællesspisning/upload handlers dispatch near the top, so they use **hoisted functions** instead (`budget_receipt_re()`, `budget_max_upload_bytes()`, `budget_default_categories()`, `budget_streg_category_key()`, `upload_path_level()`, …) or consts declared above the dispatch. Any new early-dispatched handler must do the same.
- **Per-budget datastore**: `BUDGET_DATA_DIR/<budgetId>/{budget,requests,expenses,categories,streg}.json` + `receipts/`, beside a root `years.json` (`{activeBudgetId, years:[{budgetId, year, label, createdAt}]}`). Several budgets can share a `year`; `label` is unique (checked on create and rename). Legacy budgets have `budgetId` = the year as a string (`budget_normalize_years_shape()` back-fills on every read); new ids are `<year>_<label>` slugs (`budget_slugify_budget_id()`), which can never collide with a bare year. `budget_active_budget_id()` resolves where revyst uploads land; `budget_resolve_budget_id($body)` lets admin handlers target any budget (default active); `budget_submit` always uses the active one. Year actions: `budget_create_year` (seeds `planned` from the budget closest in time), `budget_set_active_year` (`null` allowed), `budget_rename_year` (metadata only), `budget_delete_year` (recursive delete; clears `activeBudgetId` if needed). No server-side confirmation — the client asks.
- **No active budget is a supported state**: "Skift aktivt budget" has an "Intet valgt" option; revyst submissions then get an explicit `no_active_year` state, and every budget stays browsable by explicit `budgetId`. `loadAndRenderAdmin()` re-fetches the most recently created budget when nothing is active, so deleting the active budget lands on real data.
- **Server actions** (`$BUDGET_ACTIONS`): revyst — `budget_submit`, `budget_active_year_info`, `budget_active_categories`; admin — `budget_read`, `budget_receipt` (strict filename regex, the only guard against reading arbitrary files), `budget_approve`, `budget_request_reject`, `budget_request_update`, `budget_request_split` (one receipt → several expenses), `budget_save_sheet`, `budget_expense_add`/`_update`/`_remove`, `budget_categories_save`, the four year actions, and `streg_read`/`streg_save_rows`/`streg_save_categories`/`streg_save_connection`. Storage uses `budget_mutate()` (flock'd read-modify-write, no sha/409).
- **Admin layout**: Budget sheet (planned/brugt/rest per category; brugt always derived) + Afventende udlæg side by side, Betalte udgifter below. A year toolbar picks the viewed budget (`budgetViewId`, in `localStorage`) independently of the active one. Godkend stamps `paidBy`/`settled:true`/the submission date; category, bilag and receipt lock once paid.
- **Height sync** (`budgetSyncPendingColumnHeight`): Afventende udlæg's list gets Budget's exact height (scrolling or padding out); `renderPendingSection()` always wraps content in `.budget-scroll-wrap` (even the empty state), whose `flex-basis` must stay `auto` (a `0%` basis ignores an explicit `height`). No-op in streg mode.
- **Stregregnskab** (`budgetStregMode`; tab bar `renderBudgetModeTabs`/`budgetSwitchMode`, styled like Formularer's tabs, mode in `localStorage`): swaps the Budget card for a names × drink-category grid and Afventende udlæg for "Priser", hiding Betalte udgifter. Data in `streg.json` beside the budget's other files (`budget_load()`/`budget_mutate()`), seeded Øl/Cider/Soda (`streg_default_doc()`).
  - **Grid** (`buildStregSheetCard`/`stregBuildTable`): always editable (Fællesspisning look) but a Gem-batched draft underneath (`stregSheetDraft`, rebuilt after every load/save/reset/sync). Betaling and Priser's per-streg price recompute on every keystroke against the draft. Gem sends the whole rows array (`streg_save_rows`, full replace; matching `id`s keep `createdAt`/`source`; blank-Navn rows dropped); `Gemt`/`Ikke gemt` sits next to Gem (`.streg-save-group`). Row removal confirms unless the row was never saved. **Nulstil** clears every row (same action, empty array) and disconnects a Formularer connection first (it would re-sync names back). "Forbind" (Formularer Navn-field mapping, `streg_save_connection`; `streg_read` lazily syncs via `streg_maybe_sync`) is disabled while the draft is dirty. A truncated Navn shows the full name in a tooltip (`budgetShowFieldTooltip`); checkbox + input live in `.streg-navn-wrap` (a flex `<td>` broke the row border). A "har betalt" checkbox (`.streg-paid-checkbox`, persisted `paid`) strikes through the row's Betaling (`.streg-paid`). **Udskriv** (`.budget-center-btn`) prints the current draft as a plain table via `#budget-print-sheet` + `window.print()`.
  - **Priser** (`buildStregPricesCard`): **live-save** — Navn/Indkøbspris commit on blur, reorder commits on drop (`budgetWireDropHighlight`/`budgetMoveDraftItem`); each commit resends the whole list (`streg_save_categories`; unknown `key` → `stale_categories`, omitted `key` → new) and refreshes the grid. A new row isn't sent until its Navn is filled. Deleting asks first and is blocked at zero categories; existing tallies for a removed category are left alone server-side. Per-streg price previews live against the typed price (`stregPriceRefreshComputed`).
  - Pris pr. streg and Betaling are derived client-side only (`stregComputePricePerUnit`/`stregCategoryTallyTotal`, which take an explicit `rows` list so the grid can pass its draft).

## Formularer (`forms.html`/`forms.js`/`forms.css`) — self-hosted sign-up forms

Replaces the ~5 Google Forms rebuilt every year. Revyst-level page. Definitions, templates and responses (names, phone numbers) all live in the private `FORMS_DATA_DIR` (`/data/forms`) — no public consumer of a form's schema exists.

- **Two audiences**: `siteHasLevel('boss')` → management (build/edit forms and templates, view/export responses); else revyst → open forms + fill-in. Boss-level (coordination tooling, like Manus/Kalender).
- **`formsApi(action, body)`** mirrors `budgetApi` (any logged-in level; JSON-`ok` rule).
- **Storage**: `FORMS_DATA_DIR/forms/<formId>/{definition,responses}.json` + one `templates.json`. No year/active concept — several forms can be open at once. `formId`/`templateId` are server-generated hex (`forms_id()`), validated with `forms_valid_id()` before building any path.
- **Structure**: a form has `sections` (`{id, title, description, fields}`); an old top-level `fields` array is converted on read. A `FieldSpec` is `{id, type, label, required, optionsSource?, options?, sourceFilter?, …}`. Types: `text`, `textarea`, `select`, `checkboxes`, `scale`, `grid_single`, `grid_multi` (+ legacy `yesno`, accepted but no longer offered). `optionsSource` (`manual`/`scenes`/`rehearsals`) is orthogonal to type: live sources resolve client-side at render time from `SCENES_DATA`/`CALENDAR_DATA` (`formsOptionsFromScenes`/`formsOptionsFromRehearsals`, rehearsals = category `ove`), never stored — `forms.html` loads `scenes-data.js`/`calendar-data.js` for this.
- No hardcoded name/phone fields — "Navn" is just a required `text` field.
- **Frist** (`deadline`): `'YYYY-MM-DD'` or `'YYYY-MM-DDTHH:MM'` via `siteCreateDateTimeField`, shown with `formatDaDateMaybeTime`.
- **Synlighed** (`visibility`, `'boss'` default or `'admin'`): restricts only a form's responses (Statistik/Svar) — withheld server-side by caller level (`forms_visibility()`/`responsesRestricted`); the definition stays boss-editable. Oversigt greys out the icons for a boss on a restricted form.
- **Validation posture**: `forms_submit` checks shape/type/length only, never live options (a race between page load and submit must not lose a submitter's work).
- **Oversigt rows drag to reorder** (`formsWireDropHighlight`/`formsMoveListItem`, within the year-filtered view): the client stamps `order` 0..N-1 optimistically, then `forms_reorder` writes it into each `definition.json`. `forms_save` carries an existing `order` through; new forms get `null`. `formsCompareOrder`: ordered forms first, then by `id` (hex-timestamp prefix ≈ creation order).
- **Dynamic templates** (`FORMS_DYNAMIC_TEMPLATES`): client-only `{id, title, description, generate}` entries run fresh against embedded data and applied through the normal template path — `rolleonsker` (`formsGenerateRolleonskerSections`: fixed sections, one section per act incl. Ekstranumre with one 1-5 Skala per non-song scene and two (Sanger/rapper + Danser) per song, skipping `schedulable:false`, plus a Fravær section) and `fravaer` (`formsGenerateFravaerSections`: one text field per `ove` event in October–November of the current year).
- **Server actions** (`$FORMS_ACTIONS`): revyst — `forms_list_open`, `forms_get`, `forms_submit`; boss — `forms_admin_list`, `forms_admin_read`, `forms_save`, `forms_reorder`, `forms_delete`, `forms_delete_response`, `templates_list`, `templates_save`, `templates_delete`. Saves are create-or-update by optional `id`, full replace; Åben/Lukket just resends the definition. CSV export is client-side. The first save creates whatever directories it needs.

## Fællesspisning (`faellesspisning.html`/`faellesspisning.js`/`faellesspisning.css`) — communal-meal sign-up

## Øveplan (`schedule.html`/`schedule.js`)

Loads only `site.js` → `scenes-data.js` → `calendar-data.js` → `lokaler-data.js` → `schedule.js` (no `site-utils.js`, no `manus-data.js`).

- Single global `state`: `{ rooms, slots, slotsConfig, grid, scenes, allScenes, allCast, absentees, title }` — `slotsConfig` = `{startTime, endTime, segmentMinutes, gapMinutes}` (defaults 25-minute segments, 5-minute "Pause mellem segmenter").
- `grid[slotIdx][roomIdx]` is `{ sceneId, customCast?, crossedOutCast?, customText?, customName?, pairedSceneId? } | null` — only ids, never scene objects. `customCast` overrides a placement's cast; `crossedOutCast` marks people struck through in that cell; `customText`/`customName` are Scenemøde-only; `pairedSceneId` marks a merged dance/actor placement.
- State persists to `localStorage['matrevy-schedule']` on every mutation (`saveState()`), restored by `restoreState()`. Any new mutation must keep this contract. Flush sequence: `renderGrid()` + `renderSceneSidebar()` + `saveState()`. No reactive framework — explicit render calls.
- **Scene data**: from `SCENES_DATA`; on a fresh session or after "Ryd skema", `loadScenes()` prefers Manus's `localStorage` override (`matrevy-override-manus`, with its own TTL) so a just-saved Manus change shows up in the same browser. Otherwise it reflects the embed on reload.
- Scenes are placed via a picker modal (multi-select fills empty rooms left-to-right; a single pick goes straight into the clicked cell), or by drag-and-drop from sidebar chips and between cells (swap; blocked drops highlighted). The picker tags "O" (role conflict) or "F" (absent) — advisory only. A scene with `repeat` can be placed twice before it dims (↻).
- **Priority** badges are read-only, from Stjerneark's `priority`/`dansPriority` in `scenes.json`.
- `buildGrid()` preserves placements by matching rooms **by name**, so reordering/adding/removing rooms doesn't scramble them (a renamed room starts empty). Changing start/end/segment/gap fully resets the grid (`buildSlots(start, end, segment, gap)`); otherwise manually edited slot times are kept.
- **Custom scenes** (`CUSTOM_SCENES`, `custom:true`): `Scenemøde` (editable cast line/title) and `Rekvisitten` (no fixed cast — opens a full-roster checklist; chosen names become `customCast`). Both exempt from "already placed" dimming.
- **Dance/actor split**: a scene with any cast member tagged Dans or Koreograf (`isDanceSplitCandidate`/`isDanceCastRole`) is split at load (`applyDanceSplits()`) into the main part (original id) and `"<name> (Dans)"` (id `::dans`), each with its own priority/repeat (`dansPriority`/`dansRepeat`). Picking both together merges them (`pairedSceneId`, union cast). Runtime-only.
- **Cast classification**: `ROLE_CATEGORIES`/`classifyRoleCode`/`classifyOrKeep` live here (moved from the removed `import.js`). **Always call `classifyOrKeep`.** Displayed and conflict-checked cast both use the filtered list (`getCellCastNames` → `filteredCastNames`, hiding Statist/Ninja; an unmerged song/dance placement narrows to its categories), skipping crossed-out people; a `customCast` is returned verbatim.
- **Per-cell cast editor**: "Roller" (open by default) and "Andre revyster" (closed; open by default for Rekvisitten). A Roller row toggles crossed-out (`(overstreget)`). Busy/absent rows show a suffix and are disabled-but-removable.
- **Absences**: `state.absentees` = `{name, start, end}[]` (minutes since midnight). `isPersonAbsentAtSlot(name, slotIndex)` is the single source of truth (grid styling, "F" tag, editor). An absent person is exempt from conflicts for that slot.
- **Opmærksomhed** (`computeAttentionLists`/`renderAttentionSection`): lists of people needing attention, split at 13:00; hidden in print.
- **Merging/splitting slots** lives in the per-slot time editor (`openSlotTimeEditor`/`renderSlotTimeEditor`): "Flet (op)"/"Split"/"Flet (ned)" above Start/Slut. Merging (`mergeSlots(si)`, enabled only when `canMergeSlots(si)` — no room occupied in both) spans the earliest start to latest end, keeps whichever placement exists per room, and closes the modal. "Split" (`slotTimeMode`) shows two editable Start/Slut rows seeded from `defaultSplitMid()`; "Opdel" (`confirmSlotTimeEditor` → `splitSlot`) keeps placements on the first half.
- **Lokalebooking button** (on the "Lokaler (ét per linje)" line, `openLokalebookingModal()`): a modal of day columns, each listing the rooms booked that day in Koordinator's Lokalebooking (non-blank cells, sheet order; a cell's text other than "x" shown as a note), scrolled to today/the next day. "Hent" **replaces** `#input-rooms` with that day's rooms and `saveState()`s (no rebuild — "Byg øveplan" still does that). Day columns are `schedLokalerDays()`, a copy of Koordinator's `koordLokalerDays()`; data prefers the `matrevy-override-lokaler`/`-calendar` shadows (`schedLoadOverride`), else `LOKALER_DATA`/`CALENDAR_DATA`.
- The grid title (`#sched-grid-title`) is `contenteditable`, stored in `state.title`. "Ryd skema" wipes only `state.grid`.
- `escHtml()` is the sanitizer for this file's `innerHTML` templates — always use it when interpolating.

**Print** (`@media print` in `schedule.css`, via "Download" → `window.print()`): deliberately plain black/white "typewriter" style (Courier New, ruled borders, `@page { size: A4 landscape }`, 12px base), fixed-width columns, flexible rows, Opmærksomhed hidden. `@page { margin }` is unreliable (Safari) — real in-flow padding guarantees the whitespace.

## Data schemas

Full schema docs: `data/README.md`. Key constraints:

- `data/scenes.json` — scene `id` is `"act-number"` (`"1-3"`, `"E-2"`). `priority`/`repeat` (and `dansPriority`/`dansRepeat` for the dance half) come from Stjerneark. `schedulable:false` = video/band jingle with no rehearsable cast. `production` is the revy's name (set by Koordinator). `cast[].role` is a classified category in Manus-saved data (raw script codes only in legacy/hand-edited data) — classify at runtime with `classifyOrKeep` either way.

## The write endpoint (`server/update-data.php`)

`action:'login'` maps a password to a level (`hash_equals` against the three passwords). Shared passwords are not real authentication and should be treated accordingly. Dispatch order:

1. Legacy `{pin, scenes, cast}` → `save`/`manus`.
2. `login`.
3. `upload`/`delete` — binary files at client-chosen paths, level from `upload_path_level()`: `ARCHIVE_PATH_RE` (`archive/<folder>/{cover.jpg,manus.pdf,Manuskript.pdf}`) and `ARCHIVE_SNAPSHOT_RE` → admin, `WIKI_ATTACHMENT_PATH_RE` → boss. Checked before any write and re-checked inside the handlers.
4. `$BUDGET_ACTIONS`, `$FORMS_ACTIONS`, `$FAELLES_ACTIONS`, `$BAND_ACTIONS`, `$LOKALER_ACTIONS` (private stores, above).
5. `$POST_ACTIONS` (revyst, append-only — must never accept a client-supplied full array): `posts_create` (image at `POST_IMAGE_PATH_RE`), `comments_create`, `manuscripts_create`, `manuscripts_update`.
6. `manuscripts_sync_selection` (boss; only `{id, selected}` pairs; moves files between `submitted`/`sketches`/`songs`) and `manuscripts_delete` (admin; one `{pdfPath, texPath, id?}`, `ARCHIVE_MANUS_ANY_RE`).
7. `save` → `$RESOURCES` (per-resource min level + validator + writer), full-array replace: **boss** — `manus`, `calendar`, `posts`, `wiki`, `manuscripts`, `program`; **admin** — `archive`, `bosses`, `config`, `masterplan`, `lokaler`, `gantt`, `revyugen`, `production`.

**`github_api()` can write anything under `SITE_DATA_DIR`** (all public site data), so the path allow-list regexes are what stand between a request body and overwriting any of it; `github_api()` adds a generic guard (no empty/`.`/`..` segments). **Never relax one of these regexes without an equally strict replacement.** Error codes still carry their git-era names (`github_read_failed`, `github_write_failed`).

PHP's `json_encode` writes JSON with 4-space indentation (hand-edited files used 2) — a cosmetic difference, not a content change.

## Adding a new page

Copy `page-template.html` (loads `style.css` + `site.js`; add `site-utils.js` for any data-driven page), then register it **once** in `site.js`'s `SITE_PAGES` with its access level (and `group` if it belongs under Redskaber). Nav, active highlight and gating render automatically.

## Code style

- `'use strict'` at the top of every JS file.
- Section headers in JS use `// ── Section name ─────`.
- HTML and every user-facing string/label is Danish.
- Every `:hover` rule lives inside `@media (hover: hover)` (no sticky hover on touch); split a combined `:hover, :focus-visible` so `:focus-visible` stays ungated. Hover-only *reveals* need a `@media (hover: none)` always-visible fallback (see `.cell-remove` in `schedule.css`).
- **Every draggable-to-reorder row/card supplies its own drag image.** The browser's default snapshot is messy, and a `<tr>` can't be rasterized outside its table at all. Each page has a small `<prefix>GetDragImageEl()` (`formsGetDragImageEl`, `budgetGetDragImageEl`, `wikiGetDragImageEl`, `manusGetDragImageEl`, `bossesGetDragImageEl`, `koordMpGetDragImageEl`, `calGetDragImageEl`) returning one shared, lazily-created, **off-screen** `<div>` (`position: fixed; top/left: -999px` — never `display:none`, which some browsers won't snapshot), styled as a small rounded label. Every `dragstart` sets its text to the item's identifying label and calls `e.dataTransfer.setDragImage(ghost, 12, 16)` first. New draggable lists follow the same recipe (Program's QR rows are the one current exception).
- **A `<table>`'s drop highlight must never use `border-top`/`border-bottom`**: under `border-collapse: collapse` a wider border wins the whole shared edge and eats the row separators. Use an inset `box-shadow` (`inset 0 2px 0 0 transparent` → `var(--accent-warm)` on `.<x>-drop-target`), as `.budget-manage-tr`/`.forms-dashboard-row` do. `<div>` rows aren't affected.
- **A per-row drop target can only insert *before* a row** — reordering to the end needs a trailing drop-tail element (`.wiki-manage-drop-tail`, `.manus-akt-drop-tail`, `.forms-drop-tail-row`, `.budget-manage-drop-tail-row`, `.budget-subcat-drop-tail`, `.streg-price-drop-tail`, `.koord-mp-drop-tail`, `.gantt-drop-tail`), or a drop zone on the whole list (Forside's Bosser `<ul>`, whose rows stop propagation).

## Updating for a new production

Koordinator → Arkivering: generate the PDFs, **Afslut revyen** (snapshot, archive entry, empty Manus/manuscripts, no active folder), then **Start ny revy** (name, new folder, archive entry). Submissions then land in the new `archive/<folder>/submitted/`. `program.json` and Øveplan's per-browser state are not reset.

## Known issues & ideas

- **"Generér PDF'er" with an empty production** fails: with no scenes, Aktoversigt emits an empty `enumerate`, LaTeX rejects it, and the whole run aborts. Fix: skip or placeholder empty acts.
- **Edit conflicts are last-save-wins**: the browser never sends the version it loaded, so the 409 only catches simultaneous saves. Fix: every save sends the `sha` of the data the page was built from (embedded, or a cheap read action); `update_file()` compares and returns 409 → "Nogen andre har ændret dette — genindlæs". Manus is hit hardest (two people on different sketches overwrite each other) — `autosave.md` has the per-scene merge plan, plus the rest of the auto-save/undo roadmap.
