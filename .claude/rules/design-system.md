# Design system & site-utils (full detail)

The summary is in CLAUDE.md; this is the complete component reference for editing `style.css` or `site-utils.js`.

## Site-wide title & button conventions (`style.css`)

One design system for every page **except `schedule.html`/Øveplan**, which keeps its own pre-theme look and its own `.btn-primary`/`.btn-secondary` in `schedule.css` (its "Ryd skema?" confirm does use the shared `.login-overlay`/`.login-actions`/`site-btn-*`).

**Tokens** (`:root` in `style.css`): the warm palette (`--bg`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-muted` a warm grey, `--input-bg` cream, `--accent-warm*`), `--radius` (6px, every control and field) / `--radius-card` (8px), `--focus-ring` (the one focus indicator), `--disabled-opacity`, `--shadow-pop`/`--shadow-toast`, `--row-hover`, `--fs-xs/sm/md/lg`, the category colours `--cat-{blue,green,yellow,red,purple,teal}` + `-bg` (Kalender, Gantt, Revyugen, file-type badges) and `--danger-tint`/`--success-tint`. Typed text is `--text`, never `--header` (that's the header bar). Use tokens rather than new literals. The font is Computer Modern Serif, vendored in `fonts/computer-modern/` (SIL OFL).

**Global defaults** (zero-specificity `:where()`, so any class wins): every form control inherits the site font, inputs use `--text`, checkboxes/radios are amber (`accent-color`), placeholders are muted, and a link inside text (`a` without a class, or `.site-link`) is amber and underlined. A new element gets these for free.

## Site-wide components (`style.css`, a few helpers in `site-utils.js`)

Use these instead of a page-scoped copy; a page's JS builders stay page-scoped (the duplication convention) but emit these class names.

- **Tabs**: `.site-tabs` > `button.site-tab.active` (amber underline); `.site-tabs-sub` for a second-level bar (Masterplan's phases, Manus's Tabel/Boxplot). On a phone the bar scrolls sideways. No mobile dropdowns.
- **Collapsible header row**: the whole row is one `button.site-collapse[aria-expanded]` with a `.site-chevron` (one ▾, rotated while collapsed; never swap glyphs) on the left. Hover recolours only the chevron, never the title. `siteCollapseHeading(tag, title, {open, body, onToggle})` builds a card heading + hides `body`; `.site-collapse-icon` is the small chevron-only variant (a note's fold, Budget's sub-categories). Used by every Boss Box, Formularer's Betingelser/sections, Manus's (valgt)/(ikke valgt) columns, Koordinator's Lokalebooking/Fravær/logins/notes, Bandet/Teknikken/Lydfiler folders, Budget's pending groups.
- **Boss Box**: `.site-boss-box` card, **always the last card on the page**, only as wide as its content, a bare h2 that is the collapse toggle, **open on every load** (state in memory only). Settings are `.site-switch-row`s: label left, `.site-switch` (`label.site-switch > input[type=checkbox] + span.site-switch-slider`, 2.2rem, green when on) right.
- **Edit-mode toggle**: `siteEditToggle(editing, onClick, {editLabel, doneLabel})` — a pencil that becomes an amber check mark (`.site-icon-btn.site-edit-toggle`) in the card head's top-right corner. Used by Bosser, Koordinator's logins, Lydfiler's guide, Gantt, Revyugen, Ninjas (both sheets) and Wiki's chapters (whose editor leaves via its own Annuller/Slet/Gem). Budget's category sheet keeps its "Rediger/Annuller" button; buttons that just open an editor modal keep a text "Rediger".
- **Icon buttons**: `.site-icon-btn` (1.8rem square, muted glyph, hover recolours amber, focus ring), `-danger` for ✕ (hover red), `-sm` for a ✕ inside a dense header/chip, `.site-add-plus` for a "+" (`.site-add-center` centres it under a list), `.site-icon-on` keeps it amber (a pinned post). The glyph is `✕`, never `×`.
- **Fields**, three kinds:
  - **Sheet cells and in-place text with no label** — `.site-inline-field`: transparent at rest, `--border` on hover (inside `@media (hover: hover)`), amber border + ring while focused, **background stays transparent**. `[readonly]` (an older year) opts out of hover/focus. Bandet, Kostume, Rekvisit, Ninjas, Fællesspisning, Streg, Masterplan, Lokalebooking, Fravær, Stjerneark, Bosser, Gantt, Budget's sheet, Koordinator's notes, Wiki's chapter title.
  - **A field next to its own label on the page** — add `.site-field-labeled`: the same, but cream (`--input-bg`) while focused, still no resting border (Koordinator's logins, Manus's Sangboss).
  - **Fields in modals and forms** — the boxed `.edit-field` look: resting border, cream background, amber border on hover, amber border + ring while focused. Pickers (`.site-field-btn`) match.
  A non-editable field (e.g. `.budget-manage-input-locked`) opts out of the hover border explicitly.
- **Toolbar controls**: `.site-toolbar-control` on a `.site-field-btn` or `.btn-small` in a page's title row or card toolbar (revy pickers, year filters, "Print") — 2rem tall, 0.85rem, cream.
- **Segmented toggle**: `.site-segmented > button(.active)` — joined buttons, the chosen one solid amber (Kalender's Måned/Liste, Fællesspisning's Madark/Oversigt).
- **Sheets**: `.site-sheet` on a spreadsheet-style editable table (+ `.site-sheet-lines` for column lines): inset box-shadow row/column lines, muted 0.8rem headers, `.site-sheet-section` rows on `--surface-2`, `.site-sheet-noline` on a drag-handle/actions column (no line on either side), `.site-sheet-sticky` + an inline `left` for the sticky first column. Long sheets scroll **with the page** (the wrapper only scrolls sideways) and `siteStickyHead(thead or header element, container?)` keeps the header row under the site header (a transform per frame; works for div grids too). List tables (Budget's ledger, Formularer's Oversigt) don't use it.
- **Modals**: `.edit-modal` is 480px; `.site-modal-sm/-md/-lg/-xl` are 400/560/760/1040px. A one-line "Slet …?" confirm is `.site-confirm-modal` (shrink-wraps between 300 and 480px; its h2 is centred) with `.site-confirm-text` (the title line, when there's no h2) and `.site-confirm-sub` (the muted explanation).
- **Text**: `.site-muted` (0.9rem muted), `.site-hint` (0.85rem), `.site-empty` (centred, muted). Italic only for an in-tree placeholder row ("Tom mappe").
- **Save status**: `.site-save-status` (+ `.dirty` amber, `.error` red). Auto-save pages say "Gemmer…" / "Gemmes automatisk · Gemt" / "Ikke gemt: …"; pages with a Gem button say "Ikke gemt" / "Gemt". Live-write pages (Bandet, Kostume, Rekvisit, Ninjas, Fællesspisning) show no status line.

- **Page titles**: `.page-content h1` (1.6rem/600, centered). Only Arkiv's `.arkiv-hero h1` tweaks its margin.
- **First-level buttons** (inline, not in an overlay): `.btn-small`/`.btn-small-danger` — warm-cream idle, warm-amber hover; `-danger` stays red.
- **Second-level buttons** (inside a `.login-overlay`/`.login-modal`): `.site-btn-primary` (blue) / `.site-btn-danger` (red) / `.site-btn-warm` (amber) / `.site-btn-success` (green), 6px radius, solid fill, white text. `calPillBtn()`/`budgetPillBtn()`/`wikiPillBtn()`/`formsPillBtn()`/`faellesPillBtn()`/`koordPillBtn()` are thin per-page factories (`variant` names the class; default `site-btn-warm`, e.g. Annuller).
- **Blue is for Login** (and the gate card's login button). Every other positive/confirm/save action — "Gem", "Indsend", "Betalt", "Forbind" — is `.site-btn-success` (green). One deliberate exception: Formularer's builder "Skabelon" button is blue.
- **Arkiv's detail overlay keeps the old oval pills**: its link actions (`.arkiv-action-btn`) use `.site-pill-btn` / `-primary` (green) / `-danger` (red) / `-warm` (amber) — idle white/cream oval, thin border, hover/focus-visible only changing `border-color`. Kept in `style.css` solely for that. (`archive.js`'s own `openYearEditor()` also uses them, but it's unwired legacy code — years are edited from Koordinator.)
- **Button-width floor**: `.site-btn-*` buttons (Manus excepted — own sizing) have `min-width: 5rem` with `0.7rem` horizontal padding, so common labels render at a uniform width while long labels grow. Set on `.login-actions > button`; `.wiki-edit-actions > button` repeats it (not an overlay).
- **Orange = chosen/selected, everywhere**, in two strengths: solid amber + white text for a segmented toggle or a picker's chosen row (`.site-segmented`, `.site-list-selected`, `.site-dp-selected`, Kalender's today-marker); a light amber fill + amber text for a picked row in a longer list (Manus's Vælg scener, Manus's upload type box). Never blue. Øveplan's `.picker-selected` uses its own literal `#d8b879` (same idea, separate literals per its own convention). `.cal-cat-deadline`'s and the audio/MuseScore badges' blue is a category identity color (`--cat-blue`), not a selection state.
- **Scrollbars** are themed site-wide in `style.css` (every page, Øveplan included): thin tan `--border` thumb on a transparent track, `--accent-warm` while the scroll box is hovered (html/body excluded, or the page scrollbar would stay amber; Safari matches via `::-webkit-scrollbar-thumb`). Don't style a page's own.
- **Focus**: every control shows `--focus-ring` (a soft amber 2px ring) when keyboard-focused, ✕ buttons included; the `:where()` amber outline in `style.css` is only the fallback.
- **Modal action layout** (`.login-actions`): `justify-content: center` by default — every ordinary confirm dialog needs no per-modal code. Editor-shaped modals pin actions to the corners (delete left, save right) with `justify-content: space-between`, combining `.login-actions` with their own class for specificity: `.login-actions.cal-event-actions`, `.faelles-connect-modal .login-actions`, `.streg-connect-modal .login-actions`, `.login-actions.budget-expense-edit-actions`, `.login-actions.ninjas-modal-actions`. The three that can render a single button (a new Kalender event has only Gem; the two connect modals have only "Forbind" until connected) add `:has(> :only-child) { justify-content: center }`. Self-contained bars outside `.login-actions` — `.post-detail-actions`, `.budget-save-bar`, `.forms-builder-actions` — use plain `space-between` (the latter two center a middle button absolutely: `.budget-center-btn`, `.forms-builder-cancel`). Wiki's in-page editor always has Annuller/Slet/Gem, `space-between`.

## Site-wide field pickers (`site-utils.js`)

Native `<input type="date"/"time">`/`<select>` hand their UI to an unstylable OS shadow root, so every page except Øveplan uses a shared custom-popup system:

- `siteOpenFieldPopup`/`sitePositionFieldPopup`/`siteCloseFieldPopup`/`siteToggleFieldPopup` — popup chrome (`.site-field-pop`, `position:fixed`, clamped on-screen, **repositions** on scroll/resize, closes on outside mousedown or Escape, one open at a time; Escape `stopPropagation`s so it closes just the popup, not a surrounding modal).
- `siteCreateDateField(initialIso)` — `.site-field-btn` opening a month grid (`siteOpenDatePicker`, `.site-dp-today` marker).
- `siteCreateTimeField(initialValue)` — typeable combo (`.site-field-combo`: real `<input>` + clock toggle opening a quarter-hour list); `siteParseTimeInput` normalizes `14:30`/`14.30`/`1430`/`930` on blur/Enter, reverting to the last valid value otherwise.
- `siteCreateDateTimeField` — one field for date with optional time: picking a day re-opens the popup as a time list (`siteOpenTimePicker`, with an "Ingen tid" row and an optional pinned "23:59" `endOfDayOption`); the date applies as soon as it's picked.
- `siteCreateDropdownField(options, initialValue, placeholder?)` — `<select>` replacement without per-option color (`siteOpenDropdownPicker`), used site-wide.

Every factory returns an element with a `.value` getter/setter and a `change` event, so call sites use them like native inputs. Kalender's category field (`calCreateCategoryField`) stays page-specific (colored dot per option) on the same primitives. `schedule.js` carries its own `sched`-prefixed duplicates of the popup chrome, dropdown and time field (it doesn't load `site-utils.js`) with the same CSS classes; its time field fires no `change` event.


## Save-model details (from `site-utils.js`)

- **Saves send the full next array** (`{events:[...]}`, `{posts:[...]}`, …) — no per-item patch API. The server reads the file and writes it back within one request, so the stale-sha `409` only catches two saves landing in the same instant; two tabs editing the same data a minute apart resolve as **last save wins** (see Known issues). **Exceptions**: Manus merges before saving (below), and **Kalender, Posts and Wiki** save through `siteSaveListResource(resource, listKey, update)` (`site-utils.js`): boss `resource_read` returns the live file + sha, `update(liveList)` applies just this one change (add/edit/delete by `id`; may be async; a string = error message, `null` = cancelled), then the save sends `baseSha` and a 409 `stale` re-reads and re-applies (3 attempts). The result list becomes the override shadow. So a tab open all day never drops what others saved meanwhile. Same-item edits are last save wins, except Wiki's in-place chapter editor, which asks before overwriting a chapter someone else saved since editing started (`wikiConfirmOverwrite`); editing something deleted meanwhile shows "… slettet af en anden". Posts' edit keeps the live `pinned`/`comments`; Wiki's "Rediger kapitler" applies only its own order/adds/removals/title and publish changes, keeping chapters added by others (at the end).
- **`site-utils.js`** (every page except Øveplan): Danish date helpers (`DA_MONTHS`, `DA_WEEKDAYS_SHORT`/`_LONG` Monday-first, `parseIsoDate` — always from parts, never `new Date('YYYY-MM-DD')` which parses as UTC — `formatDaDate`, `formatDaDateMaybeTime`, `todayIso`); `siteShowToast`; `siteSaveResource(resource, payload)` (the boss/admin save flow — stored login password or a `sessionStorage`-cached prompt keyed `matrevy-manus-pin`; returns `{ok}` or `{ok:false, message}`, never throws; `message === ''` means cancelled → silent no-op); `siteFileAction`/`siteUploadFile`/`siteDeleteFile` (the `upload`/`delete` actions); `siteCreateAutosave({save, onStatus})` (debounced ~1 s, serialized auto-save of a page's local draft — `{schedule, flush, isBusy, hasUnsaved}`; `save()` builds from the current draft and must not re-render; a failure isn't retried until the next change/`flush()`; a `beforeunload` warning while anything is unsaved — used by Gantt, Revyugen, Masterplan, Lokalebooking, Stjerneark and Manus's Program; see `plans/autosave.md` for the site-wide plan); `siteDraftBackup(name)` (a Gem page's unsaved draft mirrored to `localStorage['matrevy-draft-<name>']` as `{data, savedAt, tabId}` — `read()` ignores this tab's own and >14-day-old backups, `clear()` only removes one this tab wrote so a clean tab never deletes another tab's work, `discard()` always; used by Manus's Gem tabs); `siteFileStatus(path)` (same-origin `HEAD`, `{exists, date, checkFailed}` from `Last-Modified` — on the server a file's `Last-Modified` only changes when it's rewritten); `siteOpenEditModal`/`siteEditField` (imperative modal chrome) and `siteOpenModalWithClose` (✕ + Escape); and the shared-component helpers `siteCollapseHeading`, `siteEditToggle`/`siteIcon` and `siteStickyHead` (see "Site-wide components"). Both modal helpers track a backdrop `mousedown`'s own target and only close on a matching backdrop `click` (a drag that started inside the modal, e.g. a textarea resize, must not close it).

**Drag images**: existing examples of the per-page recipe are `formsGetDragImageEl`, `budgetGetDragImageEl`, `wikiGetDragImageEl`, `manusGetDragImageEl`, `bossesGetDragImageEl`, `koordMpGetDragImageEl`, `calGetDragImageEl`; drop tails `.wiki-manage-drop-tail`, `.manus-akt-drop-tail`, `.forms-drop-tail-row`, `.budget-manage-drop-tail-row`, `.budget-subcat-drop-tail`, `.streg-price-drop-tail`, `.koord-mp-drop-tail`, `.gantt-drop-tail`; table highlight `inset 0 2px 0 0 transparent` → `var(--accent-warm)` on `.<x>-drop-target` (as `.budget-manage-tr`/`.forms-dashboard-row`). Program's QR rows are the one exception without a drag image.
