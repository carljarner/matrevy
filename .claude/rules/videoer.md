# Videoer (`videoer.js`/`videoer.css`, the Videoer tab on Arkiv): the recorded revyer with scene chapters

A members-only video player for the recorded revyer, with a chapter per scene and optional subtitles. **One long video of the whole revy per year** (the user's decision): the page shows, uploads and imports only that one; the store would allow more (a leftover extra shows as another row in edit mode, to delete). **A tab on Arkiv** (`arkiv.html`, see `arkiv.md`), no page of its own and not in `SITE_PAGES`. **Revyster watch; boss adds years, uploads, edits chapters and subtitles and downloads; admin also imports and removes a revy.** JS prefix `vid` (every top-level name, since `archive.js` and `albums.js` share the page: `vidEl`, not `el`), root `#videoer-root`. Plan and later phases: `plans/videoer.md`.

**Server: Teknikken's store code on a fourth store** (`teknik_stores()['videoer']`: `VIDEOER_DATA_DIR` = `/videoer` in the container = `/mnt/videoer/store` on web-1, **its own Hetzner Volume**, outside `/srv` so **never backed up** (the originals are kept elsewhere); `videoer.json` + `files/` + `uploads/` + `incoming/`). Two store flags only it uses: `'quota' => 'disk'` (`teknik_quota_bytes()` = the volume's `disk_total_space()` minus the 2 GB reserve, so growing the volume needs no deploy) and `requiresMarker` (`teknik_dir()` answers `503 videoer_volume_missing` unless `.matrevy-volume` is in the folder: an unmounted volume leaves an empty bind on the root disk, which must never fill). `$VIDEOER_ACTIONS` sets `$GLOBALS['TEKNIK_STORE'] = 'videoer'` and reuses `albums_create` (→ `409 album_exists`), `albums_reorder`, `albums_stream_urls`/`albums_stream_url_map` (the `s` claim is now `teknik_store_key()`), `teknik_delete_folder`, `teknik_rename_file` and the `teknik_upload_*` handlers, plus its own `videoer_read`, `videoer_delete_file`, `videoer_set_chapters`, `videoer_set_subtitles`, `videoer_set_duration`, `videoer_list_incoming`, `videoer_import`. Revyst: `videoer_read`, `videoer_stream_urls`. Boss: everything else but import and delete. Admin: `videoer_list_incoming`, `videoer_import`, `videoer_delete`, `videoer_delete_file` (the latter unused by the page). No `clear_all`, no folder zip: **permanent**, never emptied by "Afslut revyen", never mirrored.

- **Data model**: a year is a top-level teknik folder plus `archiveFolder` (one per Arkiv year; the page shows the live Arkiv name/cover from `ARCHIVE_DATA`, like Albums). A video is a teknik file (`mp4`/`m4v` only: `videoer_check_upload_name()` before `teknik_upload_start`, `400 unsupported_type`) plus `order` (`teknik_next_order()`, last in its year), `durationSec`, `faststart`, `codecs` (all three from `videoer_mp4_probe()`, which walks the MP4's top-level boxes: `mvhd` for the length, `moov` before `mdat` = faststart, each `stsd`'s first format: `avc1` H.264, `hvc1`/`hev1` HEVC, `mp4a` AAC), `chapters`, `chaptersVersion`, `subtitleFileId`. `teknik_store_ordered()` (albums + videoer) gates the `order`/`durationSec` branches in the upload code. Videoer skips the upload's CRC (no zips; 1-2 GB files).
- **Chapters**: `[{t, uid, label}]`. `t` in seconds (one decimal) or **null = not marked yet** (scenes inserted from the manus wait unmarked; revyster only see marked ones, `vidChapters()`). `uid` = the scene's uid from `archive/<folder>/snapshot/scenes.json` (deep links and "already inserted"), null for a free chapter (Ouverture, Pause). `label` is stored, so years without a snapshot (2004-2007, the current one) work. `videoer_set_chapters {fileId, chapters, baseVersion}` replaces the list; a different `chaptersVersion` → `409 stale` with the live list in the reply. The server keeps the client's order.
- **Subtitles**: a `.vtt` file record in the same folder with `subtitleFor` = the video's id (never shown as a video; `albums_reorder` and `teknik_next_order` skip them). `videoer_set_subtitles {fileId, vtt}`: UTF-8, starts with `WEBVTT`, ≤2 MB (`400 invalid_subtitles`), written as a new file id named after the revy (`MatRevy 2025.vtt`, the download name), swapped in under the lock, the old file deleted; `''` removes them. `videoer_delete_file` takes the subtitles with the video. `vtt` is in `teknik_inline_types()` (`text/vtt; charset=utf-8`).
- **Import**: admin rsyncs to `incoming/`; `videoer_list_incoming` lists it, `videoer_import {name, folderId, title}` `rename()`s the file into `files/<id>` (same volume, instant) and probes it. **The path guard** (`videoer_incoming_path()`): a plain name (`videoer_incoming_name_ok()`: no separators, no leading dot, no `..`, `.mp4`/`.m4v`), not a symlink, and its `realpath()`'s `dirname` must be `incoming/` itself. Never relax it.
- **Stream links** as Albums: `videoer_read` returns a signed inline URL for every file (videos and `.vtt`s) valid 12-36 h, `Cache-Control: private, max-age=43200` for both stores. The page renews them with two hours left (15-min check) and on a `<video>` error (one retry per loaded video, resuming at the same spot and play state).

## Page

- **Routing**: `#videoer` overview, `#videoer/<archiveFolder>` a year, `#videoer/<folder>/<uid>` a scene (kept for links from elsewhere later, e.g. Manus; the page itself has **no "copy link" buttons**, by decision). `vidApplyRouteTarget()` queues `vidPlayer.pendingSeek` (no autoplay) and `history.replaceState`s the uid away, so a re-render doesn't jump again. Leaving the year or the tab pauses the video (`vidOnRoute`). `vidTabShowing()` gates naming the page and the keys.
- **Overview**: a grid of `.vid-tile` covers (a ▶ badge in the corner; a year without a cover photo gets Arkiv's placeholder `archive/_assets/placeholder-cover.jpg` (`VID_PLACEHOLDER_COVER`, a copy of archive.js's constant), and like Arkiv the year as text if that fails), newest year first; revyster never see a year without a video. Meta: "2 t 41 min · 34 scener". Boss: a dashed "+" tile → "Tilføj revy" (Arkiv years not added yet).
- **Year view**: back link + `siteEditToggle` (boss), name/meta, then `.vid-stage`: the player column (`.vid-main`, as wide as a 16:9 picture fitting the screen so the strip lines up; smaller in edit mode) and the scene list beside it from 1000px (`.vid-stage-side`), below otherwise.
- **The player is one `<video controls playsinline preload="metadata">`** (`vidPlayer.video`), created once and re-inserted by every render (a media element re-inserted in the same task keeps playing; never `replaceChildren` it away and back in a later task). `vidEnsurePlayer()` only changes `src` when the video changes; `vidSyncTrack()` swaps the `<track>` when `subtitleFileId` changes. Native controls on purpose (fullscreen, AirPlay, PiP; iPhone only has native fullscreen).
- **Under it**: the scene strip (`.vid-strip`): one absolutely positioned segment per marked chapter, `left`/`width` in % of the length, so boundaries and the playhead (`--vid-pos`) match the real times. The 2px gap is cut out of the end of each segment (`padding-right` + `background-clip: content-box`), never added between segments (flex gaps shifted everything after them: the old bug). The empty track shows before a first chapter that isn't at 0; the current segment is amber; rebuilt only when chapters/length change (`dataset.key`). On mouse devices `.vid-strip-tip` (the site's dark tooltip, fixed on `<body>`, z-index 250, clamped on-screen) shows the scene's name and start time over the pointer; no native `title`. **Mouse only** (`pointerType === 'mouse'`: a tap sends a fake mousemove but no leave, which left the label standing on touch screens). Hidden on `pointerleave`, by a document-level `pointermove` anywhere outside the strip (a strip replaced under the pointer never sends a leave), on leaving the window, `blur`, scroll and every render. A click jumps to the scene's start. Then, left to right: previous scene, the current scene's name, the CC toggle (only with subtitles), next scene (rightmost). No "Fortsæt fra …" resume button and no saved positions (removed: not useful). Previous restarts the scene after 3 s, like Albums. `vidPaintNow()` repaints all of it (plus the list's `.vid-chapter-current`, light amber, scrolled into view inside the list while playing) on every `timeupdate`; never a full render.
- **Scene list** (`.vid-chapters`): time + label rows, a tap seeks and plays. Beside the video (≥1000px) it is exactly as tall as the video column and scrolls inside (`.vid-side` is `height: 0; min-height: 100%` in the grid row, so only the video column sets the height); stacked below the video it shows every row.
- **`hidden` needs CSS help**: the site has no global `[hidden] { display: none }`, so an element with its own `display` (the hover label's `flex`, `.site-icon-btn`'s `inline-flex`) stays visible with `hidden` set. `videoer.css` starts with `#videoer-root [hidden], .vid-strip-tip[hidden] { display: none !important }`; when testing, check `getComputedStyle(el).display`, not `el.hidden`.
- **Subtitles**: off by default; the CC button (or the browser's own captions menu, followed by `vidOnTrackModeChange`) toggles `vidPlayer.subsOn`, remembered per browser. **The page draws them itself** outside fullscreen: the track is `hidden` (cues load, `cuechange` → `vidPaintSubs` writes the active cues as plain text lines, tags dropped, into `.vid-subs` over the picture, inside `.vid-frame` with the `<video>`). Reason: the browser's own rendering sits low and jumps up and down, late, as its control bar shows and hides; the layer stays at a fixed `bottom: max(14%, 4.5rem)` (phones `max(18%, 3.25rem)`), font scaled by `cqw`. In fullscreen (Fullscreen API on the video, or iOS's `webkitbeginfullscreen`) the layer can't be seen, so `vidApplySubtitleMode` switches the track to `showing` there (styled by `.vid-video::cue`) and back after. Off = `disabled`. `vidPlayer.settingMode` keeps our own mode changes from looking like the user's.
- **Keys** (capture phase, Videoer tab, not in fields/modals/popups): Space only plays/pauses, like Albums: it also drops focus from whatever was clicked last (a key press on a mouse-focused button would light up its `:focus-visible` ring and look like Space went there), handles the video itself too (so it never toggles twice), and the keyup is swallowed so a focused button isn't pressed. `,`/`.` previous/next scene. Albums' Space only runs on the Albums tab.
- **Only one thing plays**: on `play` it dispatches `arkiv-media-play` (`{source: 'videoer'}`) and pauses on another source's. It sets its own Media Session handlers on every play (scene name as title, revy as artist, cover; previous/next = scenes; seekbackward/seekforward cleared), and Albums re-sets its handlers when the music starts (`albOnPlayState`).
- **Remembered** in `localStorage['matrevy-videoer']`: only `subtitles` (on/off).

## Boss: edit mode

- **The video** (`.vid-edit-list` above the player, one row): "Video", length · size, the CC icon (`.vid-sub-btn`, amber `site-icon-on` when the video has subtitles; without, a click uploads; with, a `.site-dd-pop` menu: "Download undertekster (.vtt)" (via `videoer_download_url` on the subtitle file, so any boss can correct them and upload again), "Upload nye undertekster", "Fjern underteksterne"), download (hidden iframe; iOS a new tab), and **admin only** a ✕ that removes the whole revy from Videoer (`videoer_delete`: video, scenes, subtitles) in **two steps** (`vidConfirmRemoveRevy`: "Slet videoen?" → Fortsæt → "Er du sikker?" → Slet). A revy without a video shows admin a "Ingen video endnu" row with the same ✕. There is no "Fjern revyen" button (removed: the ✕ does it). To replace a video: remove the revy, add it again, upload. No title, rename or reorder: the stored name is always `Hele revyen.<ext>` (`VID_VIDEO_NAME`, only seen in downloads). Warnings from the probe in red: HEVC or not H.264, and not faststart (with the ffmpeg fix). A bar below, **only while the revy has no video** (edit mode or not): "Upload video" and (admin) "Importér fra serveren", centred; a desktop file dropped on such a card opens the upload modal.
- **Chapter editor** (`vidBuildChapterEditor`, replaces the scene list, full width): no "Marker næste"/M (removed by decision); a centred "+" under the list (`.site-icon-btn.site-add-plus.site-add-center`: a free row at the current time, label focused, the list scrolls itself, the page never moves); "Indsæt fra tekst" (`vidOpenPasteChapters`: paste one scene per line, time then name, as in a YouTube description: `01:03:10 KomAn KomAn (2006)`; `vidParseChapterText` also takes `1:03:10 - …`, `63:10 …` and a leading `-`/`•`, quietly skips headings ("Akt 2", "Ekstranumre", "Manus") and links (`VID_PASTE_HEADING`), and tidies names (a spaced en/em dash becomes ", ", "Video : X" becomes "Video: X"); a live summary counts the scenes, quotes the first line it didn't understand and warns about times past the video's end; with scenes already there, a segmented "Erstat de N nuværende" (default) / "Tilføj til dem"; pasted scenes get `uid: null`), "Indsæt scener fra manus" (only when the year has a snapshot: a checkbox per act, counting scenes not already in any of the year's videos; appends them unmarked in manus order). No hint line and no per-row "Nu" button (both removed by decision). Rows: time (`.vid-ce-time`, typed `1:02:03`/`62:03`/`3723`/`1.02.03`, parsed by `vidParseTimestamp`; unmarked rows tinted), ▶ go, label, ✕. `vidChapterDraft` holds the rows; `vidSortDraft` sorts the marked rows by time into the marked rows' places and leaves unmarked rows where they are (so the manus order of the rows still to mark stays), on every editor render and in what is sent.
- **Saving**: `siteCreateAutosave` ("Gemmer…" / "Gemmes automatisk · Gemt" / "Ikke gemt: …") per change; `save()` never re-renders, except after a `409 stale` (shows the other person's list via a `setTimeout` render). Switching video or leaving edit mode flushes first. Registered as an unsaved check with the upload queue.
- **Subtitles upload**: `.srt`/`.sbv`/`.vtt` ≤2 MB (SBV = YouTube's format, what the revy's subtitles exist as: `0:00:01.000,0:00:05.500` timing lines, `[br]` line breaks), decoded as UTF-8 or else Windows-1252 (`vidDecodeText`), SRT/SBV → VTT in the browser (`vidToVtt`: drops SRT cue numbers and `{\an8}` tags, turns SBV's comma-separated timing line into ` --> ` and `[br]` into a line break, `,` → `.` and pads the timestamps), a preview modal with the first three cues before "Gem".
- **Upload modal**: one file (a single-file picker; a drop of several uses the first), and before any bytes go, `vidProbeMp4` (the server's probe in JS, via `File.slice`) and `vidCheckPlayable` (a hidden `<video>` on an object URL; 15 s timeout = unknown, not unplayable) show "Klar · 2:41:05 · H.264" or the warnings. Warnings don't block. The queue is a page-scoped copy of Albums' (8 MB base64 chunks, retries, cancel); free space comes from `videoer_read`'s `freeBytes`.
- **Import modal** (admin): the files in `incoming/`, "Importér" on the one that is the revy's video (closes the modal).
