# Formularer (`forms.html`/`forms.js`/`forms.css`) — self-hosted sign-up forms

Replaces the ~5 Google Forms rebuilt every year. Revyst-level page. Definitions, templates and responses (names, phone numbers) all live in the private `FORMS_DATA_DIR` (`/data/forms`) — no public consumer of a form's schema exists.

- **Two audiences**: `siteHasLevel('boss')` → management (build/edit forms and templates, view/export responses); else revyst → open forms + fill-in. Boss-level (coordination tooling, like Manus/Kalender).
- **`formsApi(action, body)`** mirrors `budgetApi` (any logged-in level; JSON-`ok` rule).
- **Storage**: `FORMS_DATA_DIR/forms/<formId>/{definition,responses}.json` + one `templates.json`. No year/active concept — several forms can be open at once. `formId`/`templateId` are server-generated hex (`forms_id()`), validated with `forms_valid_id()` before building any path.
- **Structure**: a form has `sections` (`{id, title, description, fields}`); an old top-level `fields` array is converted on read. A `FieldSpec` is `{id, type, label, required, optionsSource?, options?, sourceFilter?, …}`. Types: `text`, `textarea`, `select`, `checkboxes`, `scale`, `grid_single`, `grid_multi` (+ legacy `yesno`, accepted but no longer offered). `optionsSource` (`manual`/`scenes`/`rehearsals`) is orthogonal to type: live sources resolve client-side at render time from `SCENES_DATA`/`CALENDAR_DATA` (`formsOptionsFromScenes`/`formsOptionsFromRehearsals`, rehearsals = category `ove`), never stored — `forms.html` loads `scenes-data.js`/`calendar-data.js` for this.
- No hardcoded name/phone fields — "Navn" is just a required `text` field.
- **Frist** (`deadline`): `'YYYY-MM-DD'` or `'YYYY-MM-DDTHH:MM'` via `siteCreateDateTimeField`, shown with `formatDaDateMaybeTime`.
- **Synlighed** (`visibility`, `'boss'` default or `'admin'`): restricts only a form's responses (Statistik/Svar) — withheld server-side by caller level (`forms_visibility()`/`responsesRestricted`); the definition stays boss-editable. Oversigt greys out the icons for a boss on a restricted form.
- **Svar screen**: above the table a collapsible **Betingelser** card (`formsBuildResponseConditionsCard`, closed on every visit) hides rows that don't match its conditions, live; it uses the same `formsCreateConditionEditor()` as the Eksportér CSV modal (offered every fixed-answer question, not scoped to columns), shows the active count in its title ("Betingelser (2)") and "Viser N af M svar", and "Fjern betingelser" resets it. Each row starts with an eye button and ends with the ✕ (slet svar). The eye opens that one response as the whole form stacked on one page (`formsRenderResponseDetail`: the fill-in widgets via `formsRenderAnswerInput`, filled and locked by `formsFillAnswerInput`, text read-only and choice widgets `inert`; dependency-hidden fields left out; an answer with no matching live option shown as text); the ← top right swaps the table back in, with its conditions, pins and scroll intact (no re-fetch).
- **Svar table**: scrolls with the page like every long sheet (`.forms-responses-wrap` only scrolls sideways); the question row follows it down (`siteStickyHead`). Clicking a column title (Sendt or any answer column) opens a one-row popup, "Fastgør kolonne"/"Frigør kolonne" (`formsOpenStickyColMenu`). A pinned column is `position: sticky` with both `left` and `right` (`formsApplyStickyColumns`, offsets = summed widths of the other pinned columns), so it catches on whichever edge it would scroll out of. Pins are per browser and per form, in `localStorage` `matrevy-forms-sticky-cols`.
- **Validation posture**: `forms_submit` checks shape/type/length only, never live options (a race between page load and submit must not lose a submitter's work).
- **Oversigt rows drag to reorder** (`formsWireDropHighlight`/`formsMoveListItem`, within the year-filtered view): the client stamps `order` 0..N-1 optimistically, then `forms_reorder` writes it into each `definition.json`. `forms_save` carries an existing `order` through; new forms get `null`. `formsCompareOrder`: ordered forms first, then by `id` (hex-timestamp prefix ≈ creation order).
- **Dynamic templates** (`FORMS_DYNAMIC_TEMPLATES`): client-only `{id, title, description, generate}` entries run fresh against embedded data and applied through the normal template path — `rolleonsker` (`formsGenerateRolleonskerSections`: fixed sections, one section per act incl. Ekstranumre with one 1-5 Skala per non-song scene and two (Sanger/rapper + Danser) per song, skipping `schedulable:false`, plus a Fravær section) and `fravaer` (`formsGenerateFravaerSections`: one text field per `ove` event in October–November of the current year).
- **Server actions** (`$FORMS_ACTIONS`): revyst — `forms_list_open`, `forms_get`, `forms_submit`; boss — `forms_admin_list`, `forms_admin_read`, `forms_save`, `forms_reorder`, `forms_delete`, `forms_delete_response`, `templates_list`, `templates_save`, `templates_delete`. Saves are create-or-update by optional `id`, full replace; Åben/Lukket just resends the definition. CSV export is client-side. The first save creates whatever directories it needs.
