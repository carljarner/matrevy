# Bandet (`band.html`/`band.js`/`band.css`) — the band's folder

Replaces the band's Google Drive folder (a "Sangoversigt" spreadsheet + one folder of sheet music per song). Revyst-level page under Redskaber. **Edit rights per folder** (`bandCanEdit()` / server `band_folder_writable()`, checked at dispatch for every non-read action): only the **active folder** is open to any revyst+ (like the Drive folder); older revys, extra instances and the Arkiv tab's `_arkiv` store are view-only below boss (inputs `readOnly`, no add/remove/drag/upload/rename; server answers 403 `read_only`). Creating/editing/deleting extra instances is boss-level. The active folder is chosen in the boss-only **Boss Box** card beside Bandmedlemmer ("Aktiv mappe") (`bandBuildBossSettingsCard` → `band_set_active_folder`, stored as `BAND_DATA_DIR/settings.json` `{activeFolder}`); unset → `currentProductionFolder`. `band_instances_read` returns it as `activeFolder`; deleting the active instance resets it to unset. Private data in `BAND_DATA_DIR` (`/data/band`) — sheet music is often copyrighted, so never a web-served folder and never in the GitHub archive mirror. Online-only.

- **Per revy**: a revy picker top-right of the title (`siteCreateDropdownField`) lists Arkiv's years by `folder` (newest first, plus the current production if it has no Arkiv entry yet) and the band's **extra instances**, default `currentProductionFolder`, choice in `localStorage` `matrevy-band-revy`. Storage: `BAND_DATA_DIR/<folder>/band.json` = `{rows, instruments, columnLabels, columnWidths, updatedAt}` + `files/<rowId>/<fileId>.<ext>`. A revy without a document reads as a default (sections Revysange / Pausefisk, sketchsange eller dansenumre / Bandintroer og -jingles; Bandmedlemmer copied from the most recently edited other revy, else a built-in list: Vokal, Klaver, Guitar, Bas, Trommer, Trompet, Alt Sax, Tenor Sax, but only for the active folder, the current production or an extra instance (`band_folder_inherits_members()`); an older Arkiv year starts with an empty table) with **deterministic ids** (`band_default_id()`), so a default row can be edited before anything is written.
- **Extra instances** (e.g. "MatGalla 2025" — the band also plays the Galla): registered in `BAND_DATA_DIR/instances.json` = `{instances:[{folder, name, year, createdAt}]}` (flock'd `band_instances_mutate()`); each one's data is an ordinary band folder, so every row/file action and the Arkiv tab work unchanged. The picker's last option "+ Opret ny" (`BAND_NEW_INSTANCE`) opens a Navn + År modal; `bandRevyOptions()` sorts year desc, and within a year Arkiv's revy before instances (MatRevy 2025 → MatGalla 2025 → MatRevy 2024). `folder` is slugified from the name once (`band_slugify_folder()`, a port of `slugifyFolderName`) and never recomputed; it gets a `_2`… suffix past any clash with an instance, an existing band dir, `_arkiv`, or the client-sent `avoid` list (Arkiv's folders, which only the client knows); the client also rejects a label already in the picker. When the selected folder is an instance a "Rediger" button sits beside the picker: rename/change year (`band_instance_update`, folder unchanged) or Slet (`band_instance_delete`, registry entry first, then `band_remove_tree()` of the whole folder; refuses anything not registered, so never an Arkiv revy or `_arkiv`). Actions: `band_instances_read` (revyst), `_create`/`_update`/`_delete` and `band_set_active_folder` (boss). The registry loads before the picker renders (`bandInit()`).
- **`rows`**: one flat ordered list of `{id, type:'section', title}` and `{id, type:'song', originaltitel, revytitel, originalToneart, revytoneart, instruktoer, sangere, arrangement, arrangementKlar, files:[{id, name, ext, size, uploadedAt}]}`. `arrangementKlar` is `''`/`'delvis'`/`'klar'`, shown as a click-to-cycle pill `-` / `(Tjek!)` / `Tjek!` (the old sheet's convention).
- **Renamable column titles**: every sheet column and the Bandmedlemmer table's three headers are editable in place (a wrapping `contenteditable` `.band-head-input`, read via `textContent`, so long titles wrap instead of truncating). Only renamed titles are stored, in `columnLabels` (`{key: title}`, keys from `band_column_label_keys()`); clearing one brings the default back. Defaults: Title / Revytitel / Toneart / Revytoneart / Instruktør / Sanger(e) / Arrangement / Klar, and Navn / Instrument(er) / Stemmer.
- **Adding/removing columns** (per band folder, `band_save_columns`, full replace of both lists): clearing a column's title and pressing Backspace/Delete once more (`bandColumnTitleInput`'s `onDeleteEmpty`) opens a "Fjern kolonnen?" confirm — a built-in one is only **hidden** (`hiddenColumns`; its values stay on the rows and come back when re-added), a **custom** one (`customColumns: [{key: 'c<hex>', label, type: 'text'|'status'}]`, values stored on the row under `key` like a built-in's) is deleted along with its values, title and width. `originaltitel` (Title) can't be removed — Arkiv is keyed on it. The "+" in the header's actions cell opens "Tilføj kolonne": a new column (Navn + Tekst/Status) or a previously removed built-in. `bandSheetColumns()` = visible built-ins + customs (inserted before Klar); `bandAllValueKeys()` covers hidden ones too (drafts, content check). The server validates row fields, titles and widths against the folder's current custom keys (`band_custom_keys()`).
- **Resizable columns**: the sheet is a `table-layout: fixed` table sized by a `<colgroup>` (default px in `BAND_COLUMNS[].width`, table width = `max(100%, sum)`: fills the card, scrolls when wider). A grip on each header's right edge (`bandColumnResizer`, pointer events → touch works) drags a width (min 48px); double-click resets it. Only dragged widths are stored, shared per band folder like the titles: `columnWidths` `{key: px}` via `band_save_column_widths` (full replace, 40–1000px, sheet keys only). Cells keep their own colour while focused (only the warm border marks focus).
- **Each song row *is* a folder**: tab **Oversigt** is the sheet (+ the **Bandmedlemmer** table: Navn / Instrument / Stemmer i, stored as `instruments: [{id, navn, name, stemme}]`, rows drag-reorderable by their handle — `bandMoveMember`, saved via the full-replace `band_save_instruments`), tab **Noder** lists the same song rows as collapsible folders, in a 3-column grid per section (1 column ≤719px), sorted alphabetically by title within each section (Danish collation; the sheet's own order is untouched, so `bandRerenderFolder` finds a card by `data-row-id`, not position). "+ Ny mappe" = a new song row (revytitel + section); renaming happens in Oversigt; deleting a row deletes its files. Tabs styled like Koordinator's (`.band-mode-tabs`, duplicated), active tab in `matrevy-band-tab`.
- **Arkiv tab** (third tab; the revy picker stays visible, and picking a revy there only takes effect back on Oversigt/Noder): the long-term sheet-music library across every revy. `band_archive_read` returns every song row with a title (`originaltitel`, fallback `revytitel`) from every `<folder>/band.json` plus the reserved **`_arkiv`** store; the client merges equal titles (trimmed, case-insensitive) into one card, sorted alphabetically (Danish collation), files grouped by source (Arkiv first, then revys newest first). Arkiv only ever writes to `_arkiv` (`BAND_ARCHIVE_FOLDER`/`band_archive_folder()`; its leading `_` can never match `band_valid_folder()`, and `band_folder_from_body()` accepts it explicitly, so every row/file action works on it): "+ Ny sang" creates an `_arkiv` row (an existing title just opens its card), and uploading to a card without an `_arkiv` row creates one first (`row._ensureCreated`, so a cancelled upload leaves nothing). A search box centered in the card head (`bandArkivQuery`) filters cards by title as you type — in place via `hidden` (`bandApplyArkivFilter`), so the input keeps focus; the query survives re-renders. Only the `_arkiv` part of a card can be deleted there; a revy's song is deleted from its Oversigt. Rows carry `_folder`/`_arkivKey`, and every file call sends `folder: row._folder || bandFolder`; `bandRefreshRow()` re-renders the right card/folder.
- **Live writes** like Fællesspisning (no Gem): text cells commit on blur, pills on click, drag-reorder (handle-only, so inputs keep text selection) on drop. A new row is a client draft until its first non-empty blur (`row._inFlight` serializes); a section's "+" inserts at the end of that section via `afterId` (the only way to add a song in Oversigt); the centered "+" under the sheet adds a section. No "Opdater" button — a page refresh does the same.
- **Files**: `.pdf`/`.mscz`/`.mscx`, 15 MB (`band_max_upload_bytes()`/`BAND_MAX_UPLOAD_MB`; base64 must fit php.ini's 25M `post_max_size`), uploaded one at a time (button or drag-from-desktop onto a folder). Stored under server ids — the original filename is metadata only. `band_file` streams bytes with the password; Picking or dropping files opens a modal (`bandOpenUploadModal`) that asks for each file's name (the part — Trompet, Sax, …), required; it's sent as `<name>.<ext>` (`/`/`\` → `-`), so that name is both what the page shows (extension stripped, `bandFileDisplayName`) and the download filename. A PDF's name opens it as a blob in a window opened synchronously in the click (popup blockers); the download icon saves any file via `a[download]`; the pencil (`bandOpenRenameFileModal` → `band_rename_file`) renames it — name only, the stored extension is kept. Lists show PDFs first and MuseScore files last (`bandSortedFiles`, upload order within each); no size/date line. The "Upload filer" bar is centered under each folder/card. Badges: `MSC` (MuseScore) blue, `PDF` grey. A folder card shows the revy title with the original title smaller underneath — except in an extra instance, which has no revy titles: `bandSongLabel()` then uses the original title alone.
- **Server actions** (`$BAND_ACTIONS`, revyst except the instance writes, every row/file one takes `folder`; writes outside a revyst-writable folder need boss): `band_read`, `band_upsert_row` (create, or merge only the sent fields), `band_delete_row` (idempotent, removes `files/<rowId>/`), `band_reorder` (must be a permutation of the current ids, else 409 `stale_rows` → the page reloads), `band_save_instruments` (full replace), `band_save_column_labels`/`band_save_column_widths`/`band_save_columns` (full replace), `band_upload_file`, `band_delete_file`, `band_rename_file`, `band_file`, `band_archive_read`. `band_mutate()` = flock'd read-modify-write per revy (copy of `faelles_mutate()`); hoisted functions, no consts (dispatched early).
