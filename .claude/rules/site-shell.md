# Site shell (`site.js`) details

The summary (levels, `SITE_PAGES`, auth) is in CLAUDE.md.

- **Nav rendering**: `site.js` renders the header nav on every page from `SITE_PAGES` (`{href, label, level, group?}`). `href` is the file name without `.html` (`'kalender'`, Forside `'index'`), which is also what `siteCurrentPage()` returns; links are built by `sitePageUrl()` (`/kalender`, `/`). Revyst-level pages render greyed/unclickable until login; boss/admin-level pages are omitted below that level. Satyr's nav hides every page it can't use (greyed pages are only for visitors without a login).
- **Redskaber (grouped tool tab)**: an entry with a `group` key (label in `SITE_NAV_GROUP_LABELS`) folds into one shared nav tab; future tools register with the same `group`, no nav/CSS changes. `renderNavGroup()` lists members alphabetically (`localeCompare(…, 'da')`), whatever their `SITE_PAGES` order. `buildSiteNavLinks()` renders a group as nothing (all members hidden), a greyed `.site-nav-locked` span (all visible members locked), or an interactive tab: a click-to-open dropdown on desktop (`renderDesktopNavGroup`, reusing `.site-field-pop`/`.site-list-row`/`.site-list-selected`, with its own open/close/outside-click/Escape handling since `schedule.html` doesn't load `site-utils.js`), or an in-place accordion in the mobile overlay (`renderMobileNavGroup`, auto-expanded on a member page). `applyPageGate()`/`injectSitePrefetchLinks()` key off `SITE_PAGES` by `href` regardless of grouping.
- **Nav preloading**: `injectSitePrefetchLinks()` idle-prefetches every reachable page's HTML at load; `setupSiteNavPreload()` loads a page as soon as its nav link (`SITE_NAV_LINK_SELECTOR`: `.site-nav`/`.site-menu-nav` links) is hovered, touched or focused. Chromium gets a Speculation Rules `prerender` (`moderate` eagerness: the whole page, JS included, renders in the background, so its on-load API reads run on hover); other browsers fetch the page's HTML + its `script[src]`/stylesheets into the HTTP cache (parsed in a detached `DOMParser` doc). Both skipped over `file://`.
- **Stale-page banner** (`setupSiteStaleCheck()`): when the tab becomes visible again (≥1 min since the last check) and every 15 min while visible, HEADs `js/site.js` (its `Last-Modified` changes on every deploy → "Siden er blevet opdateret") and every `js/<name>-data.js` the page loads except `manus-data.js` (→ "Der er kommet nye ændringer"), comparing with what it saw at load. Only a real change shows the fixed bottom `.site-stale-banner` (Genindlæs / ✕; ✕ re-baselines; z-index 120). `<body data-stale-watch="code">` limits a page to the deploy check (Øveplan, which deliberately keeps its scenes). A `window.fetch` wrapper notes this tab's API writes (`SITE_READ_ONLY_ACTION_RE` skips reads), and a change within ~2 min of one (server time, estimated from HEAD `Date` headers) is accepted silently. Pages with drafts call `siteRegisterUnsavedCheck(fn)` so the banner adds "Gem dine ændringer først"; the reload still goes through each page's `beforeunload`. Relies on `embed-scenes.js` writing only changed files. Locally, PHP's built-in server sends no `Last-Modified`, so the banner only works behind a router that adds it. Skipped over `file://`.
- **Login modal**: top-right button → modal (✕, Escape, backdrop click with the mousedown guard; "Log ind" right-aligned via `.login-actions-end`) → POST `{action:'login', password}` → level. `{level, password}` stored in `localStorage['matrevy-auth']`. Logout removes the key; both reload the page.
- **Level switch** (`buildViewLevelSwitch()`): a `Revyst/Boss[/Admin] ▾` header button left of Log ud (and left of the hamburger when collapsed; never in the overlay). Satyr isn't offered. The choice is `viewLevel` in `matrevy-auth` (`siteSetViewLevel()` stores it and reloads; a fresh login has none). "Log ud (…)" shows `realLevel`.
- **Page gate**: `applyPageGate()` hides `<main>` for an insufficient level and shows a login card (blue `.site-gate-login` button).
- **`file://` bypass**: no login button, no prefetch; `sitePageUrl()` links to `<name>.html` there.
- **Mobile menu**: the header collapses to a hamburger whenever the nav + login button overflow (`siteUpdateHeaderFit()` → `.site-header-collapsed`), at any width, not tied to a breakpoint. The overlay holds nav links, then login/logout at the bottom; closes on ✕/Escape/nav-tap; body scroll locks.
