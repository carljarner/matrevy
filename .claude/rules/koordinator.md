# Koordinator (`koordinator.html`/`koordinator.js`, admin-only)

Four tabs (`KOORD_TABS`, persisted in `matrevy-koord-tab`):
- **Masterplan** (`data/masterplan.json` = `{plans:[{id, year, label, tabs:{<tabKey>:[rows]}}]}`, **admin** `masterplan` resource, `renderMasterplanCard`): a checklist grid replacing an external spreadsheet of recurring production to-dos, five fixed phase tabs (`KOORD_MP_TABS`: Blok 4/August/Blok 1/Revyen/Efter revyen). Rows are `type:'task'` (`emne`, `todo`, `beskrivelse`, `ansvarA`, `ansvarB`, `status` cycling unset→mangler→igang→faerdig) or `type:'group'` heading rows (`title`). Always-editable draft auto-saved by `koordMpAutosave` (`koordMpSaveNow`; every edit goes through `koordMpUpdateSaveStatus()`, which schedules it; plan switch/create/delete flush first, and create/delete go through `siteSaveListResource`). **Merge on save** (shared with Lokalebooking, "Merge on save" section in `koordinator.js`): each save reads the live file (`resource_read`), three-way merges `masterplanBase` / draft / live per row and field (`koordMergeList`/`koordMergeFields`/`koordMergeValue`; adds and removals from both sides kept, a removal loses to an edit, my order unless only they reordered; same field changed on both sides → mine, with a toast) and saves with `baseSha` (`koordSaveMerged`, retried on 409). If anything of theirs came in, it's merged into the draft (keeping edits made during the save) and the grid re-renders, drag-reorder (`koordMpGetDragImageEl` stacks Emne/To do/Beskrivelse; `.koord-mp-drop-tail`), plan picker remembered in `localStorage`.
- **Tjeklister & Fællesbeskeder** (`renderTjeklisterCard`): Google Keep-style notes in two columns, Tjekliste | Fællesbeskeder (`KOORD_NOTE_COLUMNS` order); each column's one "+" (top right) adds a checklist. At ≤719px (stacked) a tap on a column's top row folds it (`koordSetNotesColumnClosed`, per browser in `localStorage` `matrevy-koord-notes-cols-closed`); wider screens always show both open. Every note (`{id, column: 'beskeder'|'tjekliste', kind: 'text'|'list', title, text, items:[{id, text, done}], color}`) is free text or a checklist (switchable in its tool row; a ticked item is crossed out in place; Tab/Shift+Tab indents an item up to three levels, `indent: 0-3`; items reorder by a pointer-event drag (`koordNoteItemDragStart`, not native drag and drop, whole list as drop zone): on desktop by holding the checkbox and moving (a click still ticks it), on touch via the up/down-arrows icon left of the palette (`.koord-note-reorder`, shown only under `(hover: none)`), which puts that one note in a rearrange mode (`koordNoteReorderKey`, in memory) where every line drags until its check mark is clicked), folds up to its title via the chevron (collapsed ids per browser in `localStorage` `matrevy-koord-notes-collapsed`), has one of `KOORD_NOTE_COLORS` (↔ `koord_note_colors()`) and drags by its ⠿ handle within or across columns (the column's `.koord-note-drop-tail` = last). Private, in `KOORD_DATA_DIR/notes.json` via the admin `koord_notes_read`/`_upsert`/`_delete`/`_move` actions (`koord_notes_mutate()`, flock'd). Writes are per note like Fællesspisning's rows: a text field commits when it loses focus (never per keystroke), the rest at once, chained on `note._inFlight`; a new note stays a local draft until it has content and is then created before the next saved note (`beforeId`). Title/text/colour/kind: last save wins. A checklist's items are three-way merged (`baseItems` = the items last seen saved; `koord_note_merge_items()` ↔ `koordMergeNoteItems()`), so items added by several people are all kept (theirs appended) and show up in the saving tab from the reply. **Afslut revyen** files every current note under the closing revy (admin `koord_notes_archive {folder, name}`, sets `archive: {folder, name, at}`, idempotent); each column then lists a collapsed "Fællesbeskeder/Tjekliste (<revy>)" section per closed revy, newest first, still fully editable (so sensitive data can be removed). Edits keep a note's `archive`; drag only moves a note within its own revy's notes. Every note's tool row has a copy icon bottom left (`openCopyNoteConfirm` → `koordCopyNote`): after a "Kopier denne note/tjekliste til toppen?" modal it saves a copy at the top of this year's notes in the same column (checklist items unticked, fresh ids).
- **Lokaler & Fravær** (`renderLokalerTab`): **Lokalebooking** (`data/lokaler.json` = `{rooms:[{id,name}], bookings:{<roomId>:{<YYYY-MM-DD>: text}}, other:[{id,event,booking}]}`, **admin** `lokaler` resource, `lokalerDraft` auto-saved by `koordLokAutosave` like Masterplan) — a rooms × days table of free-text cells (sticky room column, draggable rooms, `.koord-lok-drop-tail`) replacing the yearly Lokalebooking spreadsheet. Day columns are never stored: `koordLokalerDays()` takes every `ove`/`forestilling` day from Kalender (`CALENDAR_DATA` or its override, `endDate` expanded) in the admin-chosen "Øvedage fra/til" window (optional `range: {start, end}` in `lokaler.json`, part of the draft; without it the current rolling half-year, a copy of `faellesCurrentHalfYearRange()`), merging same-date events into one column, plus the day after the last `forestilling` as "Rengøring". Bookings are keyed by date, so rooms carry over between years. Saved with the same merge as Masterplan (`koordLokMergeDoc`: rooms/other per item, bookings per room × date cell, `range` as one value; `lokalerBase`). `save_lokaler` creates `lokaler.json` if missing (it and `fravaer` are the resources that do), and a never-saved sheet is pre-filled, unsaved until the first edit, with the old spreadsheet's rooms (`KOORD_LOK_DEFAULT_ROOMS`). Below it: "Øvrige bookinger" (one-off bookings, same draft) and **Underskrevne blanketter** — signed booking-form PDFs in the private `LOKALER_DATA_DIR` (`/data/lokaler`: `files.json` + `files/<id>.pdf`), admin `$LOKALER_ACTIONS` (`lokaler_files_read`/`_upload_file`/`_rename_file`/`_delete_file`/`lokaler_file`, hoisted functions, 15 MB, `%PDF-` magic check), live (no Gem), streamed with the password like Bandet's files; online-only. **Fravær** (`renderFravaerCard`; `data/fravaer.json` = `{rows:[{id, name, days:{<YYYY-MM-DD>: text}, sources?:[{formId, responseId, name}], parts?:[row, row]}], connection}`; older rows carry a single `source`, read as one source, **admin** `fravaer` resource, `fravaerDraft` auto-saved by `koordFraAutosave` with the same merge, `koordFraMergeDoc` per row × date cell): a people × days sheet on **Lokalebooking's day columns**. Its rows are **the cast list**: every non-placeholder `cast.json` name (Sangboss included), alphabetically (`koordFraDisplayRows()`), each the saved row with that name or an unsaved one with the name-derived id `koordFraCastRowId()` (`c` + FNV hash), saved on its first typed cell; saved rows whose name isn't on the cast list follow under "Ikke på rollelisten" (red, removable). Names aren't editable, and there's no add/drag: the whole name cell (`.koord-fra-name-btn`) opens the menu (`koordFraOpenLinkMenu`) of form answers behind the row ("Forbundet til" only for rows with form sources) (`koordLokalerDays()`, so its Fra/Til window is shared and changing it re-renders both), cells free text like `14:00 - 16:00` / `fra 15` / `hele dagen` that Øveplan parses (`koordinator.html` loads `scenes-data.js` for `CAST_DATA`). **Connect to a Formularer form** (`koordFraOpenConnectModal`, Fællesspisning-style): pick a form, its Navn field and which fields map to which day (`dayFields: {fieldId: date}`, prefilled by `koordFraDateFromLabel()` from the Fravær template's labels like "Øveweekend: 24. oktober 2026 (10:00–18:00)"). `connection` is **server-owned** (`save_fravaer` keeps the live one): `fravaer_save_connection` (admin, `$FRAVAER_ACTIONS`) connects/disconnects and imports, and `forms_submit` calls `fravaer_maybe_import()` so each new answer lands within seconds. Each answer is imported **once** (`connection.importedIds`), **one row per person**: the typed name (kept in `sources[].name`) is matched to the cast roster (`fravaer_match_cast` ↔ `koordFraMatchCast`: an exact first+last-name match, else the single cast name with the same first name whose later parts/initials fit; any doubt → unconnected), the row's `name` becomes that cast name, and a later answer from the same person merges into their row (a filled-in day overwrites, so the latest answer wins per day; an empty one keeps the old value). Imported cells that are just a time are normalized (`fravaer_format_time()`: `10-18` → `10:00 - 18:00`, `fra 15` → `fra 15:00`; free text untouched). Fravær's day headers add each Kalender event's time as a grey third line (`koordLokalerDays()` returns `times`). Rows are otherwise never updated, so the koordinatorer's edits and deletions stick; the modal's "Hent alle svar ind igen" (`reimport`) clears the list. A form row's menu shows what was typed and connects it to a cast name (or "Ikke forbundet"). Whenever a rename gives a row the same name as another, they're combined (`koordFraAfterRename`/`koordFraPlanCombine`: the row with the newest `responseId`, a hex-timestamp id, wins per day), asking first in a modal listing every day that gets overwritten (Annuller puts the old name back). A combined row keeps both originals in `parts: [row, row]` (nested for repeated combines; the server import builds them the same way, validated recursively by `fravaer_clean_row()`), and the menu lists every submission in it under "Formularer lagt sammen" (`koordFraLeaves`, typed name + when it was sent, decoded from the `responseId`), each with a ✕ that takes it out as its own row with the days it was sent with (`koordFraExtract`/`koordFraWithoutLeaf`: the rest is recombined from the remaining parts, keeping every edit made to the combined row since, `koordFraEdits`). Server writes go through `fravaer_write()`, which never `respond()`s (a failed import must not fail the submit). The card re-reads the live file once per page load (`koordFraRefresh`) to show imports newer than the embed.
- **Arkivering**: the "Guide til Arkivering" card (`renderKoordGuide()`, re-rendered in place) on the left; on the right, top to bottom: Manus (active production folder), Budget, Arkiv and a **logins card** (`renderKoordLoginsCard`, heading editable, default "Google, YouTube & Spotify"): one collapsible subsection per account (`{id, title, email, password, phone}`, all collapsed on every load, open set `koordLoginsOpen` in memory only; `logins.json` = `{title, accounts, updatedAt}`; nothing saved reads as Google/YouTube/Spotify, `koord_logins_default()`). Secret, so stored in the private `KOORD_DATA_DIR` (`/data/koordinator/logins.json`) via the admin `$KOORD_ACTIONS` `koord_logins_read`/`koord_logins_save` (full replace of the list, ≤30), never in public data or the repo. Read-only until the card head's pencil turns on edit mode (`koordLoginsDraft`): the card heading and account titles editable, the ⠿ handle drags an account to reorder (the "+" row is the drop tail), a centred "+" adds an account, ✕ removes one (asks first if it has content); the check mark saves and leaves edit mode. Also the Arkiv years editor (duplicated helpers from `archive.js`, which isn't loaded here), the active budget picker (via Budget's actions), and the active production folder. Config is read as `koordConfig()` (`CONFIG_DATA` + the `config` override shadow, so this tab's own saves show without a reload).
  - **Teknikken** and **Manus** sections each end in a big centred two-box toggle, "Ikke klar" | "Klar til arkivering" (`koordReadyToggle`, the chosen box solid red for Ikke klar, green for Klar; admin config flags `archiveReadyTeknik`/`archiveReadyManus`); picking Klar asks first (`openReadyConfirmModal`, a ✕ modal with one centred amber (`site-btn-warm`) confirm button, like the "Afslut revyen?" modal), Ikke klar doesn't. Teknikken's text says to "Download alt" and upload the videos to YouTube (no login info on the site: the repo and config are public). Manus shows "Manus blev sidst opdateret" / "PDF'er blev sidst genereret" from the `Last-Modified` of `data/scenes.json` / `archive/<folder>/manus.pdf` (`koordFillFileTime` → `siteFileStatus`).
  - Afslut and "Ny Revy" are single big centred buttons in the same style (`koordGuideButton`). **Ny Revy** is disabled while a production is active (it opens once Afslut has run).
  - **Afslut revyen** (enabled only when both flags are on; the modal is the "are you sure" step) (`koordCloseYear()`): fetch the live `/data/scenes.json`/`cast.json`, add an Arkiv entry for the folder if missing, upload them as `archive/<folder>/snapshot/{scenes,cast}.json`, **delete every file in Teknikken and Lydfiler** (admin `teknik_clear_all`, `sangere_clear_all`; uploads then stay closed until Ny Revy), file this year's Koordinator notes under the revy (`koord_notes_archive`), reset `manus` to an empty 1/2/3/E skeleton, reset `manuscripts` to empty, and last set `config` to `currentProductionFolder: ''` (turning every Boss Box toggle off: manus hidden, `sketch`/`songUploadsClosedForRevyst` and `teknikUploadsClosed` `true`; both ready flags reset). While no revy is active, `save_config()` refuses to turn any of those back on (`409 no_production`, mapped by `siteSaveResource`), and Manus's and Teknikken's Boss Box toggles show off and disabled; Ny Revy opens the uploads again (manus stays hidden) — `''` blocks `manuscripts_create` until a new production starts.
  - **Start ny revy** (`koordStartNewYear()`): the admin `production` resource (sets `scenes.json`'s `production` name), an Arkiv entry for the new folder if missing, then `config` with the new `currentProductionFolder`.
  - Every step is a pure read, a guarded-idempotent create, or an overwrite of a known shape — on failure, just re-run.


## Updating for a new production

Arkivering tab: save Teknikken's files elsewhere and mark it ready, generate the PDFs and mark Manus ready, **Afslut revyen** (snapshot, archive entry, Teknikken and Lydfiler emptied, empty Manus/manuscripts, no active folder), then **Start ny revy** (name, new folder, archive entry). Submissions then land in the new `archive/<folder>/submitted/`. `program.json` and Øveplan's per-browser state are not reset.
