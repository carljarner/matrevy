# Budget (`budget.html`/`budget.js`/`budget.css`) — private datastore

Digitises the revue's reimbursement/accounting workflow. Revyst-level page. Its data (names, phone numbers, receipt photos) is personal, so it lives only in `BUDGET_DATA_DIR` (`/data/budget` on web-1), never in a web-served folder, read/written only through authenticated `update-data.php` actions.

- **Two audiences**: `siteHasLevel('boss')` → management view, **read-only below admin** (`budgetReadOnly()`: no save bar, approve/edit/split/reject, Tilføj udgift, pencils, Forbind/Nulstil, "+"/✕ or drag; amounts shown as text via `budgetMarkReadOnly`/`budgetReadOnlyAmount`; receipts, filters, mode tabs, budget picker and Udskriv still work); else revyst → submit form (a boss submits from the Revyst view). Online-only.
- **`budgetApi(action, body)`**: its own authenticated POST helper (a revyst-level submit needs a revyst password, which `siteSaveResource` won't use); JSON-`ok` rule as everywhere. Receipt images are re-encoded to JPEG client-side with a `createImageBitmap`→`<img>`→original-bytes fallback chain (HEIC iPhone photos always upload); receipts are streamed password-gated (`budget_receipt`), never at a public URL.
- **Categories** are per-budget data (`categories.json`, `{expense:[{key,label,abbrev,subcategories?}], income:[{key,label}]}`), lazy-seeded from `budget_default_categories()` and admin-editable via the sheet's "Rediger" toggle (`buildCategoryEditSection`/`budget_categories_save`). Receipt filename + bilagsnummer is `<abbrev>_<n>`, numbered per category at approval; deleting/re-abbreviating a category with a paid expense is blocked (`abbrev_locked`).
- **Sub-categories** (one level, `{key,label}`, sharing one global key namespace so `planned`/`subBreakdown` lookups are unambiguous): edit mode's per-row chevron expands an indented sub-list (same draft, drag helpers, `.budget-subcat-drop-tail`, delete confirms). A category with subcategories shows a read-only Planlagt sum of its subcategories' editable Planlagt; each subcategory gets a derived Brugt/Rest (`computeSpentBySubcategory` over expenses' `subBreakdown`). Revyster only pick the top-level category; splitting happens at approval/"Tilføj udgift"/expense edit, where `subBreakdown` must sum to the amount (`budget_validate_breakdown_sum`, shared with Stregregnskab's `stregBreakdown`). The protected `stregnskab` category never has subcategories and is excluded from the main sheet.
- **⚠️ PHP const-ordering landmine** (whole file): `update-data.php`'s top-level `const`s are registered in execution order, so a const used by a handler dispatched *before* its declaration line is `Undefined constant` at call time. Budget/Forms/Fællesspisning/upload handlers dispatch near the top, so they use **hoisted functions** instead (`budget_receipt_re()`, `budget_max_upload_bytes()`, `budget_default_categories()`, `budget_streg_category_key()`, `upload_path_level()`, …) or consts declared above the dispatch. Any new early-dispatched handler must do the same.
- **Per-budget datastore**: `BUDGET_DATA_DIR/<budgetId>/{budget,requests,expenses,categories,streg}.json` + `receipts/`, beside a root `years.json` (`{activeBudgetId, years:[{budgetId, year, label, createdAt}]}`). Several budgets can share a `year`; `label` is unique (checked on create and rename). Legacy budgets have `budgetId` = the year as a string (`budget_normalize_years_shape()` back-fills on every read); new ids are `<year>_<label>` slugs (`budget_slugify_budget_id()`), which can never collide with a bare year. `budget_active_budget_id()` resolves where revyst uploads land; `budget_resolve_budget_id($body)` lets admin handlers target any budget (default active); `budget_submit` always uses the active one. Year actions: `budget_create_year` (seeds `planned` from the budget closest in time), `budget_set_active_year` (`null` allowed), `budget_rename_year` (metadata only), `budget_delete_year` (recursive delete; clears `activeBudgetId` if needed). No server-side confirmation — the client asks.
- **No active budget is a supported state**: "Skift aktivt budget" has an "Intet valgt" option; revyst submissions then get an explicit `no_active_year` state, and every budget stays browsable by explicit `budgetId`. `loadAndRenderAdmin()` re-fetches the most recently created budget when nothing is active, so deleting the active budget lands on real data.
- **Server actions** (`$BUDGET_ACTIONS`): revyst — `budget_submit`, `budget_active_year_info`, `budget_active_categories`; boss (the read-only view) — `budget_read`, `budget_receipt` (strict filename regex, the only guard against reading arbitrary files), `streg_read`; admin — `budget_approve`, `budget_request_reject`, `budget_request_update`, `budget_request_split` (one receipt → several expenses), `budget_save_sheet`, `budget_expense_add`/`_update`/`_remove`, `budget_categories_save`, the four year actions, and `streg_upsert_row`/`streg_delete_row`/`streg_save_rows`/`streg_save_categories`/`streg_save_connection`. Storage uses `budget_mutate()` (flock'd read-modify-write, no sha/409).
- **Admin layout**: Budget sheet (planned/brugt/rest per category; brugt always derived) + Afventende udlæg side by side, Betalte udgifter below. A year toolbar picks the viewed budget (`budgetViewId`, in `localStorage`) independently of the active one. Godkend stamps `paidBy`/`settled:true`/the submission date; category, bilag and receipt lock once paid.
- **Height sync** (`budgetSyncPendingColumnHeight`): Afventende udlæg's list gets Budget's exact height (scrolling or padding out); `renderPendingSection()` always wraps content in `.budget-scroll-wrap` (even the empty state), whose `flex-basis` must stay `auto` (a `0%` basis ignores an explicit `height`). No-op in streg mode.
- **Stregregnskab** (`budgetStregMode`; tab bar `renderBudgetModeTabs`/`budgetSwitchMode`, styled like Formularer's tabs, mode in `localStorage`): swaps the Budget card for a names × drink-category grid and Afventende udlæg for "Priser", hiding Betalte udgifter. Data in `streg.json` beside the budget's other files (`budget_load()`/`budget_mutate()`), seeded Øl/Cider/Soda (`streg_default_doc()`).
  - **Grid** (`buildStregSheetCard`/`stregBuildTable`): always editable (Fællesspisning look), **auto-saved per row** like Fællesspisning: Navn and each count commit on change (blur), "har betalt" on click, each sending only the changed field via `streg_upsert_row` (`stregCommitRow`; `navn`/`paid` replace, `counts` merges per key, 0 clears it), so two admins editing different rows/cells don't overwrite each other. Commits on one row are chained on `row._inFlight` (a create always lands before the edits queued behind it). A "+" row stays local (in the working copy `stregSheetDraft`) until its Navn is filled; clearing a saved Navn puts the saved one back (the server refuses empty). Status ("Gemmer …" / "Gemmes automatisk" / the error) sits in the bottom bar (`.streg-save-group`, `stregPaintSaveStatus`); `beforeunload` warns while a save is in flight. Betaling and Priser's per-streg price recompute on every keystroke against the working copy. Row removal confirms (unless never saved) and deletes right away (`streg_delete_row`, idempotent). **Nulstil** clears every row (`streg_save_rows` with an empty array — its only remaining caller) and disconnects a Formularer connection first (it would re-sync names back). "Forbind" (Formularer Navn-field mapping, `streg_save_connection`; `streg_read` lazily syncs via `streg_maybe_sync`). A truncated Navn shows the full name in a tooltip (`budgetShowFieldTooltip`); checkbox + input live in `.streg-navn-wrap` (a flex `<td>` broke the row border). A "har betalt" checkbox (`.streg-paid-checkbox`, persisted `paid`) strikes through the row's Betaling (`.streg-paid`). **Udskriv** (`.budget-center-btn`) prints the current grid as a plain table via `#budget-print-sheet` + `window.print()`.
  - **Priser** (`buildStregPricesCard`): **live-save** — Navn/Indkøbspris commit on blur, reorder commits on drop (`budgetWireDropHighlight`/`budgetMoveDraftItem`); each commit resends the whole list (`streg_save_categories`; unknown `key` → `stale_categories`, omitted `key` → new) and refreshes the grid. A new row isn't sent until its Navn is filled. Deleting asks first and is blocked at zero categories; existing tallies for a removed category are left alone server-side. Per-streg price previews live against the typed price (`stregPriceRefreshComputed`).
  - Pris pr. streg and Betaling are derived client-side only (`stregComputePricePerUnit`/`stregCategoryTallyTotal`, which take an explicit `rows` list so the grid can pass its draft).
