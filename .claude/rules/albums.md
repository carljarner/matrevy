# Albums (`albums.js`/`albums.css`, the Albums tab on Arkiv): the revy songs as a music player

A members-only, Spotify-like player for the mixed revy songs (FLAC, 30-40 MB each), replacing SoundCloud/Spotify. **A tab on Arkiv** (`arkiv.html`, see `arkiv.md`), no page of its own and not in `SITE_PAGES`. **Revyster listen; boss creates albums, uploads, edits and downloads.** JS prefix `alb`, root `#albums-root`. Plan and later phases: `plans/albums.md`.

**Server: Teknikken's store code on a third store** (`teknik_stores()['albums']`: `ALBUMS_DATA_DIR` = `/data/albums`, `albums.json` + `files/` + `uploads/`, 12 GB quota, `needsRevy: false` so uploads are open without an active revy). `$ALBUMS_ACTIONS` sets `$GLOBALS['TEKNIK_STORE'] = 'albums'` and runs the matching `teknik_*` handler, plus its own `albums_read`, `albums_create`, `albums_reorder`, `albums_stream_urls`. Revyst: `albums_read`, `albums_stream_urls`. Boss: `albums_set_imported_plays`, `albums_download_url` (always attachment; no button uses it now), `albums_folder_download_url`, `albums_create`, `albums_delete` (→ `teknik_delete_folder`), `albums_rename_file`, `albums_delete_file`, `albums_reorder`, `albums_upload_*`. No `teknik_create_folder`/`move_*` and no `clear_all`: **permanent**, never emptied by "Afslut revyen", never mirrored, **excluded from the nightly restic backup** like Teknikken/Lydfiler (the originals are kept elsewhere).

- **Data model**: an album is a top-level teknik folder plus `archiveFolder` (an Arkiv `folder`, at most one album each; `409 album_exists`). `albums_create {archiveFolder}` looks the folder up in `data/archive.json` (that lookup is the guard) and copies its `name` (used for the zip). The page shows the **live** Arkiv name and `coverImage` from `ARCHIVE_DATA` (`js/archive-data.js`), falling back to the stored name / a ♪ placeholder. A track is a teknik file plus `order` (set last in its album by `teknik_upload_finish`) and `durationSec` (a FLAC's is read from its STREAMINFO header by `albums_flac_duration()` in `teknik_upload_finish`; otherwise the browser's measurement from a local object URL, sent with `albums_upload_start`, which can time out in a background tab. A FLAC stored without one is filled from the file on the next `albums_read` (`albums_fill_missing_durations`); a non-FLAC without one is filled in this tab only on first play). `albums_reorder {folderId, fileIds}` must list exactly the album's tracks (`409 stale` otherwise → the page reloads).
- **Stream links up front**: `albums_read` returns a signed inline URL for every track (`streamUrls`, `streamExpiresAt`), because iOS only starts audio when `play()` runs inside the tap itself (no request first), and the next song must start while the phone is locked. Expiry = the first 04:00 at least 12 h away (valid 12-36 h, identical all day), and album streams get `Cache-Control: private, max-age=43200`. The page renews them (`albums_stream_urls`, no folder = all) when under an hour/two hours remain, after an upload, and on an `<audio>` error (one retry per track, resuming at the same position).
- **Play counts**: `albums_count_play {fileId}` (revyst) adds 1 to the track's `plays` (flock'd). The page decides what a play is, like Spotify: **30 s actually listened** (half the song if it's under a minute), counted once per start (repeat one counts each round). `albTrackListening()` adds up time between `timeupdate`s while playing and ignores jumps over 1.5 s, so seeking doesn't count. Sent quietly with the stored login only (`albCountPlay`: no password prompt, no error toast; a lost count is just lost). Shown as "▶ 1.234" (`.alb-track-plays`, muted, empty at 0) between the title and the duration, in a fixed-width left-aligned column so the ▶ icons line up (every row is its own grid). Shared passwords, so it's a popularity counter, not an audit. **Imported plays**: boss types the plays a song had on Spotify/SoundCloud in edit mode (`albImportedPlaysField`: a small field by ▶, "12.408"/"12408" accepted, saved on blur/Enter, with a hint line above the list) → `albums_set_imported_plays {fileId, plays}` (boss) stores `playsImported` apart from `plays`, so correcting an import never wipes the real count. Rows show the sum (`albTotalPlays`); the tooltip says how many were imported.
- **Zip**: `teknik_zip_entries` orders an album by `order` and numbers the names (`01 Title.flac`).
- **Only browser-playable formats upload** (`ALB_AUDIO_EXTS`: flac, mp3, m4a, wav, aac, ogg, all in `teknik_inline_types()`); a non-inline file would get an attachment stream link and not play.

## Page

- **Routing**: overview at `/arkiv#albums`, an album at `/arkiv#albums/<archiveFolder>` (`albRouteFolder()`; `hashchange` → `albOnRoute`, after `archive.js` has shown the tab). `albTabShowing()` gates what only makes sense on the Albums tab: naming the page and the Space shortcut. The player bar, queue and playback stay on every Arkiv tab; the player's song title jumps to the Albums tab. On play it dispatches `arkiv-media-play` (`{source: 'albums'}`), re-sets its Media Session handlers and metadata (Videoer sets its own while a video plays), and pauses when another source sends it. Revyster never see an empty album (hidden in the grid, a hash to one shows the overview).
- **Overview**: a grid of `.alb-tile` covers, newest year first, ending in an empty `.alb-tile-actions` card spot (a dashed grey border, `.alb-tile-actions-framed`, only when it has the boss's "+") holding the round amber buttons: "Bland alle" (`.alb-shuffle-all`, the same as "Bland" inside an album; only when there are songs) above "Nyt album" (`.alb-new-album`, a "+"; boss): a dropdown of Arkiv years without an album; the current production can only get one once Koordinator has added its Arkiv entry. For a revyst that card holds just "Bland alle", centred.
- **Album view** (`albBuildAlbumView`): back link, and for boss a download icon (the album as .zip) left of the `siteEditToggle` in the top-right corner (`.alb-album-tools`); cover/name/meta ("17 sange · 58 min"), three round amber buttons (play, `.alb-big-play-main`; shuffle; and the queue icon, `albQueueAddAlbum`: the whole album in album order last in "Næste i køen", toast "17 sange fra … er tilføjet til køen."; with nothing in the player the first song starts and the rest are queued), then the tracklist (`ol.alb-tracks`, row = `button.alb-track-main` + a ⋯ button for the queue menu, no per-song download). The playing row gets `.alb-track-current` (light amber) and `.alb-track-playing` (three bars instead of the number) via `albMarkPlaying()`, never a re-render.
- **Edit mode** (boss): the whole row drags to reorder (held on touch screens; see Reordering), title as a `.site-inline-field` saved on blur/Enter, ✕ with confirm, trailing `.alb-drop-tail`, and a bar with "Slet album" left and "Upload sange" centred (also shown outside edit mode on an empty album). Desktop files dropped on the card open the upload modal.
- **Upload modal**: one title per file, prefilled from the file name without extension/leading track number (`albParseFileName`: `03 - Hej_med_dig.flac` → 3, "Hej med dig"), in track-number order; songs land last in the album in that order. The queue is a page-scoped copy of Lydfiler's (8 MB base64 chunks, retries, cancel).
- **Player** (`albPlayer`, one `<audio>` in `body`, two on Android, see Preloading), two parts like Spotify:
  - **Context**: what was started (an album, or every song for "Bland alle"). `ctxIds` = album order, `ctxOrder` = play order (shuffled: current first, rest mixed), `ctxPos` = the context song playing now, or the last one before a queued song, `ctxFolder` (null = "Bland alle").
  - **`upNext`** ("Næste i køen"): songs added via the row's ⋯ menu (`albOpenTrackMenu`, a `.site-field-pop` with "Spil som næste" = first, "Tilføj til køen" = last). Played before the context continues; starting a new context keeps them. With nothing in the player, the song just starts.
  - `nowId` is the song in the player, `nowQueued` = it came from `upNext`. Next: `upNext` first, then `ctxPos + 1`; repeat all wraps the context (reshuffled), repeat one replays, otherwise it stops at the end. Previous restarts after 3 s; from a queued song it goes back to `ctxOrder[ctxPos]`. Shuffle only reorders the context. `albLoadTrack` must stay synchronous (iOS). `albPlayerReconcile()` after deletes/reorders/reloads; a deleted current song stops the player.
  - **Preloading the next song (Android only, `ALB_PRELOAD`)**: with the screen off, Chrome on Android sometimes didn't start the next song (the hidden tab plays nothing while the new FLAC's first bytes arrive, and Android may throttle it, cut its network or refuse `play()`). So in a song's last `ALB_PRELOAD_SEC` (30 s) `albMaybePreload()` (from `timeupdate`) loads `albPeekNextId()` (what `albNext` would pick, without changing state; none for repeat one or a shuffled repeat-all wrap) into a second `<audio>`, `albPlayer.spare`/`spareId`, and `albLoadTrack` swaps it in (`albTakeSpare`) when it's that song from its start; any other load empties the spare (`albClearSpare`). Both elements come from `albCreateAudioEl()`, whose listeners ignore events unless the element is `albPlayer.audio`, so code always uses `albPlayer.audio`/`albAudio()`, never a kept reference. Not on iOS (an element only plays while locked once a tap has started it, and one element already works there) or desktop. Untested on a real Android phone so far (headless Chromium with an Android user agent swaps correctly).
- **Kø panel** (`albRenderQueue`, `.alb-queue`, toggled by the queue icon at the right of the player bar; an amber dot on it while `upNext` has songs): "Spiller nu", "Næste i køen" (✕, "Ryd", a row click plays it and drops the ones before), "Næste fra <album>" / "Næste fra Bland alle" (row click jumps, ✕ removes it from the context; max 100 rows shown). Both lists reorder (see Reordering), and a context song can be dragged up into "Næste i køen" (`albContextToQueue`: it leaves the context). An empty "Næste i køen" is rendered but hidden (`.alb-q-upnext-empty`) and shows as a dashed "Slip sangen her" drop area only while a context song is dragged (`.alb-q-dragging-context` on the panel). Moving a context song changes `ctxOrder` (and `ctxIds` when unshuffled), and `albPlayerReconcile()` keeps the queue's own order instead of re-sorting it by album. A one-line hint under the lists says how to move a song (hold on touch, drag with a mouse). Re-rendered from `albPaintPlayer()` (never while a row is dragged). It sits at the right, above the bar (`--alb-player-h` from a ResizeObserver on the bar). **From 900px it displaces the page content**: `albPositionQueue()` gives the showing `.arkiv-tab-panel` (`albQueueHost()`; the year grid, Videoer or the album card / grid; the title and tabs stay put) a right margin so it keeps its left edge and ends 16px before the panel, and lines the panel's top up with it, always full height down to just above the player bar, even with an empty queue (staying 16px below the sticky header once that scrolls away; on scroll, resize, every render and on close). Below 900px it overlays the page and a click outside closes it. Escape closes it.
- **Reordering** (`albWireReorderRow`, used by edit mode and both queue lists; **no drag handles**, like Teknikken): with a mouse the whole row is `draggable` (not while pressing in a title input), shared `albGetDragImageEl()` ghost; on touch screens a row is **held** `ALB_HOLD_MS` (350 ms) without moving (moving sooner is a scroll), then follows the finger (the panel or page scrolls near the edges) and drops before the row under it (`.alb-lifted`, `.alb-drop-target`). Rows carry a `group` (`album`, `upnext`, `context`); each drop list is set up by `albFinishReorderList(list, group, onDrop)` (adds the trailing `.alb-drop-tail`, wires rows + tail) and takes the groups in `ALB_DROP_ACCEPTS` (`upnext` also takes `context`); `onDrop(drag, before)` gets the dragged row's `{group, index}`. Touch drops pick the nearest accepting list under the finger (`albTouchTarget`). `albTouchDropped` swallows the tap a drop would cause. Rows get `user-select`/`-webkit-touch-callout: none` (inputs keep text selection).
- **Player bar** (`.alb-player`, built once, dark like the site header, z-index 110, `env(safe-area-inset-bottom)`; the page has `viewport-fit=cover`): song + album (click → the album), shuffle/prev/play/next/repeat (a dot under an active mode, a "1" for repeat one), seek bar (`--alb-seek-pct` paints the played part), and left of Kø a volume control (`.alb-volume`: a speaker button that mutes, icon by level, plus a short `.alb-seek.alb-volume-range` slider; dragging unmutes, unmuting at 0 goes to 50 %). Volume is per browser in `localStorage['matrevy-albums-volume']` (`{level, muted}`), applied to the `<audio>` when it's created. Hidden on phones (≤719px, the device's buttons) and where the browser ignores `audio.volume` (`albVolumeSettable()`, i.e. iOS/iPadOS). A ✕ (`.alb-player-close`, "Luk afspilleren") closes the Kø panel and calls `albStopPlayer()`: the music stops, the song, context and "Næste i køen" are emptied (also in localStorage), and the bar hides until something is played again. From 720px it sits in the bar's top-right corner (the bar has extra right padding for it); on phones it is a small dark tab sticking up from the bar's top-right corner (`bottom: 100%`, height `--alb-close-tab-h`, which the body padding, the toast offset and the phone Kø panel's `bottom`/`height` add, so the open panel sits above the tab). On phones (≤719px) the left title block is hidden and a centred one-line `.alb-player-line` ("Titel · Revy", bold title, muted revy, ellipsis; click → the album) sits on top, then the seek row, then the cover (also links to the album), the controls exactly centred (`1fr auto 1fr`, gap `clamp(0.5rem, 5vw - 0.5rem, 1rem)`) and Kø. The album card gets less side padding there, song titles wrap instead of being cut off, and play counts are hidden. `body.alb-has-player` pads the page and lifts `.site-toast` above the bar. **Space always plays/pauses** (capture-phase keydown + keyup, so a focused button isn't pressed again), except in text fields or with a modal open.
- **Media Session**: title, album name as artist, the Arkiv cover as artwork; play/pause/previous/next/seekto. **No seekbackward/seekforward**, or iOS shows ±10 s instead of previous/next. Safari offers those by default, and `setActionHandler(x, null)` only drops a command the page set itself, so `albInitMediaSession` sets a no-op and then clears it (Videoer does the same).
- **Remembered** in `localStorage['matrevy-albums-player']`: context, `upNext`, `nowId`, shuffle, repeat, position (saved every 5 s, on pause and on `pagehide`). A restored song shows paused; play loads it at the saved spot.
- **Downloads** (boss only) go through a hidden iframe (leaving the page would stop the music); on iOS a new tab opened inside the click.
- The music stops when navigating to another page (multi-page site); out of scope for now.
